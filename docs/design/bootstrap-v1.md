# konOSuba 最小自举实现合同

工作草案，2026-10-10。优先级：自举、简单、现代。本合同选定一条可以实施和检验的路线，不再并列罗列架构选项。它是后续实现提案，不将尚未完成的模块写成已有能力；不覆盖 SOS 旧需求中的已实现状态。

## 1 最终要交付什么

在固定 RV64 系统中，编辑器修改文件，编译器读取自身与系统的源码，直接生成可装载映像；新编译器能再次生成自己，新内核可保存并在下一次启动使用。系统内完成这些操作不调用 Rust、Zig、Python、Clang、LLD 或宿主文件服务。

允许宿主负责第一次种子构建、启动 QEMU、收集测试输出和导入／导出磁盘映像。QEMU 是机器环境，不替我们实现文件系统、进程、窗口或编译。第一版不要求自制 CPU、不要求系统内运行 QEMU，也不把实体板移植加入闭环。

以下五类源码进入自举输入：编译器；用户运行库和命令工具；内核与设备代码；编辑器及基础 GUI；固件／启动与陷入汇编。最初种子可用现有语言，最终日常构建路径必须由 biomiya 程序和受限汇编处理器完成。固件可以由宿主在下一次 QEMU 启动时安装，但固件映像须能在系统内重建。

首个命令行闭环是中间验收，不取消最终 GUI、持久化和两个执行活动的需求。网络、多核、动态链接、通用包管理、增量编译和任意第三方 C 库链接不进入这条首版路径。

## 2 固定执行环境

候选参考机采用 QEMU virt、RV64IMA＋Zicsr＋Zifencei、单 hart、256 MiB RAM、4 KiB 页。固定一种块设备传输、一种显示／输入后端；GUI 的设备选择不阻塞早期串口自举。目标使用 S-mode 内核、U-mode 用户程序、Sv39 保护。早期 Linux 用户态实验只作为编译器的运行适配层，不算 SOS 自举通过。

用户虚拟地址约定：

| 区域 | 候选地址与限制 |
| --- | --- |
| 映像 | 从 `0x00010000` 开始；text RX，rodata R，data／bss RW；用户态禁止 W+X |
| heap | 从映像末尾向上页对齐开始，首版仅增长；每进程 heap 上限 64 MiB |
| 栈 | 顶端 `0x40000000`，向下 1 MiB；下方一页不映射 |
| 启动参数 | `0x3FEFE000` 开始的只读一页，位于栈保护页下方 |
| 地址零及未分配区 | 不映射 |

所有进程使用相同虚拟映像基址，各有页表，不需要 PIE 或装载重定位。256 MiB 是初始实验条件，不是内存用量成绩；分配失败必须返回错误，不能因配置足够大而删除检查。

固件链接基址沿用 `0x80000000`，内核沿用 `0x80200000`。固件区保留前 2 MiB，BootInfo 和固件栈从该区域明确划出，加载器禁止内核段覆盖。内核页表首版保留其使用的 RAM 身份映射及明确的设备映射；U-mode 页表不授予这些 S 页的用户访问权。

## 3 让一个构建程序承担编码、链接与打包

最终工具暂名 `bmc`，一次处理完整程序的显式输入集合：

```text
.vt 文件 → 声明和具体类型 → 单函数检查与控制流 → 机器指令编码
.s0 文件 → 受限指令解析 ──────────────────────────────┘
                         ↓
             text／rodata／data／bss，符号，回填项
                         ↓
                 地址分配、回填、ELF 输出
```

首版不写通用 `.o`／`.a` 读取器，不支持弱符号、COMDAT、TLS、动态重定位或 GNU 链接脚本。模块是源代码组织边界，每次整体重建；链接是同一构建器中的地址分配和符号回填阶段。

保留 C ABI，便于语言函数与少量汇编相连。`extern abi(C)` 声明的符号必须由本次 manifest 输入提供；不隐式寻找 libc。ABI 兼容不等于首版构建器必须读取任意 C 工具链对象。

构建文件采用行格式，UTF-8，无变量、通配、命令替换或 shell：

```text
format 1
profile sos-user
entry _start
source compiler/main.vt
source compiler/source.vt
source compiler/scan.vt
source compiler/parse.vt
source compiler/types.vt
source compiler/check.vt
source compiler/ir.vt
source compiler/rv64.vt
source compiler/image.vt
source runtime/user.vt
assembly runtime/sos.s0
output build/bmc.elf
```

每行最多一个指令及一个无空白参数；空行和以 `#` 开头的整行忽略。所有路径相对构建输入根，不相对 manifest 所在目录；Linux 适配使用启动工作目录，SOS 使用第 11 节的文件名空间。禁止空路径、空路径分量、`.`、`..`、绝对路径及重复输入；末尾 LF 可省略。format／profile／entry／output 必须各一次，format 必须为 1，未知项错误。源码按列出顺序获得 FileId，声明和字符串按明确遍历顺序获得编号，不依赖哈希表枚举顺序。

这是拟实现的命令接口，不是当前命令：

```text
bmc build compiler/sos.build
bmc build system/kernel.build
bmc check compiler/sos.build
bmc compare build/bmc2.elf build/bmc3.elf
```

不依赖 make 或 shell 才能递归重建：一个 `rebuild.vt` 按固定 manifest 列表调用库函数 build，依次生成工具和系统。需要多个构建目标时列在这个普通程序里，不先设计可编程构建语言。

## 4 输出映像到字节级的合同

用户映像固定 ELF64 little-endian、ET_EXEC、EM_RISCV=243、soft-float 标志。ELF header 为 64 字节，紧接三个 56 字节 PT_LOAD；不要求 section header、符号表、动态段或解释器段。入口必须位于可执行段内。

三个段固定顺序 RX、R、RW，文件偏移和虚拟地址起点均 4 KiB 对齐，满足相同页内偏移。文件头占首个文件页而不映射。text 从文件偏移 4096／虚址 0x10000 起，其后两段顺序向上对齐；段内各对象再按自身对齐分配。空 rodata／data 保留至少一字节填充，避免依赖空 PT_LOAD 的处理差异。

| PT_LOAD 字段 | 含义 |
| --- | --- |
| p_offset | 段初始化字节在文件中的偏移 |
| p_vaddr | 目标虚拟地址，用户固定基址下分配 |
| p_filesz | 需要从文件读取的字节数 |
| p_memsz | 运行时占用的字节数，必须 ≥ p_filesz |
| p_flags | 5／4／6，分别 RX／R／RW |
| p_align | 4096 |

RW 段先放 data，再放对齐后的 bss；bss 不写入文件，只增加 p_memsz。**文件大小、内存大小和文件偏移是三个不同的量。** ELF 字段逐字段按小端编码，不将宿主结构直接 memcpy 到文件。

加载器验证：头部与表范围、目标／版本／标志、恰好允许的段、入口、大小加法溢出、文件边界、页内同余、段的页映射不重叠、用户范围、权限及总内存额度。先分配全部物理页并清零，再拷贝 p_filesz，最后安装权限；失败释放本次分配，不发布半个进程。首次执行前兑现目标的指令可见性要求。

内核复用 ELF 写出器，使用不同基址和入口。固件 profile 另输出供固定启动方式使用的平坦 `firmware.bin`：从 `0x80000000` 起连续放置初始化段及对齐填充，首条指令就是入口；bss 不写入文件，内存末端仍须在保留的 2 MiB 内。它复用同一套段布局和回填，不经宿主 objcopy。启动汇编先清零 bss、建立独立固件栈，再调用语言入口；所需边界符号由构建器显式提供。

固件加载内核时按 PT_LOAD 搬运／清零，验证物理范围及与固件／加载缓冲区不相交；逐块读取到独立 bounce buffer 后写入目的地址。不再让一个追加在固件尾部的任意大小 payload 与目标区域重叠复制。

当前 SOS 代码中两项必须替换的具体行为：

- [mkimage.zig](../../../SOS/tools/mkimage.zig)把 file_size 和 memory_size 都写成 kernel.bin 长度，不能描述 `.bss` 和内核栈所需内存。
- [bootloader.zig](../../../SOS/src/bootloader.zig)从 `0x80100100` 向 `0x80200000` 正向逐字节复制。payload 超过 `0xFFF00` 字节时源目标重叠，后写入的数据会覆盖尚未读取的源数据。当前小内核未触发不意味着该格式可直接扩展到自举系统。

这两点本轮仅记录并由新加载方案避开，未修改现有启动代码。

## 5 内部符号与回填

不把系统范围的所有地址都提前算好。先生成三个字节缓冲和一个 bss 大小，记录以下具体表：

```text
Symbol { name:NameId, region:u32, offset:usize, size:usize, align:usize }
Fixup  { region:u32, kind:u32, offset:usize, symbol:u32, addend:isize }
```

region 只有 Text／Rodata／Data／Bss；名字和 symbol 都是稳定编号。源码内部函数按模块＋声明编号命名，导出和汇编引用使用显式 ASCII 名字。重复定义、未定义、类型上要求函数却解析到数据对象，均在写出前拒绝。汇编函数签名仍是平台受信合同，不能从机器指令自动证明。

回填只保留两族：

1. **PCREL_PAIR**：AUIPC 与 ADDI／JALR 两条指令，从首条指令地址算差值。`hi=(delta+0x800)>>12`，`lo=delta-(hi<<12)`；检查 hi 的 20 位有符号范围和 lo 的 12 位有符号范围。
2. **ABS64**：将符号最终地址加 addend 写为八字节，用于静态数据中的对象／函数地址。

不做链接松弛。跨块跳转始终 8 字节，条件远跳始终“反向条件跳过两条指令＋8 字节跳转”，共 12 字节。普通直接调用同样采用 8 字节序列。x5/t0 保留给这些展开，IR 值不能假定它跨展开存活。间接调用走寄存器 JALR。

这样布局大小在回填前确定，不需要反复缩短／加长分支。第一版以较大机器码换取简单实现；遇到超范围返回构建限制错误，不截断地址。当前候选映像跨度限定在 64 MiB 内，仍逐项检查差值。

### 5.1 本轮已有可执行证据

[bootstrap-image/probe.py](../../experiments/bootstrap-image/probe.py)直接编码一段 RV64 程序并写 ELF，生成被测映像不调用汇编器／链接器。程序执行大于 4 KiB 的前向调用、条件远跳和反向跳转，读取 ABS64 静态指针，验证 data 值和跨页 bss 首尾清零。

运行方式：

```sh
python3 biomiya/experiments/bootstrap-image/probe.py
```

本次实际通过：13 个 PCREL 回填、1 个 ABS64，text 5416 字节、rodata 3041 字节、data 16 字节、bss 4096 字节；QEMU 用户态退出 0。独立用 Clang／LLD 编码同一指令序列，三个初始化段的字节完全一致。另检查高低立即数舍入边界及越界拒绝。

这个实验是 **Python 构造的手写指令程序＋Linux write/exit 适配**，没有 biomiya 前端，没有 SOS 加载器，也没有证明自举。它只验证本节建议中的直接编码、地址回填和最小 ELF 输出确实能组成一条机器执行路径。[复现说明](../../experiments/bootstrap-image/README.md)；运行后生成的报告位于 `experiments/bootstrap-image/out/report.json`。

## 6 少量汇编如何在自举中重建

不能一面说“内联汇编交给外部文件”，一面把这些文件永久留给宿主 Clang。构建器包含 `.s0` 处理器，并和机器后端共用同一套编码函数。

`.s0` 首版只有：具名／文件内局部标签；十进制／十六进制立即数；`x0` 至 `x31`；固定 RV64I/M/A 指令及所需 CSR、fence、ecall、sret、mret、wfi。每个指令的操作数字段独立验证。A 扩展的 aq／rl 位必须显式表示，不能由“atomic”这个名字猜测内存序。

只提供三个固定伪指令：`address rd,symbol`、`call symbol`、`jump symbol`，对应第 5 节的固定长度序列。无 li／la 自动选择、宏、include、条件汇编、任意表达式或汇编器插件。大立即数由显式指令构造；纯数据定义放语言 static 中。早期确需 `.word` 时只能是明确 u32 字面量，并列入机器代码审计，不接受符号表达式。

汇编接口文件只有 `runtime/linux.s0`、`runtime/sos.s0`、`platform/entry.s0`、`platform/trap.s0` 和固定 CSR／固件辅助文件。函数体正常遵守 LP64；特殊入口由平台合同约束。首版不承诺读 GNU 汇编，现有 `.S` 要人工迁移并用旧工具链做字节／行为对照。

## 7 编译器自己用什么数据结构

不用 Rust 的 Vec／String／HashMap 类型直接当作未来语言必须支持泛型的理由。具体实现采用以下布局：

| 数据 | 具体表示 | 存储期 |
| --- | --- | --- |
| 源文件 | `{FileId, path:NameId, bytes:[]const u8}` | 整次构建 |
| 名字 | 字节池中的 `{offset:u32,len:u32,hash:u64}`，NameId 为表索引 | 整次构建 |
| 源位置 | `{file:u32,start:u32,end:u32}`，字节偏移 | 随引用它的对象 |
| 声明／具体类型 | 连续记录表；DeclId／TypeId 为 u32 包装结构 | 整次构建 |
| 顶层函数体 | 源文件起止范围和签名 | 整次构建 |
| 当前函数 AST | 记录表；子节点用 ExprId，参数列表用连续 ID 范围 | 当前函数 |
| 当前函数 IR | Slot／Block／Instruction 三张表，已知 TypeId | 当前函数 |
| 输出符号／回填 | 第 5 节的具体记录表 | 输出写完 |

别名身份写成单字段结构，例如 `struct TypeId { index:u32 }`；不使用透明别名把不同 ID 混成同一类型。大表的元素通过 ID 取出复制、修改后写回，不把可能因扩容失效的元素指针存到其他表中。

第一版表有明确容量，启动时一次分配，其后不搬迁。超过容量报告 `I_LIMIT`，附实际值和配置值；不把容量限制当语言非法。后续需要增长时只替换表存储，不改跨表 ID。表达式用带标签枚举表示各种节点，复杂载荷放额外具体表，不退回任意字节的无类型节点图。

名字哈希表用开放寻址，保存 NameId+1，0 为空；容量为 2 的幂，负载不超过一半。不支持删除，冲突逐项比较字节；插入探测次数有容量上限。哈希只用于查找，不决定输出遍历顺序。

局部作用域不另建通用哈希框架：绑定记录保存 name/type/slot/scope，进入块记 mark，退出恢复长度，查找从后向前。顶层符号数量较大，用具体名字表。布局缓存按 TypeId 保存；非名义类型先用简单具体键查重，只有测得热点再更换索引。

### 7.1 内存配额是实现参数

初始候选预算如下，不是对未来源码规模的预测。记录槽宽为预算上限，实际实现须用 sizeof 断言核对。

| 区域 | 初始上限 |
| --- | ---: |
| 全部源字节 | 4 MiB |
| 名字字节池 | 2 MiB |
| 32768 个名字记录＋65536 个哈希槽 | 768 KiB |
| 16384 个声明，每槽不超过 64 字节 | 1 MiB |
| 32768 个具体类型，每槽不超过 32 字节 | 1 MiB |
| 全局字段／参数等附属表 | 1 MiB |
| 当前函数 AST，65536 槽，每槽不超过 48 字节 | 3 MiB |
| 当前函数 IR，131072 槽，每槽不超过 48 字节 | 6 MiB |
| text 缓冲 | 8 MiB |
| rodata＋data 缓冲 | 8 MiB |
| 回填表，262144 槽，每槽不超过 32 字节 | 8 MiB |
| 诊断、扫描缓冲及其他 scratch | 4 MiB |

小计 46.75 MiB，剩余到 64 MiB 的空间覆盖符号表、分配对齐、文件表和辅助结构；这些仍要实测计量，不能叫作免费。用户栈的 1 MiB 另计。词法扫描按需推进，不同时保留全部文件的 Token 对象；源字节保持不动以便诊断。

单函数 AST／IR 在该函数代码与回填项生成后重置；defer 清理片段只引用本函数槽号，不能在全局保存已重置 arena 的指针。退出编译器进程回收其全部 heap 页，不要求为每个 AST 节点分别 free。

## 8 编译阶段的精确分工

1. **输入快照。** 读取 manifest 和全部源文件，记录字节与文件版本。之后解析只读内存快照，不在中途重新打开源码。
2. **顶层登记。** 解析模块、声明头、类型表达式、常量和 static 初始化；函数体只记录范围。检查重名和模块可见性。
3. **具体事实。** 求布局前常量，展开别名，算具体布局，再求布局后常量／断言和静态数据。局部出现的具体类型可随后按已经确定的常量构造并缓存，不反推全局事实。
4. **逐函数编译。** 解析当前函数体，做一次正式类型检查并生成有类型控制流；位置与值分开，求值顺序、快照和清理在这里确定。后端不回看源码重判类型。
5. **机械编码。** 每个值有栈槽，先不做寄存器分配或 SSA 优化。整型加载、窄值归一化、聚合复制、调用序列和必要检查明确展开。
6. **完成映像。** 加入平台汇编，分配段和符号地址，处理回填，验证入口／外部名字，然后输出 ELF。

不把解析、正式检查和机器发射强行压成单遍。减少的是重复语义权威与跨阶段求解。生成汇编文本可以作为调试视图，但不作为生产链必须重新解析的中间文件。

语言需求由这些结构明确导出：需要具名结构／枚举、数组、切片、具体函数、原始存储、整数位操作、Result 和作用域清理。尚未出现必须依赖用户泛型、闭包、CTFE 或一般借用推导的地方。是否恢复这些机制，应先提交一个这些具体表示无法清楚处理的自举用例。

### 8.1 函数 IR 如何避免重新解释语言

第一版 IR 不做 SSA，不需要 phi、支配树、活跃区间或寄存器分配。以下是设计记号，不是待解析的新语言：

```text
Slot  = { type:TypeId, stack_offset:usize, size:usize, align:usize }
Block = { first_instruction:u32, instruction_count:u32, terminator:Term }
Term  = Jump(block) | Branch(bool_slot,yes,no) | Return(slot?) | Unreachable
```

指令使用具体带标签记录，附一份源位置，分为常量／符号地址、栈槽地址、标量加载／存储、定长复制、整数操作与转换、调用、MMIO／原子和显式检查。长参数列表放当前函数的附属槽号表。所有操作数在进入后端时已有具体类型与目标宽度；后端遇到未知类型是内部错误。

关键表示是 **位置与值分开**：位置记录对象地址、TypeId 和可写性；标量值、聚合快照和地址值都落在 Slot 中。字段访问只计算偏移，取值才加载或复制。聚合赋值先保存右侧完整快照，再写目标，重叠时也保持 R1 的求值规则；不靠 memcpy 对重叠输入的偶然行为。

例如 `f(record, mutate_record())`：先求 f 并保存函数值；将 record 复制进独立实参槽；再调用 mutate_record；最后按 ABI 摆放两个已完成的实参。第二个实参的副作用不能改变第一个快照。间接调用的函数指针也不能在后续实参求值后重新读取。

内部聚合参数使用快照地址，聚合结果使用调用者提供的结果槽，遵守 R1 第 16 节。首版不复用临时槽，除非其存储期已明确结束；栈帧超过目标限额即报 I_LIMIT，不能生成会撞保护页的帧。栈深度仍须运行时处理，编译时的单帧限制不能证明递归安全。

`return e` 的顺序固定为：求 e → 保存返回快照 → 展开当前退出路径上的 defer → 从快照返回。`break/continue` 只展开被退出的作用域；`?` 的失败分支先保存 Err 返回值再清理。defer 首版在各退出点复制其有类型片段，正常 fallthrough 也展开；panic 路径不清理。记录展开后的 IR 数量，超出当前函数配额明确报错，不能无限复制。

运行检查作为有失败边的明确操作保留：零除、溢出、移位、索引边界等的失败块调用平台 panic 入口。MMIO／原子操作有独立指令标签，不将它们伪装成普通内存访问；即使将来加入优化，也不能随意删除或合并。

### 8.2 类型检查只建立一次事实

实现两个核心入口：`synth(expr)->TypeId` 和 `check(expr,expected)->CheckedExpr`。前者只处理能由局部信息定型的表达式；后者按已知期待类型检查字面量、构造和分支。已知函数签名逐项决定参数期待类型；字段名字从已知结构查出；转换按 R1 的显式表核对。不建立待解类型变量，不让后续使用回头修改已检查节点的类型。

每个节点检查后记录 TypeId、位置／值类别及已解析的声明编号，IR 生成消费这些结果。数组长度失败归常量阶段，调用参数不匹配归检查阶段，PCREL 越界归映像阶段；同一错误不在三层重复推断。诊断暂以稳定错误码、源范围、实际／期待类型为主，不先做纠错解析和自动修复建议框架。

各类型的布局查询状态只有 Unseen／Visiting／Ready；指针打断按值布局依赖，Visiting 的按值再入报告递归。透明别名另做解析环检测。常量表同样显式记录依赖及求值状态，不把布局等待塞进通用求解队列。

## 9 用户运行库只依赖哪些系统请求

所有请求通过一个普通 C ABI 汇编入口 `syscall6(n,a,b,c,d,e,f)->isize`；汇编把编号放 a7、六参数放 a0..a5，ecall 后取 a0。其他寄存器按 LP64 保存义务处理。SOS 错误为负数，成功为非负；用户库再构造具体 Result，不把这个约定扩展成完整 POSIX。

| 编号／请求 | 参数和结果 | 编译器为何需要 |
| --- | --- | --- |
| 0 EXIT | 状态码，不返回 | 成功／错误结束并回收进程 |
| 1 WRITE_CONSOLE | 字节地址、长度 → 已写长度 | 诊断，可短写 |
| 2 OPEN_READ | 名字地址、长度 → 只读句柄 | 读取源文件与 manifest |
| 3 CREATE_NEW | 名字地址、长度 → 新文件写句柄 | 创建临时输出，存在则错误 |
| 4 READ_AT | 句柄、偏移、缓冲地址、长度 → 字节数 | 无隐式文件游标；0 表示 EOF |
| 5 WRITE_AT | 同上 → 字节数 | 处理短写，不能假设一次完成 |
| 6 STAT | 句柄、输出记录地址 → 0 | 得到 size 和文件 version |
| 7 CLOSE | 句柄 → 0 | 结束文件引用；写文件关闭后才可发布 |
| 8 PUBLISH | 临时名字和目标名字各自地址／长度 → 0 | 替换完整构建产物 |
| 9 REMOVE | 名字地址、长度 → 0 | 清理失败构建遗留 |
| 10 FLUSH | 无参数 → 0 | 正常保存后的持久化边界 |
| 11 HEAP_GROW | 页数 → 新区域起始地址 | 构建 arenas，只增长 |
| 12 SPAWN | 程序名字、参数字节块及各长度 → 进程 ID | 启动下一代编译器／测试程序 |
| 13 WAIT | 进程 ID、退出记录地址 → 0 | 构建命令等待并显示结果 |

参数按表中顺序占用参数寄存器；SPAWN 的顺序是 name_address、name_length、args_address、args_length，PUBLISH 类似。保留参数为 0，未知编号返回 Limit。STAT 的输出为 size:u64、version:u64；WAIT 的输出为 reason:u32、status:u32，reason 的 0／1／2 分别表示普通退出／panic／执行故障。WAIT 只准等待自身的子进程，成功后回收退出记录；重复等待返回 BadHandle。进程 ID 同样使用带代际的 u32，不能复用为另一子进程的身份。

BootArgs 固定头为 version:u32、total_bytes:u32、argc:u32、reserved:u32；后随 argc 个 `{offset:u32,length:u32}`，再放字符串字节。version=1，reserved=0，最多 64 参数、总计不超过 4096 字节；offset 相对块起点，必须落在描述符表之后。无隐式 NUL 或宿主指针。内核先完整复制并校验，再映射成新进程只读参数页。新进程入口 a0 指向该块；入口 sp 按 16 字节对齐；平台 `_start` 调用用户运行库的入口函数，返回状态经 EXIT 结束。

编译器 core 不知道是 Linux 还是 SOS 请求：runtime/sos.vt 和 runtime/linux.vt 提供相同的 open/read/write/heap 接口，不能用同一份 syscall 数字冒充兼容。Linux 适配须将启动参数转换成上述逻辑视图，不假设 Linux 初始栈已经采用 BootArgs。

句柄是进程私有槽号＋代际值，带读／写操作权限；首版每进程 128 槽。用 u32 的低 16 位槽号、高 16 位非零代际；代际耗尽的槽退休，不能回绕复用。跨进程不直接共享数值句柄，SPAWN 只由内核复制明确的控制台能力。

内核检查用户范围溢出、映射和权限，再分块复制。保持用户虚址而非长期借用用户内存的内核指针；等 I/O 完成后重新检查进程身份和映射。WAIT／文件 I/O 可以阻塞，编译器必须允许短读、短写、空间不足和取消。

第一版负返回值固定为 -1 NotFound、-2 Exists、-3 BadHandle、-4 Denied、-5 BadRange、-6 NoSpace、-7 Io、-8 Limit、-9 Busy。数值集中于同一个 ABI 文件，由内核与用户库同时使用。上述 14 项只覆盖构建运行库，GUI、输入、计时等系统接口另外登记和计费，不能宣称这就是完整系统的全部请求。

## 10 执行与等待不保留任意内核调用栈

每进程一条 U-mode 执行流，内核不抢占、不在普通内核代码中睡眠。用户态由定时中断轮转；系统请求在入口关中断的内核路径中完成一段有界工作，然后给出 Done／Waiting／Exited。

只有已登记的请求状态可以跨等待保存：

```text
PendingIo {
    process_slot, process_generation,
    operation, file_object, file_offset,
    user_buffer_address, requested, completed,
    bounce_buffer, device_request
}
```

设备完成后推进这张记录，完成时写回用户返回寄存器并将进程置 Ready。没有通用内核 continuation，也没有每个等待点自动保存 C 栈。处理函数须有工作额度；扫描较长 FAT 或复制较多字节时也保存显式进度，不能长期关中断。

陷入汇编保存每个进程的用户整数现场；普通 C ABI 分派器返回下一份待恢复的 TrapFrame 指针，汇编再恢复用户状态。现场切换发生在分派器返回之后，不在任意语言函数中换栈。没有 Ready 进程时进入平台 idle 路径，idle 的 S-mode 中断与用户陷入分别处理，禁止把内核栈误当用户帧。

终止进程先取消调度和等待登记，关闭句柄；仍被设备持有的 bounce buffer／请求描述符延迟到完成后释放，完成事件用进程代际识别失效接收者。最后释放用户页表和私有页。硬件 DMA 尚未完成时不能仅因进程已退出就复用缓冲区。

这些规则需要新的平台实现。现有 SOS 启动代码尚未提供委托、完整陷入、U-mode 或上述调度；不能沿用旧“陷阱链不得调度”的配置名称宣称已经支持。

## 11 存储先固定为一种小格式

候选磁盘 128 MiB，文件系统逻辑块 4096 字节，总计 32768 块；底层以设备支持的扇区完成一次逻辑块请求。单层目录，文件名是最多 96 个 UTF-8 字节的键，`compiler/parse.vt` 中的 `/` 只是名字字节，没有路径遍历和子目录实现。

| 块范围 | 内容 |
| --- | --- |
| 0 | superblock：magic、version、块大小／总数、目录位置、分配起点 |
| 1..32 | FAT：每块一个 little-endian u32 条目，共 128 KiB |
| 33..36 | 128 个目录项，每项 128 字节 |
| 37..32767 | 文件数据 |

FAT 的 0 表示空闲，`0xFFFFFFFF` 表示链尾，`0xFFFFFFFE` 表示保留；其他合法值必须落在数据块范围。读链限制访问次数不超过总块数，拒绝环、越界和保留块。无需第二套块位图。

目录项固定为：state:u32、name_len:u32、size:u64、head:u32、reserved:u32、version:u64、name:[96]u8；共 128 字节，按字段偏移序列化，不使用结构填充的宿主布局。

version 是新建文件时分配的全局单调非零 u64，替换同名文件不得复用；计数器随 superblock 保存，耗尽返回 Limit。它标识内容世代，不是时间戳。重启先核对目录中的最大 version，计数器落后或溢出时拒绝可写挂载，避免静默重复身份。

写入只能对新建临时文件进行；文件关闭后才可 PUBLISH 到目标名。已经打开的旧文件内容不可变，替换名字后旧链保留到最后一个读句柄关闭，防止编译期间编辑器覆盖正在读取的字节。版本改变时，编译器在全部输入读取结束后重新打开名字核对版本；任一变化则报告 SourceChanged，不把混合版本继续作为成功构建。

输出流程是 create temp → 循环写完整 → close → publish → flush。publish 在运行中的内核里串行化目录更新，但**不声称掉电事务原子性**；正常 flush 后重启保留，掉电损坏检测／修复是另一项能力。构建内核时保留上一份已知可启动映像，不直接覆盖唯一启动文件。

固件只需同一格式的只读子集和固定块驱动，加载 `system/kernel.elf`；失败可选择 `system/kernel.prev.elf`。同一链遍历／格式校验源码在固件和内核中编译使用，不复制两份不同算法。固件启动阶段可轮询块设备；内核使用完成事件适配相同传输核心。

## 12 自举序列与跨平台比较

| 产物 | 由谁生成 | 在哪里运行 | 此时证明什么 |
| --- | --- | --- | --- |
| C0 | 宿主 Rust 构建种子编译器 | 宿主 | 仅种子能力 |
| C1-linux | C0 编译 biomiya 编译器源码＋Linux 适配 | RV64 Linux／qemu-user | 目标语言可以表达编译器 |
| C2-linux | C1-linux 编译同一源码 | 同上 | 编译器首次自编译 |
| C3-linux | C2-linux 编译同一源码 | 同上 | 比较 C2／C3 固定点，继续跑行为用例 |
| C1-sos | 已验证的自编译器换 SOS 适配生成 | SOS U-mode | 系统请求、加载与资源管理能承载编译器 |

比较必须使用同一 profile、manifest、源码字节、配置和序列化规则；Linux ELF 与 SOS ELF 的入口适配不同，不要求彼此逐字节相同。可以比较两端针对同一 SOS manifest 产生的文件。

产物不含时间戳、宿主绝对路径、哈希随机种子或构建进程地址。直接逐字节 compare 即可验收，不以自制 SHA 工具为前提。相同输出不是编译器正确性的证明，仍须运行接受／拒绝与行为用例。

### 13.1 最近一次实现只做 B0／B1

本轮之后的第一批实现限制在 Core S 的命令入口、真实源码管线、机器编码与映像写出；使用 Linux 运行适配。暂不改旧 SOS，也不顺便加入语言新特性。这批工作完成时必须能从磁盘上的 `.vt` 输入生成并运行 ELF，而不是测试代码手工构造 IR。

最小验收组如下，均须从源码进入：

| 用例 | 要观察的结果 |
| --- | --- |
| 有类型整数运算与分支 | 直接 ELF 和原汇编路径得到同一结果 |
| 跨函数调用、超过八个标量参数 | 参数位置、栈对齐和结果正确 |
| 聚合参数及后续实参修改原对象 | 被调用者读到第一个实参形成时的快照 |
| 返回值加 defer 修改原局部 | 返回原快照，清理副作用发生一次 |
| 窄整数溢出、除零 | 进入规定的 panic 路径，不能静默截断／依赖机器例外 |
| 语法错误、未知名字、类型错误 | 非零退出，有正确源范围，不写出成功产物 |

阶段尚不支持某一输入时，它仍是未通过项，不能换成手工 AST／IR 后算整条链完成。现有 `tests/check.rs` 和 `tests/backend.rs` 的隔离测试继续有用，但不能替代此组验收。远跳边界由机器级专门用例补充，不要求把源码塞满无意义语句才触发大位移。

### 13.2 如何发现复杂度再次失控

每个里程碑附同一份账：手写编译器行数、生成表行数、运行库／汇编处理／映像工具行数分别计数；同列记录实际支持的验收组。旧编译器、Rust 种子和目标语言版本并存时分别列出，不能把重复实现合计误当最终保有规模，也不能漏记最终必须保留的种子及辅助工具。

构建器报告 source bytes、Name／Decl／Type 数量、最大单函数 AST／IR／栈帧、各 arena 实际用量、指令字节、回填数量；这些统计不进入被比较的 ELF。超过第 7 节配额时输出具体对象和用量。固定点生成成功后，用真实自编译数据修正容量，不用预估替代测量。

增加一个语言机制前，先提交最小 compiler/*.vt 用例，说明现有具体结构为什么不能清楚表达；同时列出要修改的解析、检查、布局、IR、ABI、运行库和诊断模块。需要跨阶段回流、第二套类型权威或新的隐式运行协议时，单独改变本合同并重算验收。这是比“尽量少写代码”更具体的复杂度关口。
