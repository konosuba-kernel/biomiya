## A1：聚合字段错误定位依赖上一个子表达式（P2，已复现行为缺陷）

- 位置：`core-s/next/q/check.vt:1036–1056`、`init.vt:180–197`；隐藏状态根源为 `types.vt:28–37` 的 `fail/locate`。
- 对应规约：§3 局部上下文显式传入；§6 诊断在拥有上下文的边界生成；§11 保留实际错误位置。
- 当前记录构造循环读取当前 FieldValue，但不定位它；前一字段的 `expr` / `build` 已把 `types::diagnostic` 移到前一字段的值。下一个字段不存在、重复或不可访问时，错误沿用旧位置。
- 最小例子：`make Pair { a:11, missing:22 }`。局部构造实际 `E_NAME file=1 byte=85`，85 指向 `11`，错误字段在 89；静态构造实际 byte=71 指向 `11`，错误字段在 75。重复字段的两个例子同样报到前一值，错误类别为 E_TYPE。八次调用均拒绝且未产生 ELF，因此这是定位问题，不能夸大为接受性/错码问题。不可访问分支由静态阅读发现共用相同状态，本轮没有另外运行权限例子。
- 影响：编辑器跳转到错误位置时落在合法字段；仅调整前一值的写法会改变后面字段错误的位置。`ownership.md` 所称解析游标隔离已经成立，但不能推出递归语义定位也完全正确。
- 改法：当前循环在字段校验前恢复 `parse::location(p/item)`，漏字段错误恢复整个记录构造 span；更稳妥的是让记录字段校验接受具体 span 并直接 `diagnose(code, span)`，避免“先 locate，经过任意递归，再 fail”的时序约定。不要为此引入通用上下文对象或全面错误 effect 框架。
- 验证：保留以上四个反例，断言错误落在当前字段；补跨模块私有字段和漏字段例子。后续修改如涉及 IR span，同时检验新增指令归属，不能只改文本输出。

## A2：公开切片操作没有表达调用者存储责任（P2，接口安全合同缺口）

- 位置：`core-s/next/q/lex.vt:274–308` 的 `decode`；`parse.vt:103–136` 的 `join/view`；`types.vt:53–58` 继续安全转发。
- 对应规约：§8 公共函数无法建立指针/切片的存活期与访问权时声明 unsafe，并写调用者责任；非显然 unsafe 要有就近证明。
- `decode(token, output)` 是普通 `pub fn`，只检查目标长度，然后在 unsafe 中写调用者提供的切片。长度不能证明 backing RAM 存活且可写。`join(a,b)` 在内部读取任意外来切片；`view` 返回可继续传递的裸视图，但没有说明它只借用原存储、不会延长寿命。S-next 没有借用证明，这些责任不能从参数类型中自动得到。
- 当前正常调用使用私有静态池或仍存活的局部 buffer，本轮未发现真实悬空调用，也没有执行故意非法内存探针；问题是 API 没有表达其真实前置条件，不是已经证实的内存破坏漏洞。
- 改法：将实际要求外部存储有效性的原语标为 `unsafe fn`，写清普通 RAM、读/写权限、有效期及输出视图借用范围，在具体调用点给出证明。对于总是从本模块持有的冻结来源产生的视图，可以保留安全接口，以受验证身份代替任意裸 slice。同步清理 `types::join/view` 的安全转发层，不能只在叶函数加 unsafe、然后由无合同的安全包装吞掉责任。
- 附带观测：六文件共有 140 个词法 `unsafe {`，没有 `SAFETY:` 字样。此数字只说明需要定向补证据，不表示 140 个块全部错误；私有静态计数器访问通常可由模块合同统一解释，不能机械逐块复制注释。
- 验证：调用点身份/生存期静态审查；编译现有直接消费者，确保需要责任的调用确实被 unsafe 检查约束。无需以非法内存崩溃作为“证明”。

## A3：InitData 仍把不同载荷混在平坦记录中（P2，维护风险）

- 位置：`core-s/next/q/init.vt:6–23,52–70,255–274,461–516`。
- 对应规约：§2 字段量纲；§5 具体枚举表达互斥状态及载荷；§3 接口表达真实动作。
- 外层 `DataEntry::Empty/Value` 只区分槽是否占用。实际语义仍是 `kind:u32` 加 `first/target/bits/data`：`target` 对 ADDRESS 是符号身份、对 REPEAT 是重复次数；`bits` 对 SCALAR 是值、对 STRING 是字节长度、对 REPEAT 是元素步长。`add(kind, ty, offset, bits, target)` 无法从签名区分这些单位。STRING 先由通用构造置空 data，再写回补指针；REPEAT 也要追加修改 first/all_zero。
- 影响/反例：未来改重复展开时，把 stride/count 或 target symbol 混用仍是类型正确的调用；新增 kind 只要未同步序列化，就掉入运行期 ERROR_INTERNAL，编译器不会要求补全该类别。这里描述的是由表示允许的错误，并非断言当前生产路径已经传错。
- 改法：保留 InitData 的类型、偏移、next 和经说明的 all_zero 缓存，将实际载荷改为具体 `InitValue` 枚举：Zero、Scalar(bits)、Address(symbol)、String(view)、Group(first)、Repeat(child/count/stride)。构造对应具体动作，序列化穷尽该小枚举。all_zero 的推导与建树动作在同一所有者内完成。无需通用树框架，也不把 Symbol/Init 节点等所有普通整数都立刻包装。
- 验证：已有静态零值/BSS、字符串、地址重定位、数组重复与嵌套聚合用例是重点；增加“重复包含指针的聚合”反例并比对实际加载行为。测量枚举后的 arena 大小与栈/复制成本，不只比较源码行数。

## A4：AST 把不同语法域混在同一闭合枚举，放大修改面（P3，结构改进候选）

- 位置：`core-s/next/q/parse.vt:386–425` 的 Syntax；`parse.vt:1459–1576` 的 name_of、`check.vt:1488–1607` 的 block_first、`check.vt:1637–1757` 的 match_arm；其他表达式/语句消费者有同样现象。
- 对应规约：§3 边界只暴露实际需要的合同；§4 长函数只是信号，要定位职责与控制流原因；§5 类型表达状态。
- 当前源码实际有 **38 个 Syntax 变体**，包括表达式、语句、模式、字段项、匹配臂。name_of 只需要 Name，却列出其余 37 项返回 no_name；block_first/match_arm 只接受一个类别，也列出 37 项拒绝。由于语言明确禁止 enum 整体 `_`，这不是作者忘写通配分支，不能建议使用本语言不存在的捷径。
- 影响：增加一条语句会迫使名称投影、字段投影、模式校验等与它无关的函数更新；大段 ERROR_INTERNAL/no_name 分支遮住真实逻辑。问题来自语法域共享一个闭合和式，不是“match 超过60行”本身。上面几个函数已经很浅，继续抽 part1/part2 不会解决。
- 改法：在实际修改 AST 时评估按表达式、语句、模式/辅助项分域的具体枚举与窄投影接口，仍用同一有界 arena 和现有世代，不要求不同堆分配器或 visitor 框架。先选一个垂直切片计算变体/投影/调用点总成本，再决定是否推广；枚举层级可能增加拷贝或代码，不能承诺必然缩行。若暂保留当前 flat AST，记录“穷尽覆盖与单 arena 简单性优先”的明确例外即可。
- 验证：保证新增单一域语法时只触及相应消费者；AST 身份、诊断、语言拒绝边界、自举和 Node 大小均不得倒退。这项不应阻挡小范围 K0 目标适配。

## 已有改进应保留

1. `rules.vt` 真正把标量/尺寸计算收为无表、无诊断、无 I/O 的叶函数。其 `ok + bits/size` 已说明失败时没有业务载荷；不因为新规约偏好枚举就强改所有谓词/二态结果。
2. `parse.vt:474–530` 校验私有句柄的槽和世代，并区分持久头部/函数临时数据。这不是用类型名字装饰裸索引；不可为减行退回无检验 u32。
3. `check.vt:1342–1352` 先固定赋值目标再求 RHS；`744–769` 求值完实参后提交稳定 ArgumentRange；`601–616` 清理使用保存实参并恢复 IR span。它们体现了执行顺序和所有权，不能为统一模板删掉。
4. `init.vt` 建树与序列化分开，序列化不重新读取 AST；A3 是完善现有分层，不建议把常量/静态初始化塞回后端。
5. 递归解析、常量/布局都有显式深度控制的主要入口；当前是单次用户态 compiler。没有理由拿内核 IRQ/step 禁令要求把它全改成显式事件状态机。其历史 1 MiB guest 栈自举证据仍有效，本轮也未宣称重新证明全部递归最大栈。
6. `parse::statement_inner` 已用早返回直接按语法分派；`check` 的函数生命周期有显式 begin/check/end。大文件仍需整理，但过去的重构已改变实际路径，不是只换了目录。
