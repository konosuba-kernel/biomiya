## 生命周期编排与一次完成接口

读取 main/check/model/rv64/blocking 后确认主驱动顺序：

```text
begin_function → check_body → verify_function
               → 可选 blocking.capture → emit_function → end_function
```

begin 检查 active、防止重入；重置函数 arena、绑定当前声明，并解析当前函数。end 清除函数计数、当前声明、绑定/清理/循环状态，重置 parse 与 ir。静态头部语法保持其独立寿命。

model 的 type/decl/field/param、slot/inst/arg/参数槽数组已私有，获取器检查索引且按值返回。complete_type 要求旧条目未完成、新条目有对齐且名义身份不变；complete_decl 要求旧 state=0、新 state=2 且身份不变，不能二次覆盖。后端只有读取这些语义表的路径。

verify_function 完成 IR 和布局检查后记录当前函数与 function_revision；slot/inst/arg/参数标记/reset 会改变 revision。emit_function 核对函数和 revision，并一次性消费验证票据。Blocking.capture 读取语义 IR、提取稳定 DeclId/Span，不修改函数表。没有把 IR 合法性检查因 enum 加入而删除。

**额外实际探针**使用冻结 B 构建当前候选 P 的被测模块；这是测试 P 的内部接口，并非声称 P 能编译自身旧语法。记录为 owner-results.json，保存被测源哈希、B 哈希、构建/运行命令及驱动源码：

| 探针 | 实际结果 |
| --- | --- |
| type_complete_once | 新建未完成 Type 后完成一次，退出 42 |
| type_complete_twice | 相同 Type 再完成一次，I_INTERNAL |
| decl_complete_once | 新建 state=0 的 Decl 完成为 2，退出 42 |
| decl_complete_twice | 相同 Decl 再完成一次，I_INTERNAL |
| verify_mutation_rejected | verify 后追加 arg，再 emit，I_INTERNAL file=2 byte=17 |
| verification_ticket_consumed | verify 后 emit 两次，第二次 I_INTERNAL file=2 byte=17 |

最后两个基于候选 next/tests/machine.vt 的独立临时副本：把包装器中的 rv64::function(id) 分别替换为 `verify_function; add_arg(0); emit_function` 和 `verify_function; emit_function; emit_function`。生产文件未修改。前四个只选入 model 与 linux.s0，使用完整普通 Type/Decl 初始化，先验证成功路径再增加重复完成调用。

此处通过的是 P 的编排和接口边界。裸 u32 旧 ID 在下一函数同索引重用后仍没有名义世代保证；add_* 接口也不是语言层不可变借用。最终 Q owner 的封口/世代门槛不能从上述结果外推。

## 成本偏差与未闭合门槛

本候选生产 14 个 VT 模块为 **8,572 行、250,930 字节**。相对 P2 r5 增加 470 行、13,456 字节；距离原暂定 8,000 行预算超出 572 行。包括复用运行库的 VT 为 257,708 字节，加所选 linux.s0 后构建输入共 258,053 字节。目标 ELF 为 1,071,176 字节，RW 为 54,044,724 字节，映像跨度为 54,913,076 字节，仍低于 64 MiB。

表示支持与试点的结果通过，不等于复杂度目标已达成。root 已明确后续在 Q 落实真实 AST/IR 变体、opaque nominal IDs、生命周期世代并重新核账；原 P3 的这些验收项应在 DAG/方案中保留依赖并标为待复验，不能用 toy 的 42 和 epoch 抵销。P4 固定点、目标机器与源码扰动，以及 P5 系统验收尚待完成。整个计划当前仍不应标记完成。
