## 已核对语义

整型 as 仅支持整数，拓宽零扩展、缩窄截断，不给左侧字面量反传类型；const 与运行期一致。空结构和零数组布局可用，零重复仍执行元素表达式一次。私有字段对构造、zero、静态初始化和匹配取出的载荷均有效；零长度数组不能绕过私有字段检查；首标签无载荷的 enum zero 不检查非活动载荷的私有字段。私有字段本身可使用私有类型，公开字段和公开签名不可以。

同模块前向 const 拒绝，导入模块先完成；const 不采用运行期短路跳过错误。unsafe fn 的函数体仍需显式 unsafe。普通静态根取址不会执行可变静态读写，可以安全取得地址；解引用另需 unsafe。defer 登记时快照、return 先保存值、panic 不展开，与既有独立 P1/P3 证据一致。enum match 穷尽、整枚举 wildcard 拒绝，bool wildcard 允许。core::panic 调用不替代显式正常返回路径检查。

## 需要补充的参考信息

1. **运算优先级/结合性缺失。** r1 从低到高：`||`、`&&`、`== !=`、`< <= > >=`、`|`、`^`、`&`、`<< >>`、`+ - +% -%`、`* / % *%`、`as`、一元、调用/字段/下标。二元运算左结合。尤其位运算比比较结合更紧，不能让使用者按 C 规则猜测。来源：冻结 parse::precedence 与 expression。
2. **整数 match 的模式限制应说清。** 模式只接受整数字面量、bool 字面量、具体枚举标签和允许位置的 `_`；整数模式不支持命名 const、算式或 cast。`const X:u32=42; match 42_u32 { X=>{...}, _=>{...} }` 在 r1 报 E_TYPE。
3. **用户输出 ELF 的容量不能只表述为自编译预算。** image 限制所有输出的映像跨度不超过 64 MiB，文本最多 8 MiB；model 的初始化数据缓冲为 8 MiB。单函数 frame 上限 256 KiB。这些与“编译器自编译用 1 MiB guest 栈”的验收条件不同。可顺带说明固定地址、静态 ELF、无动态链接/PIE，避免误认为完整 Linux 编译工具链。
4. **关键 ABI 规则不宜只藏在旧手册链接中。** 未调用的 extern 也需有定义；跨模块同短名字 extern 共享链接符号；x27 保留 Linux 初始栈指针，汇编适配必须保持。旧 B3.1 链接页确实有这些规则，建议新版也直接保留关键句。
5. **发布身份指引尚未闭合。** 本次审查时 `next/q/release.json` 不存在；末尾指引必须在最终发布时创建对应内容或换成实际存在的身份文件。当前 JSON 只允许 r1 hash，不能用来验证之后的 R-ID 候选，须更新后再跑 3 个文档示例。

零尺寸对象地址与存储占位是实现细节：探针观察到两个零尺寸 static 的地址不同，不能由此扩大为“所有零尺寸局部地址都唯一”的语言保证。现手册没有作此承诺，维持即可。
