# P3 数据表示试点

**状态：源码与布局预测已准备，尚未用 S-next 候选编译和执行。** 这些样本不表示主编译器 AST/IR 已迁移，更不构成 P3 或 P4 完成证据。所有编译器修改都在本目录之外；本目录仅交付小型对照和决策材料。

## 完整程序与对照条件

`typed.vt` 与 `tagged.vt` 是互斥的 `trial::arena` 实现。前者采用具体 `Expr`、`Instruction` 变体及私有字段 `NodeId` / `SlotId`；后者用整数 tag、复用的 a/b/bits 字段和 u32 ID。两者都有相同的 arena 容量、合法性检查、世代编码、构造顺序、IR 执行算法和错误策略，避免把“删除检查”算成数据建模收益。

`program.vt` / `tagged_program.vt` 分别建立 `20+22` 和下一函数的 `40+2`，递归降低为 Constant/Add/Return IR，逐条遍历算出 42。两次函数构建复用同一静态 arena；旧 NodeId/SlotId 在 end 后和下一次 begin 后都不再有效。正确结果通过进程退出 **42** 表达，布局预测也由程序内 `sizeof` 检查。

句柄是单字段 u32 结构，高 16 位是函数世代，低 16 位是非零索引。arena 数组私有；所有读取检查 active、世代与有效范围；begin 在世代 65,535 时拒绝继续，不能回绕复活旧 ID。构造 Add 只接受已分配节点，禁止未来引用，因此不需要另一个图循环检查器。这里的 epoch 只覆盖本次进程内函数生命周期，不是磁盘持久句柄或并发共享句柄。

`cases.json` 列明 7 个待执行用例：两个程序退出 42；NodeId 误传 SlotId 必须 E_TYPE，而整数 ID 对照同一误传会编译通过；跨模块私有 raw 构造拒绝；两方案的 stale ID 都应 panic 101。类型区分与生命周期检查是两个独立保证，不能互相替代。

## 错误面与局限

具体变体让错误载荷类型、缺少标签分支、NodeId/SlotId 混传及外部原始 ID 构造在编译时拒绝。字段名字也把“a 到底是值、指针还是声明”转为局部可读的数据合同。

两方案仍都需要检查容量、世代、索引、已定义槽、控制流终结与算术。具体变体不会证明一个 Call 的参数个数正确，也不会证明借来的地址仍然存活；unsafe 仍可破坏表示。整条指令带错 source span、SlotId 指向错误类型、局部地址越界等也不会因 enum 自动消失。

完整 IR 与 AST 迁移建议及估算见 [Q 迁移评估](q-migration.md)。建议先迁真实 IR，再迁真实 AST；完成一个表示替换后删除旧类型和字段路径，避免“新 enum + RawInst 解包”长期并存。
