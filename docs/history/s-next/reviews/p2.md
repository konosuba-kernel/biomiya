## 阻断项：指针后面的数组被误判成按值递归

最小输入：

```text
module sample;
struct Node { next:*[1]Node }
fn run()->u32 { return sizeof(Node) as u32; }
```

递归路径经过指针，所以 Node 的有限布局应为 8 字节，数组 pointee 的布局在 Node 完成后可得到。r4 以 E_TYPE 拒绝。实际压成一行的探针诊断为 `E_TYPE file=1 byte=34`，输入和命令保存在 `build/snext-p2-independent-review/pointer_to_recursive_array/result.json`。

根因调用路径：`types.syntax_type` 先递归处理指针的元素 TypeSyntax；元素是数组时，`intern(TYPE_ARRAY)` 立即调用 `layout(a)`；这时 Node 正在准备，`prepare` 将其判为循环。它检查的是解析/建型调用栈，而不是仅按值布局依赖图，因此把合法指针断开的依赖也算作循环。

应区分具体类型身份建立和实际布局依赖：建立指针/切片的目标复合类型身份不要求立即完成目标布局；数组、记录按值边才要求完整元素布局。修复后须验证 `*[1]Node`、切片含数组元素，以及真正的 `[1]Node` 按值循环仍拒绝。不要用特判该样本或统一接受所有循环修复。

## 结构合同核对

已确认：

- parse 只导入 model/lex，无 types/check 依赖；语法树保存路径和 TypeSyntax，不调用 resolve/layout/shadowed；make 为明确入口，无 head 猜测。
- prepare/layout/constant_value 不读 token、不调用 lexer、不 seek。types.collect 的 headers_collect 是一次阶段编排入口，不是布局递归回扫。Header 保存声明信息、初始化 AST 与函数体范围；后续函数体 seek 是允许的逐函数解析。
- 常量和数组长度使用 parse.expression 生成的同类 AST；受限常量求值在 types.constant_inner 中按允许节点解释，没有 token Pratt 求值器。
- init.build 先检查类型、字段、权限和全部子项，构成私有 InitData；serialize 只读取 InitData、已完成布局，写数据与重定位，不重新读取 AST 或解析名字。零重复也先 build 子项。
- 常量按导入依赖完成、同模块声明顺序求值，普通按值循环和导入环有错误路径。简单指针递归通过，但尚不足以涵盖上述合法复合 pointee。

还需精确描述的一处方案差异：§4 明列“HeaderSyntax → 已绑定声明 → 常量/布局”。当前 prepare 中仍经 syntax_type → named_type → resolve 在布局期间解析类型名，没有独立的先绑定所有类型引用阶段。它已经实现语法/语义分离，不能描述成完整三段分离。此项已反馈实施者；最终阶段声明必须与实际架构一致，若调整阶段边界需明确记入方案，不能静默删掉承诺。

## 两项 r4 问题的关闭依据

**合法递归数组 pointee：已修复。** intern(TYPE_ARRAY) 只建立稳定类型身份，先留 size/align 为未完成；layout 对数组只沿元素的按值边递归，指针和切片已有固定尺寸，不递归要求其目标立即完成。finish_layouts 在声明处理后完成所有具体派生类型，确保未完成的 pointee 数组不会带入后端。下面同时验证了允许和禁止的递归图，未发现通过简单跳过循环检查放宽规则。

**绑定与布局混合：已分离。** bind_headers 在常量求值和 prepare 前执行，通过 nominal_types 把具名 TypeSyntax 绑定到稳定类型身份，通过 value_decls 把常量表达式名字绑定到 DeclId；public 签名可见性在此检查。syntax_type 读取绑定侧表并具体化派生类型，constant_inner 读取绑定 DeclId，不再 resolve。常量是否已完成仍在求值时按 d.state 判断，所以预先绑定身份不等于允许前向常量值。

每个函数 parse 后由 bind_function_types 覆写该函数语法区间的侧表，再具体化全部局部 TypeSyntax 并 finish_layouts；check.function 最后也完成新增类型。Header 对应范围不随函数复用清空，函数范围不会从前一个函数继承绑定。只读审查确认 prepare/layout/constant 路径仍不调用扫描器；parse 仍不做语义查找；InitData serializer 的边界未退回 AST 或名字重解析。

## 预算偏差与后续边界

r5 的 14 个生产 VT 模块合计 **8,102 物理行、237,474 字节**，超过方案第一轮暂定 8,000 行预算 102 行。此次关闭了可复现语义缺陷和阶段耦合，P2 阶段门槛可通过；这不代表最终复杂度预算也已经通过。P3 的总成本账本必须处理该偏差，报告枚举、ID/状态边界、运行库和样本的净成本，不能继续引用 r4 的 7,944 行，也不能靠压行隐藏。

新状态/ID 所有权、具体变体、最终语言参考、Q 自编译和系统切片仍按 P3–P5 独立验收。本通过结论仅适用于上述 r5 身份与 P2 合同；上游类型/初始化规则变化时，关联证据需要复核。
