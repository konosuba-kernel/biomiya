# B3.1 维护重构

2026-10-11。本次沿用 [B3.1 语言合同](reference/b3.1.md)，目标是使分支结构与职责可直接阅读。比较基线为 Git `61d10a2` 的 13 个生产 VT 模块；Rust 种子、运行库、ABI、容量常量和语言能力未修改。

## 实现变化

移除 114 处仅包裹一个 `if` 的 `else` 块，写为 `else if`。删除的块中没有独立绑定或收尾动作；真实的子条件保留嵌套。除了三个主要模块，词法、类型、输入、汇编和映像处理中的同类分派也采用这一写法。

- [parse.vt](../bootstrap/parse.vt)：`primary` 解析初始表达式，数组与路径/构造器各有处理函数；`expression_inner` 只扩展后缀及二元运算。读取 token 的次序、`head` 限制、优先级及递归预算入口保持原有规则。
- [check.vt](../bootstrap/check.vt)：提取名字、一元运算、字段、结构和数组处理函数。它们仍向当前函数的 IR 写入；不是纯函数。每个表达式仍经 `expr` 管理递归深度，并在 `expr_inner` 末尾统一执行 `same(value, expected)`，避免某个分支绕过预期类型核对。
- [rv64.vt](../bootstrap/rv64.vt)：独立存储指令和返回序列的生成。标量结果统一从 x5 写回；复制、聚合加载、存储、调用与控制流分支在各自处理后返回。指令校验仍先于发射，后端只修改自己的帧偏移和标签工作表。

行数包含空行、注释和函数边界；缩进按四空格一层统计，包含 `unsafe`、循环和记录构造，不是圈复杂度。函数变短有一部分来自提取函数；源码字节减少有很大部分来自缩进。不能据此声称语义复杂度等比例减少。

目标 RW 段仍为 53,118,748 字节，映像跨度为 53,995,292 字节，均低于 64 MiB。自编译最大单函数 frame 仍为 26,384 字节；这不是调用链峰值或进程峰值 RSS。

## 后续维护约定

增加表达式种类时，先明确其类型输入、IR 输出和求值顺序，再接入分派；不得绕过统一的预期类型核对。增加机器指令时，明确其是否产生标量结果，决定是否进入共同写回。解析的新递归入口必须沿用既有深度守卫。

独立算法适合提取为有名字的函数；几行直白的平级分支可留在分派中。不要为了缩短行数增加间接调用、注册表或通用 pass 框架。纯规则继续集中在 `rules.vt`，读取游标和写入 arena 的函数应明确保留副作用。

仍待处理的是共享可变表的隐式依赖、部分 `Node`/`Inst` 字段的复用，以及 Rust/VT 两套实现的行为同步。这次没有把它们变成显式上下文，也没有消除全部长函数。后续应按单个阶段逐步收拢状态所有权，每次保持自举固定点与行为对照可运行。
