## 正式验收前应补足的区分力

1. **保留布局能力不能只变成拒绝测试。** 原 reference_layout 同时测 Pair 的大小/对齐和零长度数组对齐；因 Result 拒绝整个样本后，这些保留规则不再得到该样本覆盖。建议另加不含 Result 的成功样本，独立计算 `sizeof(Pair)=16`、`alignof(Pair)=8`、`alignof([0]usize)=8`。pointer_cycle 目前只验证两个指针字段的 sizeof，不能代替混合宽度字段与空数组对齐。
2. **错误码不能证明诊断位置。** 当前工具只要求 E_TYPE/E_NAME 等错误码。P2 改变扫描器和语义阶段边界，应至少以跨文件声明错误、函数内错误和静态初始化错误，断言具体 file/byte，证明错误位置来自对应语法 Span，不是最后扫描位置。
3. **迁移集合需要完整性约束。** 验证器当前按 cases.json 现有项目循环，最后数量也来自现有列表；删除一个样本并不会自动报迁移遗漏。当前人工已核对 59 项全部存在，正式运行前应继续核对，或加入以 P1 37 个身份及参考 22 个身份为基准的覆盖断言。新例数量可以增长，不能用固定总数替代身份覆盖。

这些建议是避免丢失已保留合同或让测试证明不充分，不要求复制大量同构样本。11 项 retained input/machine 测试仍需在最终候选实际运行；此前成功不能自动转移到 P2。

## 待候选冻结后的独立验收方案

首先固定 ELF、manifest 的所有生产/运行支持输入、测试与工具的内容哈希。审查最终验证 JSON、构建跟踪、candidate-source.tar 与 retained 日志，核对实际执行数量、期望和失败时不发布输出。完整测试由实施者运行后，在身份一致的前提下不重复全套；独立补充少量针对性组合探针。

结构验收必须同时做源码调用路径检查，不能仅靠运行例子：

- 声明头仅解析一次，函数体以 BodyRange 后续解析；布局和常量求值不能保存/恢复扫描器或调用 seek、lex.next 等入口，间接调用同样检查。
- 表达式只有一个语法入口；布局前常量解释 AST 允许集合，禁止 sizeof/alignof、函数、地址、前向常量；没有隐蔽的第二套 token 运算器。
- 结构构造保留显式 make 路径；语法解析不调用 resolve/layout/shadowed，也不使用 head 开关决定结构与块。
- 静态初始化先形成已定型的 InitData，序列化只消费其值与重定位；序列化器不重新 resolve、不检查 AST 源语法。零重复长度中的错误仍被检查。
- 具名身份可前向登记，指针递归接受、按值循环拒绝；导入拓扑先于所依赖常量完成。语言级环有确定错误，而非 guest 栈溢出。

拟追加的独立探针按最终已有覆盖选择，不机械重复：

| 风险 | 探针设计 |
| --- | --- |
| 布局查询偷偷回流 | 正常函数 sizeof/alignof 成功；通过 const、数组长度两种入口使用同类表达式失败，检查准确位置 |
| 遍历/清单顺序泄漏 | 两个模块跨文件导入常量，改变 source 清单顺序仍得到同一语义；同模块后声明常量不得因预先登记而可用 |
| 解析依赖符号表 | 前向结构与同名局部值配合显式 make；条件块、注释/字符串中的括号不改变 BodyRange；不应语法回退猜测 |
| 静态验证与序列化混淆 | 嵌套记录/数组末项非法、零重复非法与带静态根重定位的合法对象，分别检查完整验证和运行结果 |
| P1 回归 | 保留聚合实参快照和循环/return 清理组合；新 AST 表或解析方式不能改变执行顺序 |

P2 的结构合同未满足时，即使 87 项全部成功也不判通过。P3 的枚举/ID/所有权、自举固定点及系统切片仍有各自门槛；本预检不提前验收它们。
