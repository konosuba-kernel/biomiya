# Core B 原型结果与下一步

结论：继续采用用户选择的 B 规则；已验证直接定型和 ConstValue 的有界执行路径可行，**尚未证明完整编译器净缩减或整体维护成本下降**。下一步以现有完整 Core 为底座做同范围替换试点，实际删除重复机制后再评估规模。不把受限原型的行数外推为完整编译器的行数。

## 已验证的结果

此前完整 Core 0.5 已提交为 `8bd7ffe8736c5996f6ddf2ac501dd2be3ac99088`。330 个提交文件逐个匹配已独立验收的冻结基线。原产品源码与现行 reference 尚未采用 B 规则。

规则采用 [R2 草案](core-b-rules.md)，原型范围遵守 [接口合同](core-b-prototype.md)。P2 检查器和 V3 常量执行器分别经过实施、失败审查、修复和独立复验；E1 组合及维护实验也已独立通过。

- P 只有一个表达式类型规则入口，使用已知期待类型和确定的子表达式结果；定义点与实例点复用该入口，没有旧求解器兜底。泛型实例使用有界工作队列。18 组检查测试与独立输入验证通过，真实完整运行管线示例返回 42、3，独立示例返回 43。
- V 用 ConstValue 保存结果，允许性检查遍历全部分支，执行只走选中路径，序列化消费值和布局。10 组测试及独立反例复验通过，真实 RV64 镜像验证了聚合值与符号重定位。
- E 将 6 个真实源码用例经 P 的真实 HIR 交给 V，再生成 Data、RV64 镜像；12 次候选／冻结基线运行全部通过。这里的静态声明前端仍由实验 harness 代替接线，不是生产集成。
- 审查修复了移位右项期待传播、同层重复绑定、死分支未支持常量操作和包装值类型核对错误。既有测试成功不能代替独立反例。

## 扩大迁移的决定

**进入机制替换试点，暂不把当前原型当完整新版。** P 尚不支持名义声明、数组、借用／拥有、方法、defer、?、完整 ABI 等；V 尚不覆盖全部常量操作。泛型依赖长度禁令 T2、deferred 移除和完整 Extend 传输均未证明。给这个原型补齐所有能力再比较，会长期保留两套实现，也无法及早测到真实删除量。

后续按依赖顺序推进：

1. 在冻结提交的隔离试点中实施完整 T1：用单向检查替换同级约束收集与 Span hint 回灌，保留完整 Core 的其余能力。迁移显式泛型调用和期待类型规则，直接删除不再使用的求解路径。该阶段是 T1 实验配置，不冒充完成 T2 的 Core 0.6。
2. 对完整原有覆盖建立逐断言迁移清单：分别验证保留行为、T1 有意拒绝及迁移后的等效行为。保持 ABI、目标运行、清理快照与 Extend 断言；不能以 unsupported 通过完整替换验收。规范已确认的旧字段投影误拒无需复制。
3. 独立验收真实净行数、规则权威位置与目标执行。若旧求解器仍在运行、出现第二套表达式规则、丢失完整能力，或新增实现抵消删除量，就修订试点，不扩大迁移。
4. 在这个结果上实施 T2 与完整常量值／布局接线，验证定义依赖、死分支、别名和常量／布局循环，再移除旧上下文重放与重复常量执行。共享接口先冻结，只有互斥写入范围并行。

这样可以先回答“删掉一整个机制之后，完整编译器实际省了多少”。9,000／5,000 行目标目前仍无实测可达性依据。下一阶段继续使用 DAG 的节点实施与独立验收，不把原型通过变成生产交付通过。
