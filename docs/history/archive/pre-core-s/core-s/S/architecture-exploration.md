# Core S 编译器架构探索

此文件在 L/K 验收前仅作为独立架构探索，不是 S 候选或已通过证据；最终规则以整合文档为准。

## 数据流

源码 → token/AST → 声明与具体类型表 → 常量和布局 → 按函数检查并生成有类型控制流 IR → RV64 汇编。

函数签名先登记，支持直接递归和前向调用。每个函数体仅完成一次正式类型检查与 IR 构造；不用实例队列。当前表达式输入可携带已知目标类型以检查字面量和构造，输出必须是具体类型，不能留下未知变量或反向修改兄弟节点。

位置检查产生 Place，值检查产生 Operand。字段/索引只计算位置或按需加载，不用读取整个基址聚合。检查器在同一处定义调用/复制/转换语义，后端只按已决操作发射指令。表达式求值仍按源顺序保存必要值；不能用减少 IR 层为理由改变实参快照或退出清理。

不维护一套完整的 HIR 与另一套独立解释其规则的降低器。AST 保留源结构；IR 的操作记录声明/类型/源码身份、位置投影和作用域，供 Extend 只读访问。是否需要很小的检查结果结构由接口需要决定，不能复制完整表达式语言。

defer 的词法名字在注册时绑定，检查后的清理片段在退出处展开；只保留每个活动词法作用域的清理列表。return/?/break/continue 共用 exit_scopes。IR 可以复制片段，不能每个出口重新进行类型推导或重新解析名字。panic 不走 cleanup。

常量按 L 的受限文法独立检查和求值，输出定宽标量或固定初始化数据，避免把整个运行时表达式解释器带回来。常量和布局依赖用一个明确的有向依赖模型；循环检查不能因缓存而跳过。

## 模块边界

- syntax：词法、文法、源码位置。
- resolve/types：声明、作用域、具体类型身份与签名。
- constants/layout：受限常量、静态初始化数据、尺寸/对齐/重定位。
- check/IR：唯一语义检查入口、显式 Place/Operand、结构化退出与控制流。
- rv64：简单帧布局、明确 ABI、RV64 发射与机器事实。
- driver：输入、外部汇编链接、报告和诊断。
- extend：同版本只读视图、最小注册/执行接口、结果状态，不实现验证器。

模块数不作为规模指标。最终需统计全部手写编译器、驱动和 Extend 代码，并单列生成数据、运行时、平台代码、支持库、生成工具和测试；不得把替代算法移到支持库后从交付总账消失。数千行仍需实现试点验证，没有净缩减百分比承诺。

## 未来实施验收的重点

1. 用户泛型和省略绑定类型被稳定拒绝；无约束求解、实例图和模板重放数据结构。
2. 同一标量/聚合复制后源值仍可用；句柄复制不插入 retain/release，不声称保证唯一释放。
3. 指针/切片 const 性、地址空间和显式转换接受集封闭；无自动解引用或借用。
4. 浅层 match 的标签重复、遗漏和载荷绑定类型错误均拒绝；嵌套模式拒绝。
5. 所有正常退出上仅执行已注册的 defer，顺序 LIFO；保存返回值在清理之前；panic 不执行剩余清理。
6. 常量语法外表达式拒绝；常量/布局/静态初始化的前向依赖、循环和溢出有区分力的正反例。
7. 实参逐个快照、赋值顺序、数组和切片边界、原子与 MMIO 的访问宽度按设计在真实 RV64 运行。
8. 对 C 标量/指针 ABI 作双向及超八参数验证，聚合按值 FFI 拒绝；无未声明 C shim。
9. 在未来编译器上实际构建页表操作、原子锁、MMIO和ctx+ops、失败回滚样例；通过之前不得声称可以移植整个内核。
10. Extend 只报告实际实现的分析。旧 Borrow/Ownership 规则不作为新值复制模型的默认保证。
