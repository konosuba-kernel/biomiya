## 架构：保留的真实收益

Q 使用具体 Syntax、TypeForm、Instruction、Binary/UnaryOperator；无 RawNode/RawInst 作为另一套实际执行通道。解析没有调用语义 resolve/layout；布局通过已绑定侧表读类型语法，不重新 seek 源文本。InitData 的序列化阶段不依赖 AST 或名字查找。

NodeId/TypeSyntaxId 与 SlotId/LabelId/ArgumentRange 私有字段及世代真实有效。静态头部语法保留独立寿命，函数临时引用在结束和下一次复用时失效。IR 在 finish_ir 后禁止构造变更，后端验证票据绑定当前函数和 revision，emit 消费票据。main 按 begin/check/verify/analyze/emit/end 编排，Blocking 提取稳定摘要。这些边界改善可维护性，独立探针也确实区分了错误；不能只因新增行数而全部退回。

## 架构拒绝项与最小补救

### A. 稳定身份仍混用裸整数

方案 §3.6 明确要求 NameId、TypeId、SlotId 等以不同结构表示；r1 的 Name/Type/Decl/Symbol 均仍是 u32，只有临时身份迁移完成。因此不能称原承诺已完成。

特别是 model::Type.a 同时承载 Pointer/Array/Slice 的元素 TypeId 和 Struct/Enum 的 owner DeclId。机械包成 TypeId 再到处解包回整数不会建立真实边界。最低修复应先拆开这两个具体含义，区分 kind 数值与 primitive TypeId，然后让 NameId/TypeId 从生产输入、表项到查询接口全程保持名义类型；转换只能在拥有者的受检表索引边界。稳定 Decl/Symbol 身份的剩余类别保证也应明确列账，不能暗示所有 ID 都已受类型系统区分。

验收应添加直接对生产 model 的跨 NameId/TypeId 传参拒绝和私有构造拒绝，失败位置必须在调用者；同时保留现有 Type/Decl 一次完成和非法 IR 测试。不要通过公共 raw 构造/转换函数让类别保证退化为空壳。

### B. SourceStore 与 ImageBuilder 仍可绕过拥有者写入

r1 的 model::sources、assemblies、names/imports，以及 data_objs、data_relocations、symbols、fixups、data_bytes 和各自计数均公开。image 自己的机器字节数组私有，并不足以证明整个映像拥有者成立。具体生产写入口如下：

| 当前写入口 | 最小必要边界 |
| --- | --- |
| input.vt:180–218 增加 source/assembly count、登记记录、写 bytes | 表和计数私有；受检登记、一次填充、输入 freeze；按值读取或只读视图 |
| parse.vt:1366 为 module/import 元数据覆盖整个 Source | 单独一次完成模块元数据，不能替换 path/bytes；不必复制源码 buffer |
| image::define 写 symbols 的 defined/region/offset | 私有表内的 define-once；对身份、区域和重复定义检查 |
| image::reset 清 fixup_count | 由拥有者控制开始/结束阶段，不开放任意计数重置 |
| init 的标量序列化和 repeat 直接写 data_bytes | 拥有者内范围受检写入/拷贝；以对象或有效范围约束，不给任意可写 slice |
| model 的 add_data/add_symbol/add_fixup 等容量受检追加 | 保留具体追加操作，但数据表/计数不能让调用者绕过追加路径 |
| image::put、word、patch_word、data、fixup | 任意 put 私有；发射/修补入口受阶段约束，最终完成后拒绝写入 |

源码 buffer 已由 input 私有，外部使用 const slice，因此不需要新增 SourceStore 大对象或数据复制。可以保留分散的静态单一存储，只把合法写入口收拢；无需为每个字段新增机械 getter/setter。

生命周期必须与实际顺序一致：main 当前先 types::collect/init::collect，再 image::reset。新增 reset 不能清掉此前已经生成的声明符号和静态数据；应区分整次编译初始化、开始文本发射和最终封口。最终验收需要至少覆盖输入 freeze 后替换/追加拒绝、Source 元数据不能改 bytes、映像完成后追加/patch 拒绝，以及合法完整链。

## 成本与可删除重复

按 r1 冻结源重新统计，14 个生产 VT 共 **10,549 物理行、316,311 字节**，比 P 的 8,572 行增加 **1,977 行（约 23.1%）**；比 8,000 行软预算高 **2,549 行（约 31.9%）**。运行支持另计。不能因为采用 enum 就称实现已经简洁或优雅。

增加量里既有必要生命周期检查，也有重复的穷尽分派。r1 有 38 个 Syntax 变体，多个辅助函数只需要其中一个，仍逐项重复剩余 37 个分支：

- parse::name_value 为 119 行，check::bare_name 为 43 行，types::bind_range 与 init::static_address 还各自展开取 Name 的分派。共享一个受检 name 查询及零哨兵即可删除重复；不删除检查器真正的表达式语义分派。
- FieldValue 解包在 check::field_pair 的 45 行与 init::record_field 的 122 行中重复。共享具体 payload 查询，并由调用者保留各自诊断，优于再建 RawNode 或通用 visitor。
- defer 已在解析端由 parse::is_call 的 118 行检查，检查端又用 direct_call 的 45 行重新判别。让 Defer 保存已经解析的具体 Call payload，可移除二次全变体判别；需保持调用实参快照和 cleanup 测试。
- model 中旧 AST_* 常量共 38 个，Q 生产模块已没有引用，可删除这组迁移残留。

以上是可定位的候选删除点，不是承诺这些函数整段行数都可净删；真正净收益要以修复后的源和测试重新量测。不要通过压缩多语句、自动生成隐藏样板、增加 wildcard 破坏既定穷尽规则来美化行数。也不建议为减少分支立刻增加泛型、visitor、匹配新语法或完整函数式框架。

下一候选应优先补齐上述真实边界，再做这些小范围合并，重跑固定点、语言、输入、机器、手册及 P5；原 r1 的机械通过只能作为比较基线。整个执行计划本次仍未完成。
