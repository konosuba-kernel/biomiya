## 实际机器与资源合同

读取 `system.vt`、`file_rollback.vt`、monitor、适配器和三个宿主工具，并独立重跑主 system ELF 与 Linux 文件程序。

- QEMU 命令实际为 virt、rv64、128 MiB RAM、`-smp 2`、`-bios none`；monitor 用 hart ID 将 hart 1 放入邮箱工作循环。4096 次请求的 payload 经 release 发布，工作 hart 用 acquire 取请求、release 发布响应，hart 0 acquire 等待并检查每次结果 `value+17`。这不是把普通内存读写计为原子同步。
- UART 实际访问 `0x10000000`：LSR 使用 `lbu`、数据使用 `sb`，写前后 `fence iorw,iorw`。独立机器重跑实际 stdout 为 `P5 OK\n`、退出 0。
- 页表为 Sv39 level-1 的 2 MiB 叶子，安装入口受槽位、flags、PPN 对齐及范围约束。系统程序通过 alias 与 direct 地址双向读写，确实访问映射后的 RAM；分配成功与第二次分配失败均验证 defer 回滚 bitmap。
- 独立 Linux strace 观察 `/dev/null` 以 O_WRONLY 打开，read 得 EBADF，defer 唯一成功 close，随后第二次 close 与清理失败策略各得到 EBADF；最终退出 0。它证明真实 FD 生命周期，而非替代计数器。

原始平台/应用与已验 r2 内容一致，monitor ELF 也逐字相同；r2 的反汇编和平台来源可核查。本次另外读取实际汇编指令与重新执行二 hart 路径，没有把编译器端 ABI 或 ID 的实现正确性作为本 agent 的自审结论。

## 拒绝与独立探针

作者十项负例均核验源哈希、同一 E3 编译命令、嵌套 ELF 哈希与真实退出：保留槽、非法 flags、PPN 未对齐、bit 63、bit 54、最高 PPN 位、RAM 下界外、RAM 上界、未映射读取分别退出 250；显式失败退出 7。最后一例也保证任意退出不会被 runner 误计成功。

独立复制旧区分性探针的**源码**，重新由新 E3 构建六个 ELF 并执行，未使用旧 guest ELF：

| 探针 | 预期 / 实际 |
| --- | --- |
| 原 bit 63 PTE 绕过 | 250 / 250 |
| RAM 前一超页 `0x84e00000` | 250 / 250 |
| RAM 首超页 `0x85000000` | 7 / 7，install 合法返回 |
| RAM 末超页 `0x87600000` | 7 / 7，install 合法返回 |
| RAM 上界 `0x87800000` | 250 / 250 |
| page 15 分配；同 VA 重映射至 page 14；旧页保持；4096 次交换；UART | `P5 OK\n`、0 / 一致 |

monitor 明确先拒绝 bits 63:54，再直接比较 PPN `[0x85000,0x87800)`，没有恢复旧右移再左移导致的截断问题。分配器只有 16 页，其池结束于 `0x87000000`；平台可安装范围结束于 `0x87800000`，两者合同不同，边界判定未混同。
