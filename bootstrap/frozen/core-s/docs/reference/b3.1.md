## 1 构建、运行与清单

目标编译器读取 `.vt` 源文件和可选 `.s0`，直接生成 RV64 Linux ELF。它不自动搜索包、加载标准库、调用外部链接器或链接 libc。清单列出所有输入，函数入口必须是安全的、无参数、返回 `u32` 的普通函数。

保存下例为 `main.vt`：

<!-- example: hello/main.vt -->
```vt
module app;

pub fn run() -> u32 {
    return 42;
}
```

保存为 `program.build`：

<!-- example: hello/program.build -->
```text
format 1
profile linux-user
entry app::run
source main.vt
output program.elf
```

假设 `compiler.elf` 是该版本的目标编译器，在上述文件所在目录执行：

```sh
qemu-riscv64 -s 1048576 compiler.elf check program.build
qemu-riscv64 -s 1048576 compiler.elf build program.build
qemu-riscv64 program.elf
echo $?  # 42
```

在真实 RV64 Linux 上可直接运行 ELF。当前工作区维护产物在 `core-s/build/b31-refactored.elf`，原始基线保留为 `core-s/build/b31-final.elf`，也可按 [构建说明](../../README.md) 重建。Linux shell 观察到的退出状态只有低 8 位；不要将所有 u32 返回值都当成可区分的 shell 状态。

清单格式与命令约定：

| 项 | 规则 |
| --- | --- |
| `format` / `profile` | 分别为 `1` / `linux-user`，各一次 |
| `entry` | 一次；根函数 `run`、模块函数 `app::run` 或绝对名字 `root::app::run` |
| `source` | 1–32 个不同路径，按清单顺序读取 |
| `assembly` | 0–8 个不同 `.s0` 输入路径 |
| `output` | 一次，即使执行 check 也必须提供 |
| 行 | 每条有效行两个词；允许空行和整行 `#` 注释，不支持行尾注释 |
| 路径 | 相对**启动工作目录**，不是清单所在目录；不自动创建输出父目录 |
| 路径限制 | 最多 96 字节；不接受绝对路径、空分量、`.`、`..`、反斜线或空白/控制字符 |
| 发布 | build 独占新建输出，拒绝已有文件；失败清理本次不完整输出 |

`check` 仍完成类型、机器和符号链接检查，但不生成输出文件。重复 build 需要新的 output 路径或先处理已有产物。清单、源码、汇编与诊断位置均以字节为基础。

目标编译器目前没有 `--version` 命令；请用本页登记的 ELF 哈希识别版本。

Rust 种子是另一个 CLI：`core-s project MANIFEST [--root DIRECTORY]`，以及单文件 `check INPUT`、`build INPUT --entry FUNCTION -o OUTPUT`、`asm INPUT --entry FUNCTION -o OUTPUT`。不要把种子命令与目标编译器命令混用。

## 2 词法与名字

源文件必须是合法 UTF-8，不接受 BOM。LF、CRLF、CR 均可分行；ASCII 空格、制表、换行、垂直制表与换页为空白。`//` 注释到行末，`/* ... */` 可以嵌套。

标识符为 ASCII 字母或 `_` 起始，后接字母、数字或 `_`，区分大小写。保留关键字不得作普通名字；`core` 与 `root` 是保留命名空间。非 ASCII 标识符未支持，UTF-8 注释和字符串可用。没有字符字面量。

整数支持十进制、`0x` 十六进制、`0b` 二进制；负号是运算符，不是整数词素的一部分。类型后缀是 `_u8`、`_u32`、`_usize`。数字之间允许单个 `_`，不允许开头、结尾或连续分隔符。例如 `1_024_usize` 合法，`1__2` 拒绝。数值必须能由相应整数类型表示。

字符串类型是 `[]const u8`，具有静态存储期，按 UTF-8 字节计长度，没有隐式尾零。允许 `\0`、`\n`、`\r`、`\t`、`\\`、`\"`、`\xHH`；`\xHH` 产生一个任意字节，因此字符串解码结果未必仍是合法 UTF-8。没有插值、多行字面量或 `\u{...}`。空字符串使用非零哨兵地址，不是 null 指针。

下面同时验证 UTF-8 字节长度、空字符串地址和整数分隔符，结果为 8：

<!-- example: lexemes/main.vt -->
```vt
fn run() -> u32 {
    let word:[]const u8 = "中文";
    let empty:[]const u8 = "";
    let n:u32 = 0b1_0_u32;
    if core::addr(empty.data) == 0_usize { return 0; }
    return (word.len as u32) + n;
}
```

连续分隔符拒绝：

<!-- example: separators_bad/main.vt -->
```vt
fn run() -> u32 { return 1__2; }
```

## 3 模块与可见性

源文件顺序为可选的 `module a::b;`、若干 `import`、顶层声明。没有 module 的文件属于根模块。同模块可拆为多个显式列入清单的文件；允许函数、结构和常量前向引用，但不允许非法布局或常量依赖环。

顶层声明支持 `struct`、`const`、`static`、`static mut`、普通/unsafe 函数和标量 C extern，可加 `pub`。没有 `pub` 时仅当前模块可见。`import a::b;` 引入模块末段名字 `b`，用 `b::item` 访问；没有选择性 import、`as` 别名或通配导入。重复名字、导入别名冲突拒绝。

未限定名字优先匹配局部绑定，然后查当前模块。`root::a::b::item` 从根模块解析。局部变量遮蔽函数后不能再把该局部当函数调用。公开函数签名和公开声明不能泄露私有类型；当前 `pub struct` 要求**所有字段都 pub**。

下例将两个文件同时列为 source，入口为 `app::run`，结果为 42：

<!-- example: modules/math.vt -->
```vt
module math;
pub fn twice(n:u32) -> u32 { return n * 2_u32; }
```

<!-- example: modules/main.vt -->
```vt
module app;
import math;
pub fn run() -> u32 { return math::twice(21); }
```

## 4 类型、布局与值复制

当前类型闭合集合如下。大小和对齐以字节计，机器为 RV64 小端：

| 类型 | 大小 / 对齐 | 说明 |
| --- | --- | --- |
| `()` | 0 / 1 | 唯一值 `()` |
| `bool` | 1 / 1 | false / true；不是整数 |
| `u8` | 1 / 1 | 0…255 |
| `u32` | 4 / 4 | 0…2³²−1 |
| `usize` | 8 / 8 | 0…2⁶⁴−1 |
| `*T`、`*const T` | 8 / 8 | 可写/只读原始指针 |
| `[N]T` | N × sizeof(T) / alignof(T) | 固定数组，N 为编译期整数；通常写 usize |
| `[]T`、`[]const T` | 16 / 8 | 指针与 usize 长度的描述符 |
| `struct Name { ... }` | 按字段声明顺序布局 | 各字段自然对齐，尾部补齐到最大字段对齐 |
| `Result<T,E>` | u32 标签及共用载荷区 | Ok=0、Err=1；载荷偏移为 4 向 max(4, alignof(T), alignof(E)) 对齐；大小由最大载荷补齐 |

结构采用名义类型身份；相同字段的两个不同结构不是同一类型。空结构和零长度数组可用。`sizeof(T)`、`alignof(T)` 返回 usize。没有 packed、用户布局属性或 `offsetof`。

所有值采用复制语义：传参、赋值、返回复制当前值，结构和数组复制自身内容；指针和切片只复制地址/描述符，不复制目标存储。没有 move、借用检查、自动析构或 GC。调用者负责间接引用对象的存活、初始化和权限。

<!-- example: values/main.vt -->
```vt
struct Pair { x:u32, y:u32 }
fn run() -> u32 {
    var first:Pair = Pair { x:20, y:1 };
    let saved:Pair = first;
    first.x = 99;
    return saved.x + saved.y;
}
```

结果为 21。数组与结构不支持整体 `==` 比较。

布局查询示例，结果为 48（Pair 大小 16、对齐 8，Result 大小 16，零数组对齐 8）：

<!-- example: layout/main.vt -->
```vt
struct Pair { small:u8, wide:usize }
fn run() -> u32 {
    return (sizeof(Pair) + alignof(Pair) + sizeof(Result<u8,usize>) + alignof([0]usize)) as u32;
}
```

## 5 绑定、函数与返回

```text
let name:T = expression;
var name:T = expression;
var name:T;
fn name(parameter:T, ...) -> R { statements }
unsafe fn name(parameter:T, ...) -> R { statements }
```

每个参数、局部绑定和返回类型都要显式写出。参数和 let 绑定不可重新赋值；var 可以赋值。绑定的不可变性不等于指针/切片所指对象不可写，后者由 `*const` / `[]const` 控制。同一作用域重复绑定拒绝，内层作用域可遮蔽外层名字。

`let` 必须初始化；`var` 可不初始化，但读取前完成初始化是使用者责任，当前编译器没有完整的数据流初始化证明，也不承诺自动填零。不要用未初始化值试探运行结果。

所有正常结束路径必须显式 `return value;`，即使返回 `()` 也要写 `return ();`。不提供尾表达式返回或 `return;`。永不落出的 loop 可作为不返回路径；普通函数可递归，但不会自动证明递归终止或栈容量安全。

`unsafe fn` 表示调用必须处在 unsafe 块中；**本版本函数体里的危险操作仍要显式写 `unsafe { ... }`**。它不自动开启整个函数体的 unsafe 权限。

## 6 整数定型、运算与转换

没有一般类型推导和隐式数值转换。运行期无后缀字面量从已知上下文取得整数类型，例如局部初始化、参数、返回值、数组元素或结构字段。没有这种上下文时不保证有默认类型。

比较操作不把一侧的类型传播给另一侧：`n == 0_u32` 合法，u32 的 `n == 0` 在当前目标编译器中拒绝。`as` 不向其左侧字面量反向提供类型，因此写 `1_usize as u8`，不要依赖 `1 as u8`。

<!-- example: literal_bad/main.vt -->
```vt
fn run() -> u32 {
    let n:u32 = 1;
    if n == 0 { return 0; }
    return n;
}
```

上例预期 `E_TYPE`。正确写法：

<!-- example: literal_good/main.vt -->
```vt
fn run() -> u32 {
    let n:u32 = 1;
    if n == 0_u32 { return 0; }
    return n;
}
```

| 运算 | 规则 |
| --- | --- |
| `+ - *` | 同类型无符号整数；溢出/下溢触发 panic |
| `+% -% *%` | 同类型无符号整数，按类型位宽回绕 |
| `/ %` | 无符号除法/余数；除零 panic |
| `<< >>` | 两操作数同整数类型；移位量小于左侧位宽；左移丢弃移出位，不以此判溢出 |
| `& \| ^ ~` | 位运算，仅整数 |
| `! && \|\|` | 仅 bool；运行期 && / \|\| 短路 |
| `== !=` | 同类型标量：整数、bool、unit、指针；没有聚合比较 |
| `< <= > >=` | 同类型整数 |
| `as` | 仅整数之间；拓宽零扩展，缩窄截低位，不是溢出检查 |
| 一元 `-` | 运行期表达式未支持；常量计算只允许结果仍可表示的零值取负 |

从低到高的二元优先级为 `||`、`&&`、`== !=`、`< <= > >=`、`|`、`^`、`&`、`<< >>`、`+ - +% -%`、`* / % *%`，同级左结合。其上是 `as`，再是一元 `! ~ - *`，最高为调用/字段/下标/`?`。复杂组合建议显式加括号。

<!-- example: arithmetic/main.vt -->
```vt
fn run() -> u32 {
    let wrapped:u8 = 255_u8 +% 1_u8;
    let low:u8 = 258_usize as u8;
    return (wrapped as u32) + (low as u32);
}
```

结果为 2；将回绕加法换成普通加法会 panic：

<!-- example: overflow/main.vt -->
```vt
fn run() -> u32 {
    let n:u8 = 255_u8 + 1_u8;
    return n as u32;
}
```

此版本 Linux 运行时 panic 退出码为 101，不展开 defer。

## 7 构造、访问与求值顺序

结构构造 `Name { field:value, ... }` 必须恰好给出全部字段，不能重复。数组列表 `[a,b,c]` 必须匹配期望数组长度；重复构造 `[value;N]` 将 value 求值一次，再复制 N 次。即使 N 为 0，也检查并在运行期求值 value。

字段和数组元素的写入要求位置可写。数组下标须为 usize，并总有运行期边界检查；普通局部数组访问本身不要求 unsafe。数组 `.len` 为 usize，只读。切片访问规则见第 10 节。

普通操作数、函数实参、结构字段初始化表达式和数组列表元素按源码从左到右求值。实参和聚合值在其求值点取得快照。**赋值先求右侧值，再执行左侧地址计算**；返回值在执行退出清理之前保存快照。

<!-- example: assignment_order/main.vt -->
```vt
static mut trace:u32 = 0;
fn value() -> u32 {
    unsafe { trace = trace * 10_u32 + 1_u32; }
    return 7;
}
fn index() -> usize {
    unsafe { trace = trace * 10_u32 + 2_u32; }
    return 0;
}
fn run() -> u32 {
    var data:[1]u32 = [0];
    data[index()] = value();
    unsafe { return trace; }
}
```

结果为 12。不要根据等号左侧的书写位置推断它先执行。

<!-- example: zero_repeat/main.vt -->
```vt
static mut count:u32 = 0;
fn next() -> u32 {
    unsafe { count = count + 1_u32; }
    return 7;
}
fn run() -> u32 {
    let empty:[0]u32 = [next();0];
    unsafe { return count; }
}
```

结果为 1。

## 8 控制流与模式

支持块、`if/else if/else`、`while`、`loop`、`break;`、`continue;`、`return`、语句式 `match`。条件必须是 bool；没有整数到 bool 的隐式转换。没有 for、循环标签、带值 break、if/match/块表达式或复合赋值。

match 的每个分支必须是块，分支之间用逗号，可有末尾逗号。只支持 bool、整数和 Result 的浅层模式：

- bool：`true`、`false`、`_`。
- 整数：字面量、`_`；即使列出全部 u8 值，仍要求兜底 `_`。
- Result：`Result::<T,E>::Ok(name:T)`、`Err(name:E)` 或载荷 `_`。

模式必须无重复且穷尽；`_` 必须在最后。Result 载荷绑定只在分支内有效，按值复制；没有嵌套解构、守卫、范围或多个模式合并。

<!-- example: control/main.vt -->
```vt
fn run() -> u32 {
    var n:u32 = 0;
    var total:u32 = 0;
    while n < 4_u32 {
        n = n + 1_u32;
        if n == 2_u32 { continue; }
        total = total + n;
    }
    match total {
        8_u32 => { return 42; },
        _ => { return 0; },
    }
}
```

所有函数体、不可达语句和未调用声明仍检查，不能用 `if false` 隐藏非法代码。

## 9 Result、问号与 defer

`Result<T,E>` 是唯一内建的带载荷分支类型，不意味着支持用户泛型。构造必须写完整类型，如 `Result::<u32,u32>::Ok(42)`。`value?` 要求 value 和当前函数结果都是 Result，且错误类型 E 完全相同；成功取出 T，失败形成当前返回类型的 Err，执行退出清理后返回。没有自动错误转换。

`defer { ... }` 在所在词法块退出时按注册逆序执行，包含正常离块、return、`?` 的错误返回、break 和 continue 所离开的作用域。清理体读取执行清理时的当前存储值；返回值和 Err 载荷已在清理前保存。

清理体必须有限且结构简单：禁止嵌套 defer、循环、return、break、continue、`?` 和未初始化 var；允许已初始化局部、赋值、调用、if/match 与 unsafe 块。调用的函数可以有自己的控制流；这里不是终止性证明。panic 不执行清理，也没有异常展开。

<!-- example: cleanup/main.vt -->
```vt
static mut cleaned:u32 = 0;
fn read_value() -> Result<u32,u32> {
    defer { unsafe { cleaned = cleaned + 1_u32; } }
    return Result::<u32,u32>::Err(7);
}
fn operation() -> Result<u32,u32> {
    let n:u32 = read_value()?;
    return Result::<u32,u32>::Ok(n);
}
fn run() -> u32 {
    match operation() {
        Result::<u32,u32>::Ok(n:u32) => { return n; },
        Result::<u32,u32>::Err(e:u32) => { unsafe { return e + cleaned; } },
    }
}
```

结果为 8。以下清理体拒绝，而不是跳出外层函数：

<!-- example: defer_bad/main.vt -->
```vt
fn run() -> u32 {
    defer { return 1; }
    return 0;
}
```

清理执行时读取当前 x，但不能改变已保存的返回值。下例结果为 22：

<!-- example: cleanup_snapshot/main.vt -->
```vt
static mut observed:u32 = 0;
fn sample() -> u32 {
    var x:u32 = 1;
    defer { unsafe { observed = x; } x = 9; }
    x = 2;
    return x;
}
fn run() -> u32 {
    let value:u32 = sample();
    unsafe { return value * 10_u32 + observed; }
}
```

## 10 指针、切片与 unsafe

`*T` 可写，`*const T` 只读；`*kernel T` / `*kernel const T` 是保留的兼容拼法，不提供独立地址空间语义。`null` 需要明确指针类型上下文。没有隐式可写转只读，使用相应内建显式转换。

`[]T` 可写，`[]const T` 只读；`.data` 和 `.len` 本身只读。可写切片的 let 绑定仍可写元素。数组不会隐式转换成切片。切片下标先检查长度，但不会验证地址存活、对齐或目标对象是否真实存在。

以下内建以 `core::` 限定写法使用。`T` 表示由操作数取得的具体类型，不是用户可定义泛型。

| 内建 | 返回 | 是否要求 unsafe |
| --- | --- | --- |
| `core::addr_of(place)` | `*const T` | 普通局部/静态根取址不要求；位置计算自身的危险访问仍要求 |
| `core::addr_of_mut(place)` | `*T` | 同上，且 place 可写 |
| `core::addr(pointer)` | usize 地址位 | 否 |
| `core::ptr::<T>(address)` | `*T`，address 为 usize | 是 |
| `core::ptr_const(pointer)` | `*const T` | 否 |
| `core::ptr_add(pointer,n)` | 同指针类型，前进 n 个元素 | 是；n 为 usize |
| `core::ptr_add_bytes(pointer,n)` | 同指针类型，前进 n 字节 | 是；n 为 usize |
| `core::slice_of(array_place)` | `[]const T` | 普通局部数组不要求 |
| `core::slice_of_mut(array_place)` | `[]T` | 普通可写局部数组不要求 |
| `core::slice_from_raw_parts(pointer,n)` | `[]const T` | 是；n 为 usize |
| `core::slice_from_raw_parts_mut(pointer,n)` | `[]T` | 是；pointer 必须可写 |
| `core::slice_const(slice)` | `[]const T` | 否 |
| `sizeof(T)` / `alignof(T)` | usize | 否 |
| `core::panic()` | 不返回到下一条运行语句 | 否；本版不接受消息参数 |

解引用 `*pointer`、切片元素访问、读写 static mut、调用 unsafe/extern 函数需要 unsafe 块。unsafe 不关闭类型、只读权限、算术或边界检查。没有通用内存读写、memcpy、分配器或原子内建；可用显式循环和平台接口构建库。

<!-- example: memory/main.vt -->
```vt
fn run() -> u32 {
    var data:[2]u32 = [20,1];
    let view:[]u32 = core::slice_of_mut(data);
    let pointer:*u32 = core::addr_of_mut(data[0]);
    unsafe {
        *pointer = *pointer + view[1];
        return view[0];
    }
}
```

结果为 21。危险操作要在函数体中显式授权，即使签名是 unsafe：

<!-- example: unsafe_body_bad/main.vt -->
```vt
unsafe fn get(pointer:*const u32) -> u32 { return *pointer; }
fn run() -> u32 { return 0; }
```

预期 `E_PERMISSION`。正确写法为 `unsafe fn get(...) -> u32 { unsafe { return *pointer; } }`，其调用者也要使用 unsafe 块。

指针有效期、对齐、对象初始化、地址加法不越过有效存储、切片覆盖范围，以及并发同步都由程序负责。类型通过不保证无悬垂、无别名冲突、无数据竞争或无泄漏。语言没有自动检查这些合同，不能依赖违反合同后的行为。

## 11 常量与静态对象

```text
const NAME:T = constant_expression;
static NAME:T = static_initializer;
static mut NAME:T = static_initializer;
```

顶层 const 当前仅支持整数和 bool。可用已声明 const、整数/逻辑运算、整数 as、sizeof/alignof；没有 const fn、用户函数调用或编译期语句解释器。无后缀常量在缺少期望类型时回退 usize，二元常量右侧会受到左侧类型影响；这与第 6 节运行期定型不同。依赖环拒绝，不允许靠短路或零长度隐藏依赖。

**常量计算不会用 `&&` / `||` 跳过另一侧验证与计算。** 不要用常量短路隐藏除零等错误。

static 初始化支持标量常量、null、字符串、数组列表/重复、具名结构、Result 构造，以及 `core::addr_of(STATIC_ROOT)` / `addr_of_mut(STATIC_MUT_ROOT)`。静态根取址不支持字段/下标路径；没有任意指针运算、运行期函数调用或通用切片构造。所有子项完整检查，零重复长度也不豁免非法表达式。

<!-- example: statics/main.vt -->
```vt
const N:usize = 2;
static message:[]const u8 = "hi";
static mut data:[N]u32 = [20,22];
static address:*const [N]u32 = core::addr_of(data);
fn run() -> u32 {
    unsafe {
        let values:[N]u32 = *address;
        return values[0] + values[1];
    }
}
```

结果为 42。只读静态数据放只读段；可写全零对象可放 BSS。每个进程映像独立初始化这些静态对象，复制指针或切片不会复制目标。

下面两个例子都应在编译期拒绝：

<!-- example: constant_bad/main.vt -->
```vt
const HIDDEN:bool = false && (1_usize / 0_usize == 0_usize);
fn run() -> u32 { return 0; }
```

<!-- example: static_zero_bad/main.vt -->
```vt
static EMPTY:[0]u32 = [1_u32 / 0_u32;0];
fn run() -> u32 { return 0; }
```

## 12 外部函数与 s0

声明为 `extern abi(C) fn name(parameters) -> T;`。参数只支持 bool、现有整数和指针；unit 只能作结果，数组/结构/切片/Result 的 C 参数与结果未支持。调用需要 unsafe。外部符号名取函数声明的短名字，不支持用户指定链接名或动态链接；跨模块同名 extern 会链接到同一符号；使用者必须保持这些声明与实际实现的 ABI 一致，不能依赖编译器发现所有跨声明签名冲突。

**所有 extern 都必须由本次 assembly 输入提供符号，即使未被调用。** 普通 VT 函数采用编译器内部 ABI，不应直接从 C 按聚合 ABI 调用。标量 C 接口遵循 RV64 参数寄存器、溢出栈参数和保存寄存器约定；此外 x27 保留 Linux 初始栈指针，汇编适配必须保持它。

将以下文件一起列入 source/assembly，入口为 `app::run`：

<!-- example: ffi/main.vt -->
```vt
module app;
extern abi(C) fn answer() -> u32;
pub fn run() -> u32 { unsafe { return answer(); } }
```

<!-- example: ffi/answer.s0 -->
```text
answer:
addi x10, x0, 42
jalr x0, 0(x1)
```

结果为 42。`.s0` 是固定汇编子集，不是 GNU 汇编：寄存器只写 `x0`…`x31`，一行一条指令或标签，逗号分隔操作数，`#` 注释。符号由 ASCII 字母/`_`/`.` 起始，后续允许数字；`.L` 前缀标签仅当前文件可见。

| 指令组 | 形式与限制 |
| --- | --- |
| `add sub mul mulhu divu remu and or xor sltu sll srl` | `op rd, rs1, rs2` |
| `addi addiw xori sltiu` | `op rd, rs, imm`；−2048…2047 |
| `slli srli` | `op rd, rs, shift`；0…63 |
| `lbu lwu ld` / `sb sw sd` / `jalr` | `op reg, offset(base)`；offset −2048…2047 |
| `beq bne bltu bgeu` | `op rs1, rs2, label` |
| `address` | `address rd, symbol`，rd 不能是 x0 |
| `call jump` | `op symbol`，分别有/无返回地址 |
| `ecall unimp` | 无操作数 |

立即数支持十进制和带可选负号的小写 `0x` 十六进制，十六进制字母只接受 a–f。没有宏、节指令、数据伪指令、CSR、原子扩展指令或自动 GNU 语法兼容。源级算术检查不覆盖手写汇编。

## 13 Blocking 分析

这是可选的外部配置分析，不改变语言语法或生成代码：

```text
compiler.elf build program.build --blocking program.blocking
compiler.elf check program.build --blocking program.blocking
```

对上一节的 ffi 程序使用：

<!-- example: ffi/program.blocking -->
```text
format 1
require app::run
nonblocking app::answer
```

分析报告 `Verified`，生成 ELF 与未开启分析时完全相同。`nonblocking` 是使用者提供的外部假设，编译器没有证明汇编实现。

- `require` 指定本次构建的普通函数，可含私有函数；名字用完整模块路径，可加一次 `root::`，不使用 import 别名。
- `nonblocking` / `may_block` 只标注 extern。同一 linker symbol 共用合同；重复、冲突、未知名字或内部函数合同拒绝。
- 到达 may_block 为 `Violation`；没有已知违反但到达缺失合同或未捕获函数为 `Unknown`；闭包全部已知非阻塞才 `Verified`。Violation 优先于 Unknown。
- 递归按调用图传播；未调用的外部函数不会污染根，IR 中保留的不可达调用仍保守计入，defer 中的调用也计入。
- 所有 require 都 Verified 才允许 build 发布；Unknown 也拒绝。check 始终不发布文件。

此属性不证明终止性、实时性、忙等不存在、IRQ 或并发安全。配置上限 16 KiB，至少一个 require，每行两个词，允许空行/整行注释；详见 [Blocking 配置说明](../../bootstrap/blocking.md)。未开启时没有这些分析保证。

## 14 错误、panic 与容量

目标编译器成功退出 0，编译或分析失败退出非零。常见诊断如下；不承诺与 Rust seed 的错误码、措辞或定位完全相同：

| 诊断 | 含义 |
| --- | --- |
| `E_PARSE` | 词法、语法或清单格式错误 |
| `E_NAME` | 未知、重复、不可见或冲突名字 |
| `E_TYPE` | 类型、常量、布局依赖或模式等检查失败 |
| `E_PERMISSION` | 缺 unsafe 或某些权限违反；其他只读类型错误也可能报告 E_TYPE |
| `E_IO` / `E_LINK` | 输入输出或符号/映像构建失败 |
| `I_UNSUPPORTED` | 识别到本版本未提供的机制 |
| `I_LIMIT` | 超过实现容量，通常附 actual/limit |
| `I_INTERNAL` | 编译器内部不变量失效，应报告缺陷 |
| `E_BLOCKING_CONFIG` | 分析配置无效 |

通常位置形如 `file=N byte=M`，N 为清单输入顺序中的文件 ID（source 从 1 开始，其后为 assembly），M 为零起始字节偏移；0 可能表示清单或无具体源位置。只报告首先遇到的错误，不保证不同缺陷的报告顺序。

panic 是程序运行时失败，当前 Linux profile 退出 101，无消息参数、无回溯和清理展开；不是编译错误。指针使用合同违反不是可可靠捕捉的 panic。

主要容量如下，均为当前实现限制，不是未来语言永久承诺：

| 项目 | 上限 |
| --- | ---: |
| 清单 / Blocking 配置 | 各 16 KiB |
| source / assembly 文件数 | 32 / 8 |
| 源码总字节 / 汇编总字节 | 4 MiB / 1 MiB，分别由所有文件共享 |
| 声明 / 类型 / intern 名字 | 各 8,192 |
| 单结构字段 / 单函数参数 | 各 256 |
| 单函数 AST / slot / IR 指令 | 32,768 / 32,768 / 65,536 |
| 单函数活动绑定 / defer / 嵌套循环 | 8,192 / 1,024 / 256 |
| 单函数栈帧 | 256 KiB |
| 映像跨度、静态数据布局预算 | 64 MiB |
| Blocking CALL 摘要边 | 65,536 |

另有具体解析/表达式递归深度、名字字节池、数据、符号和回填表容量；不要将上表当成所有合法程序都必然能编译的保证。运行时递归和调用链栈峰值不由单帧限制保证。编译器自编译已在 1 MiB guest 栈配置下验证，这不是任意用户程序的栈安全证明。

## 15 未支持能力与种子差异

B3.1 未提供：用户泛型、trait、方法、重载、宏、闭包、用户枚举、Option、类型别名、元组、语言引用、隐式移动/析构、GC、函数值/间接调用、never 返回类型、新整数宽度/有符号整数/浮点、一般 CTFE、原子/volatile/MMIO/CSR/陷阱内建、packed、源内联汇编、动态链接、通用分析插件和其他目标 profile。

某个未支持或非法写法可能在词法/语法阶段就失败；不保证上述所有概念都得到 I_UNSUPPORTED。不要把内部错误或未校验的行为当成可用扩展。

Rust seed C0 用于启动自举，当前保留的两项已知差异是：接受 `1__2`，以及局部同名变量存在时误解析 `root::n`。VT 目标编译器拒绝前者并正确处理后者。本参考以上述指定目标 ELF 为准；C0 也没有 Blocking 命令。实现尚不覆盖旧 0.5 或完整 R1a，不能直接编译它们的全部程序。
