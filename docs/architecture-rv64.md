# biomiya 0.5 RV64 目标补充

**目标配置** `rv64-core-v1`  
**职责** 闭合 [reference](reference.md) 的目标表示、调用与运行接口；不是 Extend。  
**状态** 首版实现基线；仓库提供 Rust 参考实现与 QEMU 平台，实际交付状态由 workflow 的完整验收确定。

本文件适配 reference 0.5。目标名仍为 `rv64-core-v1`：本次增加源接口与验收要求，不改变既有数据布局、调用约定或 TrapFrame。

本配置选择小端 RV64IMA + Zicsr + Zifencei、S-mode、LP64 整数 C ABI。不生成浮点、向量或压缩指令，不依赖未对齐硬件访问。平台必须允许 S-mode 执行本配置使用的特权操作；不支持的机器不能宣称运行此配置。页表模式、物理装载地址、设备地址、hart 启动与内存分配由平台提供，不成为新的源语言语法。

psABI 基线固定到提交 `48969b7995b3ae1582f230dcce32a12d443d1a7a`（本轮核对的版本），不随上游后续修订自动变化。外部依据采用 [RISC-V psABI 的 LP64 整数约定](https://github.com/riscv-non-isa/riscv-elf-psabi-doc/blob/48969b7995b3ae1582f230dcce32a12d443d1a7a/riscv-cc.adoc)、[Supervisor ISA 1.13](https://docs.riscv.org/reference/isa/priv/supervisor.html) 与 [RVWMO](https://docs.riscv.org/reference/isa/unpriv/rvwmo.html)。仅引用相应已定义的基础接口，不启用它们列出的可选 ABI 或 ISA 扩展。下面的普通 biomiya ABI、TrapFrame 和运行时符号是本项目自己的约定，不是 RISC-V 标准接口。

## R1. 编译与构建输入

编译输入包含显式源文件列表、目标配置、可选外部对象／库、链接脚本和平台运行对象。Core 模式关闭全部 Extend。编译器可输出汇编再调用外部汇编器／链接器，也可生成对象；不要求自带汇编器、链接器、优化器或启动固件。

对象使用 ELF64 little-endian、RISC-V machine 标识和 soft-float LP64 ABI；编译驱动必须向工具链传递一致的 ISA／ABI 设置。本版只要求静态链接，没有动态装载、TLS 或共享库 ABI。未导出符号的修饰由实现定义，必须在一个构建中唯一；用户不得使用 `__biomiya_` 开头的外部符号，该前缀留给运行时和测试适配器。不同编译器生成的普通 biomiya 对象不承诺互链，C ABI 对象按 LP64 互通。

链接入口为平台提供的 `_start`；语言没有隐式 `main`。平台可以调用用户定义的 `@export("kernel_main") extern abi(C) fn kernel_main() -> ()`。启动前平台完成静态映像装载、零初始化区处理、16 字节对齐的栈、gp／tp 与所需映射配置；静态初始化器不生成运行时构造函数。

默认只读代码放 `.text`，只读常量／静态放 `.rodata`，可变初始化数据放 `.data`，可用零填充表示的数据放 `.bss`。静态对象含 Atomic 或 UnsafeCell 的实际内部可变载荷时必须放可写存储；MaybeUninit 本身不提供内部可变性。`@section` 接受非空、不含 NUL 的节名，声明所需权限仍必须满足；链接脚本负责映射，不能以节名推断可写性。自定义节和高对齐必须由链接器落实，失败就是构建失败。

`extern abi(C) static` 不分配节或存储，使用声明名引用外部 ELF 符号；其实际对象布局按 R2 与 reference 25.1 的字段规则。链接脚本提供的地址符号只用于取址时，不要求存在对应的 ELF OBJECT 大小或可读字节；编译器不得为 `addr_of` 插入该符号的加载。不可变本地静态对象的常量取址使用地址重定位；位置不确定不构成常量求值失败。工具链必须支持相应链接重定位，缺少实际引用的定义时构建失败。

## R2. 数据表示与布局

所有尺寸和字段偏移以字节计。整数使用二元补码，存储大小及自然对齐等于位宽除以 8；`usize`／`isize` 为 8／8。`bool` 为 1／1，合法表示仅 0 和 1。原始指针、引用、函数指针均为 8／8，原始空指针为零，引用和函数指针不得为零。数据地址按 64 位数值存储；是否为有效虚拟地址由运行合同决定。

`()`、空结构体大小为 0、自然对齐为 1。零大小对象仍有逻辑存储身份，但不同对象可有相同数值地址；从非空对齐地址构造的合法零大小引用不要求访问实际字节。不得用地址相等推导零大小对象身份相同。

所有布局采用以下确定规则；不做字段重排或 niche 优化：

- 数组元素连续，步长为元素 sizeof，长度乘法须可由 usize 表示；对齐为元素对齐，零长度数组保留元素对齐。
- 结构体、newtype、元组按声明／位置顺序布局。每个字段起点向上舍入到字段对齐，最终大小向上舍入到整个类型的最大字段对齐。newtype 仍是单字段聚合。
- 切片大小 16、对齐 8；偏移 0 为地址、偏移 8 为 usize 长度。空切片地址仍须非空且对齐，可为原对象的一过尾地址；零长度不授予元素访问权。字符串字节相同可共享静态存储。
- 枚举使用 u32 标签，按变体声明顺序从 0 编号，之后为最大载荷大小的联合存储。各变体载荷按结构体规则布局；载荷起点向上对齐，整体对齐为 max(4, 最大载荷对齐)，最终大小向上对齐。无载荷变体的载荷不参与合法值判定，非法标签违反表示合同。变体数大于 2^32 时拒绝。
- `Option`／`Result` 使用同样枚举布局，不利用指针空值。MaybeUninit 和 UnsafeCell 与载荷大小／对齐相同；前者允许任意未初始化字节，后者须含合法 T。
- `Atomic<u8>` 和 `Atomic<u16>` 使用大小 4、对齐 4 的独立存储，低位表示载荷，高位由实现保持为零；其余 Atomic 与载荷大小／对齐相同。包装器不是 ABI 透明类型，不能绕过 API 读写其存储。

`@align(N)` 支持 1 到 4096 的 2 次幂。类型属性提高类型对齐并向上舍入 sizeof；对象属性仅提高该静态对象地址对齐。`@packed` 按 reference 连续布局；普通按值读写可拆成字节操作，取引用仍要求实际对齐。本配置拒绝在同一类型上组合 `@repr(C)` 与 `@packed`／`@align`；普通非 C 类型仍可单独使用后两者。

`@repr(C)` 使用 LP64 的对应 C 字段表示及结构体布局。本配置的整数／指针／bool 和允许的正长度数组正好按上述自然布局排列；它不开放 C union、bit-field 或空 C 结构体。

`addr_of`／`addr_of_mut` 降低为一次位置地址计算，不先读取或复制目标；packed 字段取址不生成未对齐加载。切片指针成员读取描述符中的数据地址，原始切片构造直接形成 R2 的地址／长度对；MaybeUninit 的指针成员返回其载荷地址，不创建或读取 `T`。这些操作不加入堆分配或运行时借用追踪。

布局加法、乘法或向上对齐溢出 usize 时编译失败。填充字节不要求初始化，聚合复制可以复制它们但不得把它们当成合法用户字段读取；相等比较必须忽略填充。取未激活枚举载荷不是合法字段操作。

## R3. 普通 biomiya 与 C 调用约定

C 接口完整遵循所引用 psABI 的 LP64 integer calling convention，包括标量扩展、寄存器耗尽、聚合拆分、栈对齐及间接结果规则；实现不能只覆盖不超过八个标量参数的例子。C 字段与参数类型的允许集合仍由 reference 25.1 决定。

普通 biomiya 调用先作下面的类型降低，再对降低后的签名使用 LP64 标量传参：

| 源类型 | 降低 |
| --- | --- |
| 整数、bool、指针、引用、函数指针 | 相应 LP64 标量；引用视为数据指针 |
| `()` 或其他零大小值参数 | 省略传参，但保留源求值／移动 |
| 非零大小聚合，包括数组、newtype、切片、枚举和存储包装器 | 指向调用者准备的按值快照的一个参数 |
| 非零大小聚合结果 | 增加第一个隐藏参数，指向调用者结果槽；机器返回值为 void |
| `()` 或其他零大小结果 | 机器返回值为 void |
| `!` 结果 | 无正常返回边，不读取机器返回值 |

聚合快照在每个源实参求值时建立，不能推迟到后续实参完成后再从源复制。callee 的按值参数拥有独立逻辑位置；允许直接把快照作为参数存储，不能借此把源调用者对象变成按引用传参。结果槽不得与仍在读取的实参快照重叠。切片快照只复制视图，不复制目标元素。

安全／unsafe、resource、借用与效果标记不改变机器参数列表。函数指针调用使用相同降低规则。必须按源语言求值顺序先保存参数，再分配实际寄存器／栈位置；不能依赖宿主 C 的实参顺序。同一签名采用同一降低，不能根据调用点是否启用验证变化。

实现记录调用者／被调用者保存寄存器、保持 16 字节调用栈对齐，并在调用 C、运行时或内联汇编时遵守相应 clobber。不要求尾调用优化；正常递归可消耗栈，栈界限证明属于 Extend。

## R4. 算术、内存与原子降低

普通算术的溢出、除零、MIN/-1、移位计数和下标检查必须在执行产生无效机器／宿主操作前完成；失败进入 R5 的 panic 路径。包装运算按无符号位运算实现，不能以宿主有符号溢出代替。`@packed` 访问不依赖硬件支持未对齐操作。除零大小操作外，volatile／MMIO 每次生成相应宽度的一次机器加载／存储，不能拆分、合并或消除；调用者保证自然对齐及设备允许该宽度。

原子必须满足 reference 22 的模型。允许把请求提升为更强的顺序；首版可以统一以顺序一致操作实现。后端必须采用与链接运行时兼容的 [RISC-V 原子映射](https://github.com/riscv-non-isa/riscv-elf-psabi-doc/blob/48969b7995b3ae1582f230dcce32a12d443d1a7a/riscv-atomic.adoc)，或给出等价实现；不能把普通 volatile 当作原子。窄原子使用自身独占的 32 位存储做掩码操作，不对相邻普通字段做越界读改写。

本配置要求所有支持的原子实例无需分配、不调用可能睡眠的锁，并在 IRQ／TrapEntry 也可使用。可用原生 AMO 或 LR/SC 重试；不承诺 wait-free。强 compare_exchange 必须在仅因保留集丢失失败时内部重试，不向程序报告伪失败。程序其他部分不能普通读取、写入或 MMIO 访问同一原子存储。

指针 addr／ptr 往返按 reference 的数值地址模型降低，不引入可选 Borrow 的独占假设。若使用其他编译器作为后端，必须选择能保留本模型的表示／操作，不能无条件给 `&mut` 添加 noalias／restrict，也不能用未启用的效果分析优化掉调用。

## R5. Panic 与最小运行支持

编译器生成的 panic 调用以下平台符号；源程序不需要声明它：

```text
__biomiya_panic(message_address: *kernel const u8, message_length: usize) -> !
```

物理入口按 LP64 两个指针宽参数传递，且永不返回。平台可记录、停机或重启；不得展开栈、恢复原控制流或调用用户 defer。显式 panic 传入原消息视图；隐式检查失败可使用实现自定的静态消息，空消息使用非空对齐哨兵及零长度。该钩子必须在普通与陷阱上下文都可用，不依赖可睡眠服务。

后端生成的内存复制、整数或原子辅助调用必须由最终构建提供；它们也受同一不展开与上下文约束。工具链不能悄悄引入堆分配、全局初始化构造或未说明的系统调用。编译驱动必须列出需要的平台符号；缺少定义不得报告可运行构建成功。

## R6. 陷阱接口与平台责任

系统类型为 `arch::TrapFrame`，不自动预导入。它等价于以下公开 C 布局结构：

```text
@repr(C)
pub struct TrapFrame {
    pub x: [32]usize,
    pub sepc: usize,
    pub sstatus: usize,
    pub scause: usize,
    pub stval: usize,
}
```

字段偏移分别为 0、256、264、272、280，大小 288、对齐 8；平台可以将整个帧存储额外对齐到 16。x[n] 保存被中断的 xn，x[0] 为零、x[2] 是被中断的 sp。sepc／sstatus 是返回状态，scause／stval 是只读语义的故障快照（结构字段语法仍可写，但返回桩不以它们改写硬件故障状态）。没有隐藏资源句柄字段。

特殊函数的唯一签名为：

```text
@trap_entry fn entry(frame: &mut arch::TrapFrame) -> ! { ... }
@trap fn handler(frame: &mut arch::TrapFrame) -> () { ... }
@irq fn interrupt(frame: &mut arch::TrapFrame) -> () { ... }
```

形参名字可不同。三者的物理入口都接收 a0 中的帧指针并使用 R3 的保存约定；它们仍不能被源普通调用或转换成函数指针。`@export` 可以为其指定平台可链接符号，但不会使其成为 C 源调用接口。

硬件入口桩由平台提供，不由普通函数前序替代。平台负责保存被中断整数状态、构造帧、选择可访问的内核栈、建立 gp／tp、维护每 hart 活动帧与嵌套记录，再进入唯一选定的 trap_entry。入口桩策略（如 sscratch 用法）属于平台内部；传给语言代码的上述帧和 ABI 必须一致。入口及正常处理期间 SIE 保持关闭；首版不支持在处理函数内调度、睡眠或主动开启中断。故障造成的嵌套仍须由平台保存／恢复活动帧，或可靠进入 panic，不能覆盖未处理帧。

提供两个特殊转移内部函数：

```text
arch::enter_trap_handler(frame, named_trap_handler) -> !
arch::enter_irq_handler(frame, named_irq_handler) -> !
```

两者仅在 trap_entry 的尾转移位置可用，第二参数须为编译期具名、相应属性、相同帧签名的函数。第一参数基础类型为 `&mut arch::TrapFrame`；实际必须指向当前活动帧，不能是局部仿制帧或已失效的帧。此实际身份合同由平台调用者承担，Core 不额外证明。

转移先求值并保存帧地址，再按普通返回的作用域规则执行 trap_entry 的 defer、结束局部存储，然后进入下面的运行时分派器；此后不会返回 trap_entry：

```text
__biomiya_dispatch(frame_address, handler_address, kind) -> !
```

物理参数是两个地址宽标量及一个 usize，按 LP64 传递；kind=0 表示 trap、kind=1 表示 IRQ。handler_address 由编译器内部产生，不是源语言可构造的特殊函数指针。平台调用相应处理体；处理体正常返回前先执行其自己的 defer，然后分派器完成陷阱返回。panic 或不返回路径不执行剩余退出动作。

返回路径检查／维持帧存活和访问权限，恢复允许恢复的 sstatus、sepc 及 x1—x31，释放当前嵌套记录，执行 SRET；x0 的写入忽略。平台必须保证返回地址、特权位、映射和所选栈合法，修改帧不自动授予非法机器状态。Frame 的所有引用在该次返回后失效，不得将其存入长期存储后继续访问。页表切换、地址空间释放和非法返回状态属于显式平台合同，不能仅靠布局检查证明。

Blocking 开启时，三类特殊函数及其调用链都必须为空效果。Kernel Verification 可以另行检查栈、驻留和故障闭包；Core 只生成上面的转移及 ABI。

本配置的内核支持范围是具有上述不调度陷阱路径的运行环境。时钟中断直接调度、可睡眠系统调用、处理函数内主动开启中断等机制需要另行命名的平台配置，明确栈切换、活动帧所有权、恢复路径与阻塞合同；不能只关闭 Extend 就把这些行为算作 `rv64-core-v1` 支持。普通平台服务仍可通过规定的 ABI 提供。

## R7. 架构内部函数

下列名字位于保留模块 arch 中，不能由用户重新定义。除特别说明外 Blocking 效果为空；它们不能取函数指针。

| 接口 | 语义 | unsafe |
| --- | --- | --- |
| `arch::riscv::cpu_relax() -> ()` | 本配置使用 nop；不保证调度或睡眠 | 否 |
| `arch::riscv::wfi() -> () effects { may_block }` | 执行 WFI，允许提前返回；调用者重新检查唤醒条件 | 是 |
| `arch::riscv::csr_read(number: usize) -> usize` | 读取 CSR | 是 |
| `arch::riscv::csr_write(number: usize, value: usize) -> ()` | 写入 CSR | 是 |
| `arch::device_read_fence() -> ()` | `fence iorw, iorw`，提供设备与普通内存的保守顺序 | 否 |
| `arch::device_write_fence() -> ()` | 同上；两个名字表达调用意图，不减弱指令 | 否 |
| `arch::riscv::fence_i() -> ()` | 本 hart 的 FENCE.I；不代替其他 hart 的同步 | 是 |
| `arch::riscv::sfence_vma_all() -> ()` | `sfence.vma x0, x0`；不代替其他 hart 的失效协议 | 是 |

CSR number 必须是编译期 usize，且属于以下集合：sstatus=0x100、sie=0x104、stvec=0x105、sscratch=0x140、sepc=0x141、scause=0x142、stval=0x143、sip=0x144、satp=0x180；其他编号在本配置中编译失败。写操作必须符合 ISA 的保留位、权限及 WARL 规则。SIE、入口桩状态或映射的修改还须维持 R6 与平台合同；unsafe 不让这些合同失效。CSR 操作作为有副作用的操作，不得消除、合并或越过源顺序中的其他架构内部函数。

## R8. 受限内联汇编

本配置以以下专用表达式提供内联汇编，结果为 `()`：

```text
arch::asm("add a1, a0, a0", in("a0") value, out("a1") result);
```

参数语法为一个 STRING，后接零个或多个逗号分隔的 `in(STRING) expression`、`out(STRING) place`、`clobber(STRING)`，末尾可加 `effects { may_block }` 项，允许尾逗号。整个表达式必须位于 unsafe 块内。`arch::asm` 只能使用此完整路径，不允许导入为短名或经模块别名调用，避免依赖名字解析才能确定专用参数文法。

寄存器只接受 a0—a7、t0—t6 的规范名字；x 数字别名、sp、gp、tp、ra、s 寄存器及浮点／向量寄存器不作为操作数或 clobber 接受。同一寄存器至多一个输入和一个输出，允许输入／输出共用以表示先读后写；有输出的不再重复声明 clobber，其他重复声明拒绝。输入输出类型限整数、bool 和原始指针，不允许引用或聚合；有符号输入符号扩展到 64 位，无符号和 bool 输入零扩展，指针保留全部地址位。输出截取目标位宽，bool 的整个寄存器输出必须为 0／1。

先按出现顺序求值所有输入并保存，再按出现顺序求值所有输出位置地址并保存，然后装载输入、执行汇编、按输出顺序写回。输出位置不要求事先初始化，必须可写且满足存储合同；unsafe 及 Ownership 的资源约束没有被绕过（输出不接受资源类型）。汇编执行前出错不写输出；不允许观察尚未写回的输出值。

模板使用真实寄存器名字，不做占位符替换。解码后的模板必须是无 NUL 的 UTF-8；可用转义换行。允许目标汇编器支持的本配置指令和局部数字标签，不允许指示节／定义全局符号的数据指令、外部符号引用或任何函数调用。控制流必须在模板内并最终落到模板末尾；不允许 `ret`、SRET、非局部跳转、隐式正常返回或改变 sp。不得修改未列为输出／clobber 的通用寄存器；输入仅在同时列为输出或 clobber 时可修改。输出与纯输入寄存器不同，写输出不能破坏尚需读取的纯输入。

Core 验证参数语法、寄存器集合、类型及 unsafe 授权；模板指令与上述执行合同的匹配由汇编器及 unsafe 作者负责，不要求 Core 解码证明机器指令。汇编一律视为有副作用、可能读写普通内存的编译器屏障，不插入硬件 fence，不承诺原子或设备顺序。修改 CSR、普通存储或原子对象仍须满足其各自协议。

省略效果项声明空效果；如模板可能等待／阻塞必须声明 may_block，作为 Blocking 的受信合同保留。没有纯汇编、nomem、noreturn、动态模板、自动寄存器分配或通用约束字符串选项。

## R9. 构建交付与验收

平台必须交付启动／链接配置、panic 钩子；使用特殊陷阱函数时另交付入口桩和 dispatch／SRET 路径；使用后端辅助调用时提供相应符号。编译器应能列出未满足的目标依赖，不能以“Extend 未启用”替代它们。

前端按 [合规范用例](conformance.md) 验证 Core 接受和拒绝；后端至少验证整数边界、聚合参数与结果、C ABI 互调、所有退出路径的 defer、原子与 MMIO 宽度、陷阱帧偏移及特殊转移。测试固件和硬件模型不是本文件附带的实现；在这些验收完成前，本配置是可据以实现的规范，不是已有可运行编译器的声明。
