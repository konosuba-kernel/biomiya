**版本** 0.5
**配置** Core；Extend 按需启用；首个目标配置为 RV64
**状态** Core 实现基线；Extend 按章节声明支持范围；尚待编译器合规范验证

Architecture Supplement 提供目标机器的 ABI、寄存器、CSR、汇编、陷阱和设备栅栏定义，是目标适配规范。它与用于附加分析的 Extend 分属不同职责。Kernel Verification Supplement 属于 Extend，见第 34 章。首个可实现目标由 [RV64 目标补充](architecture-rv64.md) 闭合；[合规范用例](conformance.md) 提供接受、拒绝与运行结果的判定基线。

# 第一部分：核心集与语法（Core）

## 1. 引言

### 1.1 范围与分层

biomiya 是面向裸机、操作系统内核和底层系统软件的静态类型语言。Core 定义：

1. 有限大小的值、名义类型、简单泛型及显式布局。
2. Copy 与移动的值传递行为，以及无隐式析构的存储模型。
3. 引用、切片、原始指针和地址空间的表示与访问操作。
4. 确定的求值顺序、结构化控制流、`Result`、`?`、`defer` 和 panic。
5. 原子、volatile、MMIO、ABI 与目标接口。
6. 供扩展读取的资源、引用和效果标记。

Extend 在上述程序模型上增加所有权与资源消费、借用与逃逸、阻塞效果、并发使用及内核可靠性分析。Core 的通过表示程序满足基础翻译规则；它不表示程序无泄漏、无悬空访问、无数据竞争或满足业务正确性。每项验证保证必须对应实际启用并通过的扩展及其适用条件。

0.5 Core 不定义用户 trait、`const fn`、128 位整数和浮点类型。Core 不要求一般 lifetime 求解、非词法借用分析、分区来源跟踪、跨函数阻塞传播或栈上界证明。借用扩展可对 Core 能表示的程序施加保守限制，见第 31 章。

### 1.2 规范性用语

| 用语 | 含义 |
| --- | --- |
| 必须／不得 | 在所在配置内成立的要求／禁止 |
| 可以 | 允许，不是要求 |
| 应当 | 建议，不是合规范条件 |
| 未规定 | 本参考不选择具体结果，但实现仍须遵守其余适用条款 |
| 实现定义 | 实现必须文档化所选行为，并在同一程序内一致 |
| Core 编译失败 | 基础语法、解析、类型或翻译条件不成立，Core 必须拒绝 |
| 扩展验证失败 | 已启用扩展发现违反要求或不能完成要求的证明；不等于 Core 编译失败 |
| 执行合同违反 | 实际执行的操作不满足其存储、表示、访问或机器前置条件 |
| 超出规定语义 | 从实际违反执行合同的操作起，本参考不再约束后续执行 |

第 1—28 章未加限定的“编译失败”均指 Core 编译失败；第 29—34 章的验证要求只对启用相应扩展的配置生效。例子与说明性文字不覆盖规范条款。

### 1.3 合规范

一个 Core 实现必须：

- 拒绝正式部分规定的基础翻译错误；
- 为通过基础检查的程序实现规定的值表示、控制流和操作行为；
- 保留边界检查、规定的算术 panic、`defer` 和原子语义；
- 文档化实现定义的行为以及目标适配；
- 不把未启用的扩展证明作为接受程序或生成代码的前提。

Core 可以报告额外警告，但不得把没有通过未启用分析的程序当成 Core 语法或类型错误。程序能被翻译不保证其每次执行都满足运行合同。资源未消费、效果声明未验证或借用证明缺失本身不使执行超出规定语义；实际访问无效存储、读取移动后的未初始化值或发生数据竞争等违反执行合同的操作按第 17 章处理。

本文件与所选目标补充共同构成当前 0.5 的规范来源。附录 A 的完整语法与正文语义共同适用；用例不得覆盖二者。`draft.md` 保留设计历史，不参与合规范判断。Core 模式必须拒绝明确排除的语法。第 29 章规定的分析扩展只附加验证，不改变合法执行的行为；增加新语法或运行机制的实现扩展必须另外命名和文档化，不得与分析扩展混称。

### 1.4 翻译与验证阶段

Core 概念上执行：

1. 词法和语法分析。
2. 模块、名字与基础类型解析。
3. 泛型实例化、有限大小和布局检查、常量求值。
4. 结构化控制流与退出动作展开。
5. 目标代码生成与链接。

实现可以合并阶段。Extend 可以在保留源位置、类型和标记的程序表示上运行，但 Core 不要求构造借用来源集合或资源控制流证明。对同一满足执行合同的程序，启用分析不得改变求值、布局、ABI 或清理行为。

### 1.5 实现边界与拒绝条件

本版 Core 是闭合集合：附录 A 未列出、正文及目标补充也未明确引入的语法或操作必须拒绝。不得从 Rust、C 或其他语言补入默认行为。基础语法和类型错误即使位于未执行分支中也必须诊断；执行合同不是必须由编译器证明的静态条件。

实现资源不足可以终止翻译，但必须单列为实现限制，不能据此宣称程序违反 Core。正常模式下必须接受合规范用例中的正例；尚未实现的 Core 特性应报告“不支持”，不得当作扩展验证失败。编译器驱动的命令名、错误文字、缓存和内部表示不属于源语言规范。

本版不要求 Core 实现任何 Extend。第 30—32 章可以分别开发；第 33—34 章仍须选定具名验证配置后才有完整保证，不能仅凭本手册宣称通用并发或内核正确性验证已经实现。

## 2. 记号与词法

### 2.1 输入

源文件必须是 Unicode UTF-8。推荐扩展名是 `.vt`。字节序标记不是合法源字符，出现则编译失败。

行终止符是 U+000A。U+000D 后接 U+000A 视为一个行终止符。单独的 U+000D 视为一个行终止符。

### 2.2 空白与注释

空白是空格、水平制表符、垂直制表符、换页和行终止符。空白分隔记号，本身不产生语法节点。

注释有三种，均不产生语法节点。

```text
// line comment
/* block comment */
/// documentation comment
```

块注释可以嵌套。文档注释是语法上的注释。它附着于紧随其后的声明。本参考不规定文档注释的渲染。

未闭合的块注释编译失败。

### 2.3 标识符

标识符是 XID_Start 后接零个或多个 XID_Continue，或单个下划线后接至少一个 XID_Continue。单独的 `_` 是通配模式，不是标识符。

```text
identifier = XID_Start XID_Continue*
           | _ XID_Continue+
```

标识符字符分类固定为 Unicode 15.1 的 XID_Start／XID_Continue；源文件不做规范化，名字按 Unicode 标量序列精确比较。关键字不得作为标识符。原始标识符不在 0.5 定义。

### 2.4 关键字

```text
module import pub type struct enum fn impl
const static mut let var if else match
loop while for break continue return
defer unsafe extern effects
true false null as
resource
```

上下文关键字，仅在指定位置保留：

```text
abi self move in
kernel user phys mmio
```

`sizeof`、`alignof`、`offsetof`、`static_assert` 是保留的语法内部函数名，不可声明同名绑定；`Self` 在实现块内保留为目标类型名。其余预定义名字通过名字解析识别。

`Some`、`None`、`Ok`、`Err` 不是关键字。它们是 `core` 预导入的变体名。

### 2.5 整数字面量

```text
decimal     = [0-9][0-9_]*
hexadecimal = 0x [0-9a-fA-F][0-9a-fA-F_]*
binary      = 0b [01][01_]*
integer     = decimal | hexadecimal | binary
```

下划线不改变数值。数值部分不得以下划线结尾，也不得在进位前缀后立即出现下划线。后缀前的分隔下划线属于后缀，不属于数值部分。

后缀由下划线和整数类型名组成，直接粘连在数值部分后：

```text
1_u8  1_u16  1_u32  1_u64  1_usize
1_i8  1_i16  1_i32  1_i64  1_isize
```

无后缀且上下文不能决定类型时，类型是 `i32`，前提是数值能被 `i32` 表示。不能表示则编译失败。

一元 `-` 紧邻有符号字面量时，幅度可以达到该类型 `MAX + 1`，仅用于形成 `MIN`。因此 `-128_i8` 合法，`128_i8` 不合法。

### 2.6 字符串字面量

```text
string = " string_char* "
```

字符串字面量的类型是 `[]const u8`。它存放在静态存储中，程序生命周期有效。不自动追加 U+0000。

转义：

| 转义 | 含义 |
| --- | --- |
| `\0` | U+0000 |
| `\n` | U+000A |
| `\r` | U+000D |
| `\t` | U+0009 |
| `\\` | `\` |
| `\"` | `"` |
| `\xHH` | 一个字节，`HH` 为十六进制 |

未转义的字符按 UTF-8 编码为字节；字符串不得跨物理行，未转义的双引号结束字符串，反斜线只用于下表中的转义。

`\xHH` 产生原始字节，不要求是标量值。未知转义编译失败。0.5 不定义原始字符串、字节串前缀或 Unicode `\u` 转义。

### 2.7 标点与最长匹配

词法分析使用最长匹配。下列三个双字符序列各是单个记号，不是二元运算符后接 `?`：

```text
+?  -?  *?
```

后缀 `?` 是独立运算符，按第 12.1 节的优先级绑定到其左侧操作数。

分隔符：

```text
( ) [ ] { }
, ; : :: . .. ..=
-> =>
```

运算符见第 12 章。

## 3. 语法约定

语法使用下列写法：

- `italics` 或中文描述是语法范畴。
- 引号内或代码体是字面记号。
- `( ... )*` 表示重复零次或多次。
- `( ... )+` 表示重复一次或多次。
- `( ... )?` 表示可选。
- 选择分行或用 `|` 分隔。

语句与声明以分号结束，或由块自然结束。块表达式的值是尾表达式；没有尾表达式时值是 `()`。

```text
block = { statement* tail? }
tail  = expression
```

`unsafe { ... }` 是块，同时打开第 17 章的词法授权上下文。它不关闭基础检查或已启用的扩展验证。

### 3.1 分号、尾表达式与解析边界

完整产生式见附录 A。`let`、`var`、`defer call`、`static_assert` 和普通表达式语句必须有分号。块、`unsafe` 块、`if`、`match`、`loop`、`while`、`for` 作为独立语句时可省略分号；它们的值在语句位置丢弃。块中紧接结束 `}`、未带分号的最后一个表达式是尾表达式，包括块式表达式。单独 `;` 是空语句。

语句起始的未加括号块式表达式，仍先连接调用、字段、下标与 `?` 后缀。随后若紧接 `*`、`&` 或 `-`，按独立块式语句结束；该记号开始下一条一元表达式语句。例如 `if ready { continue; } *p = n;` 中，`*p = n` 是下一条语句。要把这三个记号用作该块结果的二元运算符，须写 `(if flag { a } else { b }) * c` 等括号形式。其他二元运算符继续当前表达式。这项定界仅适用于语句起始，绑定初始化器、调用实参、return／break 操作数和括号内部使用普通表达式解析；`{callback}()` 仍是调用，`let n = if flag { 1 } else { 2 } * 3;` 仍是乘法。

`if`／`while` 条件、`match` 被检表达式和 `for` 输入的最外层禁止未加括号的具名字段构造；该层遇到 `{` 开始控制流块。需要构造时写 `if (Flag { value: true }).value { ... }`。括号、调用实参、数组和索引内部恢复普通表达式语法。`else` 绑定最近的未配对 `if`。

没有闭包、标签、局部函数或局部类型声明，没有 `if let`、`while let`、模式守卫、宏、方法值捕获或用户运算符重载。函数调用、字段、下标、`?` 按从左到右的后缀链解析。`return` 和 `break` 的操作数延伸到当前位置的表达式结束分隔符；二者及 `continue` 的类型是 `!`。

## 4. 程序、模块与名字

### 4.1 源文件

一个源文件可选地以模块声明开始，然后是零个或多个导入，然后是零个或多个声明。

```text
file       = module_decl? import* declaration*
module_decl = module path ;
path       = identifier (:: identifier)*
```

一个编译单元是一组显式提供的源文件；不根据目录自动发现模块。未写 `module` 的文件属于根模块。相同模块路径的文件合并为一个声明集合，与命令行顺序无关；模块路径的前缀自动形成模块。声明可向前引用，局部绑定只从初始化器完成后可见。

`core` 和 `arch` 是根下保留的系统模块，用户不得重新定义；`root` 是指向用户包根的路径前缀，不可用作绑定名。模块导入可以成环，但别名、常量依赖和按值布局依赖不得成环。模块来源和外部对象由构建输入确定，0.5 不定义包管理器。

### 4.2 可见性

声明默认只在当前模块可见。`pub` 使声明对导入它的模块可见。

```text
pub struct Page { number: usize }
pub fn alloc() -> Result<Page, AllocError> { ... }
```

模块路径只是命名容器，路径可遍历不授予其私有成员访问权。父子模块之间也不自动获得私有访问权。公开声明暴露的参数、结果和公开字段类型必须对所有可访问该声明的模块可见；私有字段可以含私有类型。

字段默认私有，与所属结构体的可见性无关。`pub` 字段对外可见。枚举变体的可见性与枚举相同。0.5 不定义 `pub(path)` 或其他受限可见性。

### 4.3 导入

```text
import path ;
import path :: { name (, name)* ,? } ;
```

`import mm::page` 把末段 `page` 引入当前模块。花括号形式只引入列出的名字。导入不是重导出。要重导出，必须再声明 `pub` 别名或 `pub` 包装函数。0.5 不定义 `import ... as`。

### 4.4 路径与解析

路径 `a::b::c` 从左到右解析。首段按下列顺序查找：

1. 当前词法作用域及逐层外部词法作用域中，在当前位置可见且属于所需名字空间的绑定，包括函数参数、局部绑定和泛型参数；最近的绑定优先。
2. 当前模块的声明与导入。
3. 预导入的 `core`。
4. 包根。

类型位置的最终名字必须是类型或类型参数；值位置的最终名字必须是值、函数、常量或变体构造者。路径中间段可以解析为模块或具有相应成员的类型。模式中引入的新绑定不按既有名字查找处理。同一名字空间中同一作用域不得有两个可同时可见的同名绑定，否则编译失败。

模块／类型／值分别具有名字空间；构造者占用值名字空间，结构体及枚举类型占用类型名字空间。模块与类型作为同一路径中间段时不得同名。函数不按参数重载。相同名字的导入和声明在同一名字空间中冲突，重复导入也拒绝。局部同一作用域不允许再次绑定同名值；嵌套作用域可遮蔽。

局部绑定遮蔽外层绑定。遮蔽不结束外层绑定的存储期；启用 Ownership 时也不清除其拥有状态或消费义务。

### 4.5 预导入

下列名字在每个模块可用，无需导入。显式局部声明可以遮蔽它们。

```text
Option Some None
Result Ok Err
MaybeUninit UnsafeCell Atomic MemoryOrder
Relaxed Acquire Release AcqRel SeqCst
replace swap split_at_mut forget panic checked_cast
addr ptr ptr_add ptr_add_bytes
addr_of addr_of_mut slice_from_raw_parts slice_from_raw_parts_mut
volatile_load volatile_store mmio_load mmio_store
```

上述普通名字也可用 `core::名字` 访问；整数类型、`bool`、`Copy` 是不可重新声明的预定义类型／约束名。内部函数按所解析声明身份识别，不按用户函数的拼写识别；除具名普通函数外，内部函数不能取函数指针。完整接口见附录 D。

整数类型上的 `MIN` 与 `MAX` 通过类型路径访问，例如 `i8::MIN`、`u64::MAX`。

## 5. 声明

### 5.1 类型别名

```text
type Name = Type ;
```

别名透明。`type Phys = usize` 与 `usize` 没有 nominal 区别，也不产生新的借用或资源属性。别名不得循环。需要 nominal 类型时使用 newtype。

### 5.2 结构体

```text
struct_decl = attribute* resource? struct Name generic_params? { field_list? }
           | attribute* resource? struct Name generic_params? ( Type ) ;
field_list  = field (, field)* ,?
field       = pub? Name : Type
```

构造使用字段名，顺序无关：

```text
let task = Task { pid: pid, state: Ready };
```

字段声明不得重名。构造表达式缺少字段初始化、重复字段或提供多余字段时编译失败；没有字段简写，所有字段均写 `name: expression`。构造表达式的访问权限必须覆盖全部字段，字段表达式按源码书写顺序求值，再放入各自声明位置。0.5 不定义函数式记录更新。

单字段结构体是 newtype：

```text
struct PhysAddr(usize);
struct VirtAddr(usize);
struct Pid(u32);
```

不同 newtype 不隐式互换。使用 `Name(value)` 构造，使用 `Name(pattern)` 解构；载荷按私有字段处理，`.0` 只在定义模块可访问。0.5 不支持公开位置载荷。元组的数字字段另见第 11.8 节。

### 5.3 枚举

```text
enum Name generic_params? { variant (, variant)* ,? }
variant = Name
        | Name ( Type )
        | Name { field_list }
```

枚举至少有一个变体，变体名字不得重复；具名载荷字段不得写 `pub`，其可见性等于变体。变体可以无载荷、有一个位置载荷，或有具名字段。使用完整名 `TaskState::Ready`。上下文能唯一确定枚举类型时，可以只写变体名。唯一性由期待类型决定，不由可达值决定。

### 5.4 函数

```text
fn_decl = attribute* unsafe? (extern abi(C))? fn Name generic_params?
          ( param_list? ) return_ty? effect_clause? block
param_list = receiver (, param)* ,? | param (, param)* ,?
receiver = self | &self | &mut self
param   = Name : Type
return_ty = -> Type
effect_clause = effects { (may_block ,?)? }
```

参数名字必须唯一；参数绑定不可重新赋值，但可通过 `&mut` 参数修改目标。函数正常到达体末尾时，尾表达式作为返回值；没有尾表达式等于返回 `()`。函数体类型必须能按第 6.12 节检查为返回类型，`!` 返回的函数不得存在结构上可到达的正常结束。

参数和返回类型必须显式写出。省略返回类型等于 `-> ()`。局部绑定可以推断。

接收者只允许 `self`、`&self`、`&mut self`，且必须是第一个参数。`self` 的类型是实现类型。`&self` 是 `&Self`，`&mut self` 是 `&mut Self`。

接收者只允许出现在固有实现的方法中。`effects {}` 与省略效果子句相同；重复或未知效果编译失败。

```text
impl Page {
    fn number(&self) -> usize { return self.number; }
    fn clear(&mut self) { ... }
}
```

### 5.5 实现块

```text
impl generic_params? Type { fn_decl* }
```

0.5 只有固有实现。没有 trait 实现。实现目标必须是本模块声明的名义结构体或枚举；不得为别名、引用、数组、原始指针或其他模块类型添加实现。对泛型类型 `S<A, B>`，只允许 `impl<A, B> S<A, B>`，参数数量、顺序和 Copy 约束与类型声明一致；不允许专门化、额外实现参数或重叠实现。方法自己的泛型参数不得与实现参数同名。方法默认私有，可用 `pub fn` 公开；实现块本身不带 `pub`。同一类型的多个固有实现允许，方法名不得冲突。泛型实现使用第 10 章的参数与约束规则。`Self` 在实现块内表示该实现的目标类型。

### 5.6 常量与静态

```text
const NAME : Type = expression ;
static NAME : Type = expression ;
static mut NAME : Type = expression ;
```

`const` 不占有存储身份，类型必须 Copy。`static` 是程序生命周期、具有存储身份的唯一对象。`static mut` 的普通读、写、借用及原始取址必须位于 unsafe 块中。初始化器必须是常量表达式；外部静态声明另见第 5.7 节。

`const` 初始化器中的引用只允许指向静态存储，这是常量构造规则。Copy 静态对象可以按值读取；可写 non-Copy 静态对象的移出按第 7 章使目标未初始化，后续读取仍须满足执行合同。静态对象没有局部退出析构；资源与全局拥有关系的验证见第 30 章。对 `static mut` 的 unsafe 要求仍适用。

### 5.7 外部声明

```text
extern abi ( C ) fn Name ( param_list? ) return_ty? effect_clause? ;
```

此处的外部声明不带函数体，定义由链接提供。使用同一 `extern abi(C)` 前缀并提供函数体时，是 biomiya 定义的 C ABI 函数。两种形式均不得具有泛型参数或可变参数，参数与返回值必须满足第 25.1 节的 ABI 兼容条件。调用均是 unsafe 操作；函数体内的 unsafe 操作仍须显式 unsafe 块。外部声明可以在返回类型后写效果子句，省略表示空效果集；Blocking 扩展使用该声明作为需验证或明确受信的效果合同。

外部静态对象使用同一 ABI 前缀：

```text
extern abi(C) static NAME: Type;
extern abi(C) static mut NAME: Type;
```

声明不带初始化器，链接符号为声明名；不能带 `@export`、`@section` 或 `@align`，也不能在实现块中出现。类型必须满足第 25.1 节的 C 字段条件，允许正长度数组。外部存储的所有读取、写入、引用构造及原始取址均要求 unsafe。没有 `mut` 时仅可读取或取得只读引用／const 原始指针；`mut` 表示声明所需的写权限，不证明平台确实提供了该权限。

平台须保证实际访问的对象具有声明的大小、对齐、有效期和初始化状态。链接脚本的边界符号可以声明为外部 `u8`，用 `addr_of(NAME)` 取得符号指针，再用 `addr` 取得数值地址；这一仅取址用法不要求该符号本身提供一个可读的字节。读取、借用或写入仍要求真实对象合同，链接符号存在不授予这些权利。外部符号一致性与链接失败按第 25.3 节处理。

### 5.8 属性

0.5 属性是声明前缀：

```text
@copy
@repr(C)
@align(expression)
@packed
@export(string)
@section(string)
@irq
@trap_entry
@trap
```

不识别的属性编译失败。仅启用 Core 时，第 34 章提到的专用验证注解不是已识别属性；启用相应验证补充后，按该补充识别和检查。验证注解不得静默忽略。除 `@copy` 外，属性不改变所有权种类，除非条款明确说明。

每个 Core 属性在同一声明上至多出现一次，重复即编译失败，即使参数相同。适用位置和参数如下；其他位置编译失败。

| 属性 | 适用声明 | 参数与组合限制 |
| --- | --- | --- |
| `@copy` | 结构体、newtype、枚举 | 无参数；按第 7.2 节检查，不得与 `resource` 同用 |
| `@repr(C)` | 结构体、newtype | 唯一参数是标识符 `C`；0.5 不定义 C 布局枚举 |
| `@align(N)` | 结构体、newtype、枚举、静态对象定义 | `N` 为正的 2 的幂整数常量，且在目标支持范围内 |
| `@packed` | 结构体、newtype | 无参数；不得与同一声明上的 `@align` 并用 |
| `@export(name)` | 非泛型函数定义、静态对象定义 | `name` 是非空且不含 NUL 的字符串字面量，不用于外部声明 |
| `@section(name)` | 函数定义、静态对象定义 | `name` 是非空且不含 NUL 的字符串字面量；具体节的可用性由目标文档规定 |
| `@irq`、`@trap_entry`、`@trap` | 非泛型且未声明 C ABI 的函数定义 | 无参数；三者互斥，不得与 `extern abi(C)` 并用；签名及入口 ABI 须符合 Architecture Supplement |

`@repr(C)` 与 `@align` 或 `@packed` 的布局组合按第 24 章处理；不能仅因接受属性语法就假定目标 C ABI 支持该组合。属性书写顺序不改变含义。Core 属性不用于字段、参数、局部绑定、类型别名或实现块本身。

## 6. 类型

### 6.1 类型文法

```text
Type = path generic_args?
     | & mut? Type
     | * address_space? const? Type
     | [ expression ] Type
     | [ ] const? Type
     | ( Type_list? )
     | fn_type
     | !
     | ()

address_space = kernel | user | phys | mmio
fn_type = unsafe? (extern abi(C))? fn ( Type_list? ) return_ty? effect_clause?
Type_list = Type (, Type)* ,?
```

省略地址空间等于 `kernel`。`*T` 等于 `*kernel T`。`*const T` 等于 `*kernel const T`。

`extern` 与 `abi(C)` 必须一起出现。外部函数指针的调用按第 5.7 节要求 unsafe，不因省略 `unsafe` 前缀而成为安全调用。括号内只有一个类型时是类型分组；空括号是 `()`。

### 6.2 整数

```text
u8 u16 u32 u64 usize
i8 i16 i32 i64 isize
```

`usize` 与 `isize` 的位宽等于目标自然地址宽度。RV64 上二者均为 64 位，`sizeof` 均为 8 字节。0.5 没有 `u128`、`i128` 和浮点。

每个整数类型提供 `MIN` 与 `MAX`，且是常量。

### 6.3 `bool`

值只有 `true` 和 `false`。整数不得隐式转换为 `bool`。`if count { }` 编译失败，必须写 `if count != 0`。

### 6.4 单元与 Never

`()` 既是类型也是唯一值。`!` 表示正常求值不产生结果。`!` 可以强制到任何具体类型的表达式位置。`!` 不是对象类型，没有 `sizeof`。

```text
fn halt() -> ! effects { may_block } {
    loop { unsafe { arch::riscv::wfi(); } }
}
```

### 6.5 数组与切片

`[N]T` 是拥有元素的定长数组。`N` 必须是类型为整数的常量表达式，且不得为负。数组是对象。

`[]const T` 是只读切片。`[]T` 是可变切片。切片是固定长度的借用视图，不拥有元素。切片本身是一对地址与长度，其 Copy 属性见第 7 章。

数组和切片索引执行边界检查。负数或越界索引均 `panic`。范围 `a..b` 要求 `0 <= a <= b <= len`，否则 `panic`。

### 6.6 元组

`(T1, T2, ...)` 是结构积。空元组就是 `()`。解构 `let (x, y) = pair;` 按位置绑定。一元元组不存在。单个括号只分组。

### 6.7 引用

`&T` 是只读引用，`&mut T` 是可写引用，均以非空目标地址表示。Core 检查构造与访问的基础类型；实际访问要求目标存活、对齐且读取时为合法已初始化值。引用本身不延长存储期，也不代表已经证明独占或无悬空。共享冻结、可变独占与生命周期证明由第 31 章提供。从原始指针构造引用仍要求 unsafe，见第 19 章。

### 6.8 原始指针

```text
*kernel T    *kernel const T
*user T      *user const T
*phys T      *phys const T
*mmio T      *mmio const T
```

原始指针可以为空、悬空、未对齐、未映射或指向未初始化存储。它们不是引用。地址空间决定哪些操作合法，见第 20 章。

### 6.9 函数指针

```text
fn(u32) -> bool
unsafe fn(*u8) -> ()
extern abi(C) fn(*u8, usize) -> i32
fn() -> () effects { may_block }
```

函数指针 Copy、非空、不捕获环境、不隐式分配。Core 允许返回引用或切片；借用扩展对这种间接调用接口的限制见第 31.5 节。

具名的非特殊上下文函数可以转换为签名相符的函数指针；泛型函数必须先唯一确定具体实例。参数和返回类型必须相同，ABI 必须相同；Core 保留效果元数据而不检查其扩大关系，第 32 章负责该验证。普通安全函数可以转换为 unsafe 函数指针，反向不允许。C ABI 函数指针无论是否显式写 `unsafe` 都具有相同的 unsafe 调用要求；不得转换为普通 biomiya ABI 指针。`@irq`、`@trap_entry` 和 `@trap` 函数不得通过普通函数指针调用。

### 6.10 对象大小

除 `!` 外，每个可作为对象存在的类型必须有编译期有限的 `sizeof(T)` 和 `alignof(T)`。按值直接递归不合法：

```text
struct Node { next: Node } // 编译失败
```

经固定间接递归合法：

```text
struct Node { next: *Node }
```

### 6.11 标准库类型

下列类型由 Core 识别其表示、构造或操作语义：

```text
Option<T>  Result<T, E>
MaybeUninit<T>  UnsafeCell<T>  Atomic<T>
```

概念定义：

```text
@copy
enum Option<T> { Some(T), None }

@copy
enum Result<T, E> { Ok(T), Err(E) }
```

`@copy` 在这里表示条件结构 Copy：当且仅当全部类型参数 Copy 时，该实例 Copy。资源与携带引用属性随参数传播。Core 泛型可携带引用；在借用扩展的保守限制下，`Option` 与 `Result` 是借用透明例外。

“携带引用”（borrow-carrying）指类型自身是引用或切片，或递归按值包含它们；原始指针和函数指针不沿其目标、参数或返回类型传播该属性。Core 可以按结构计算此属性以检查 ABI，不需要为值追踪具体引用来源。

### 6.12 类型相容、推导与强制转换

类型相等先展开别名，再比较名义声明身份、类型实参、数组长度及类型构造。整数不做提升。基础函数签名比较参数、结果、ABI 和 unsafe 属性；效果元数据按第 16 章保留并由 Blocking 检查，不参与 Core 的接受判定。不能通过别名或嵌套函数指针抹去效果元数据。

Core 使用局部结构推导，不进行重载搜索或一般约束求解：

1. 显式绑定类型、函数结果、已确定的调用形参、赋值目标和聚合字段向对应表达式提供期待类型。
2. 相同类型的运算操作数、数组元素、分支结果与 `break` 结果生成类型相等约束；`!` 不限制其他结果类型。泛型调用的形参／结果结构与实参／期待结果统一，类型参数不能递归等于含自己的类型。
3. 无后缀整数字面量先保持待定整数；传播上述约束到不动点后，仍待定的整数默认为 `i32` 并检查范围。`null` 必须被约束成原始指针，不能默认；没有元素的数组须有确定元素类型。仍未确定的泛型参数或空构造载荷类型编译失败。
4. 推导范围是一个完整表达式或一个绑定初始化器；不从后续语句倒推先前绑定类型。未实例化泛型体的名字和语法总要检查；依赖类型的运算按第 10.2 节在所需实例中检查。

仅允许下列隐式适配，且只能发生在已确定目标类型的位置：`!` 到任意结果类型、同元素 `&mut T` 到 `&T`、`[]T` 到 `[]const T`、同地址空间可变原始指针到 const 指针、具名函数到相容函数指针，以及安全函数指针到 unsafe 函数指针。引用与切片的这两种弱化分别生成再借用和只读视图，不读取或移动目标；不移动原可变视图绑定。其他 non-Copy 按值传参仍执行移动，不自动再借用。

没有数组到切片、引用到原始指针、整数拓宽、结构递归转换或 `T` 到 `&T` 的隐式适配。不同分支没有已确定的期待类型时须相等，不自动寻找共同超类型。泛型参数推导先按原实参类型统一，不靠尝试上述弱化寻找候选；已经显式确定的形参则可以适配。方法接收者的特定借用规则见第 11.9 节。

不可达语句仍检查语法、名字及类型。结构可达性只使用 `!`、顺序、分支和循环跳转，不以算术求值或求解条件是否恒真来免除类型错误。`()` 可作参数、字段或数组元素；`!` 只可作函数结果和表达式类型，不可作变量、成员、元素或泛型类型实参。

## 7. 值传递与资源标记

### 7.1 Copy 与移动

Core 以 Copy 属性决定按值使用的含义。Copy 使用复制值，源仍保持初始化；non-Copy 使用移动值，源在该次操作后逻辑上未初始化。实现不必清零源字节或维护运行时移动标志。实际再次读取未初始化的源违反执行合同；对所有控制流路径预先排除此类读取属于第 30 章。

赋值、拥有参数、按值返回和按值匹配使用同一规则。通过引用读取 Copy 目标得到副本。通过可变引用移出 non-Copy 目标使目标未初始化；通过共享引用不得移出 non-Copy 目标，这是访问类型规则。类型与语法允许的操作是否维持完整的拥有关系，由所有权扩展检查。

### 7.2 类型分类

Copy 类型包括 `()`、整数、`bool`、原始指针、函数指针、`&T` 和 `[]const T`。`&mut T`、`[]T`、`MaybeUninit<T>`、`UnsafeCell<T>`、`Atomic<T>` 及资源类型是 non-Copy。

用户结构体和枚举默认 non-Copy。`@copy` 为非泛型聚合选择结构 Copy，所有按值成员必须 Copy，否则编译失败。泛型 `@copy` 表示实例的全部成员 Copy 时该实例才 Copy。数组按元素、元组按各分量确定 Copy。引用和指针不沿目标传播 Copy 属性。

### 7.3 资源分类

```text
resource struct Frame { number: usize }
```

`resource` 是 Core 识别的类型标记，不添加运行时头部、自动释放或隐藏析构。资源类型是 non-Copy，不能同时标记 `@copy`。资源属性沿按值结构体、枚举、数组、元组、`Option`、`Result` 和 `UnsafeCell` 传播，不沿引用、切片或指针的目标传播；`MaybeUninit` 不传播资源属性。

Core 计算该属性以保持 Copy 分类与 ABI 规则一致。`must-consume` 表示第 30 章验证器的消费要求，不要求 Core 跟踪每条路径的消费状态。`discardable` 表示没有这种附加义务。

### 7.4 存储结束与丢弃

Core 不运行隐式析构。丢弃值、覆盖值和局部作用域结束不会自动关闭句柄、释放帧或销毁引用指向的对象。资源泄漏检查属于所有权与资源扩展；泄漏本身不是 Core 的未定义执行。显式调用的释放函数仍必须满足其执行合同。

字段移出使对应字段未初始化，实际读取该字段或需要整个聚合值的操作违反初始化合同；其他已初始化字段的普通读取不自动变为无效。第 30 章采用更保守的整体移动规则。

```text
unsafe { forget(value); }
```

`forget` 按值接收并丢弃值，不执行释放。Core 保留其 unsafe 调用要求；启用所有权扩展时，它还表示显式放弃消费义务。它不赋予再次使用已移动源或破坏已存在访问合同的权利。

## 8. 绑定与赋值

### 8.1 `let` 与 `var`

```text
let value = expression;
var value = expression;
```

`let` 和 `var` 必须初始化，不允许只声明后赋值。二者均接受不可反驳模式，模式内所有绑定分别为不可变或可变；名字在整个初始化器完成后同时生效。

`let` 创建不可重新赋值的绑定。值仍可读取、移动和借用。`var` 允许重新赋值和可变借用。

类型可写：

```text
let value: T = expression;
```

显式类型是期待类型。

### 8.2 位置

位置是可读取或可借用的存储；只有可写位置才能赋值。位置包括局部、静态对象及其字段和数组元素，以及引用或原始指针的解引用目标。可写位置包括：

- 可变局部；
- 可写聚合位置的字段；
- 可写数组位置的元素；
- `&mut T` 的目标；
- unsafe 上下文中可变 kernel 原始指针的解引用位置。

不可变绑定的普通拥有字段不是可赋值位置。`&mut T` 或 `[]T` 的目标可写性不受保存视图的绑定是否可变影响。对只读引用、const 指针的普通目标不得写入。非位置的值在需要字段／下标读取时物化为完整表达式内的临时存储；临时存储可读但不可变借用。`&` 仅接受位置，不隐式物化任意右值。

### 8.3 赋值顺序

对 `place = expression`：

1. 求值右部。
2. 求值左部的位置表达式一次，包括基址与索引，并按基础类型检查其可写性、执行必要的边界检查。
3. 结束旧值生命周期。
4. 写入新值。
5. 位置成为已初始化。

Core 的赋值可覆盖现有值，不隐式释放旧值；资源覆盖的诊断属于第 30 章。已移动的可写位置可以重新初始化。覆盖无需读取旧值，也不要求旧值已初始化。

右部若通过 `?`、`return` 或 panic 离开，则不求值左部，也不写入。赋值表达式的类型和值为 `()`。实现必须保存右部结果直到完成写入；保存引用不延长其目标存储期。复合赋值按第 12.6 节执行。

### 8.4 `replace` 与 `swap`

```text
replace(place: &mut T, value: T) -> T
swap(a: &mut T, b: &mut T)
```

`replace` 移出旧值、写入新值并返回旧值；`swap` 交换两个位置的值，完全相同的位置交换无效果。两者要求有效、已初始化且可写的完整 `T` 存储；不同位置不得部分重叠。Core 不限制 `T` 是否携带引用，相关逃逸与借用限制由第 31 章检查。

### 8.5 控制流与初始化

不同分支可以执行不同的移动和赋值。Core 不要求分支合并点上的拥有状态一致，也不要求循环回边恢复初始拥有状态。实际读取的值必须已初始化；静态证明由第 30 章负责。

## 9. 引用、切片与存储期

### 9.1 引用操作

`&place` 取得只读引用，`&mut place` 取得可写引用。Core 检查位置、类型和可写性，不计算借用来源集合或别名关系。引用保存目标地址，不拥有目标，不延长目标存储期。再借用是通过现有引用取得另一个引用，不复制目标对象。

`&T` 禁止通过该引用写入普通 `T`；`&mut T` 允许写入。仅有这两个类型名不意味着 Core 已证明目标无其他别名。独占与共享冻结的静态要求属于第 31 章；`UnsafeCell` 的显式内部可变访问见第 21 章。

### 9.2 切片操作

切片保存地址与长度，固定长度且不拥有元素。下标和范围按第 11.8 节执行运行时边界检查。只读切片禁止通过它写入；可变切片允许写入。Core 不证明两个切片是否重叠。所有实际访问仍必须满足存活、初始化、对齐和同步合同。

### 9.3 必备切片辅助函数

```text
fn split_at_mut<T>(slice: []T, mid: usize) -> ([]T, []T)
```

该操作移动输入视图；`mid > slice.len` 时 panic，否则构造逻辑元素区间 `[0, mid)` 和 `[mid, len)` 的两个可变切片。元素不复制、不移动，顺序不变。`mid` 为 0 或 `len` 合法；零大小元素按逻辑下标分段。

Core 只实现长度检查和视图构造，不维护分区身份。第 31.7 节规定启用借用扩展时对两个结果的证明规则。

切片提供以下内建成员，不读取元素或移动原视图；接收者规则见第 11.9 节：

```text
[]const T::as_ptr(&self) -> *kernel const T
[]T::as_ptr(&self) -> *kernel const T
[]T::as_mut_ptr(&self) -> *kernel T
```

这些行是接口记法，调用写作 `view.as_ptr()` 或 `view.as_mut_ptr()`；只读切片没有 `as_mut_ptr`。返回切片保存的数据地址，空切片同样可用。不创建元素引用、不延长目标存储期；后续原始访问仍要求 unsafe，取得可写指针不授予绕过现有借用或同步合同的权利。

原始存储可通过以下 unsafe 内部函数构造成视图：

```text
unsafe fn slice_from_raw_parts<T>(data: *kernel const T, len: usize) -> []const T
unsafe fn slice_from_raw_parts_mut<T>(data: *kernel T, len: usize) -> []T
```

两者仅保存地址和长度，不复制元素，不分配。调用者必须保证地址非空、按 `T` 对齐，`len * sizeof(T)` 及地址加上该字节数可由 `usize` 表示；非空元素区间属于同一个存活的普通存储区域，全部元素已初始化且具有合法 `T` 表示，并具备相应读／写权限。零长度不要求存在可访问的元素，但仍要求非空、对齐；零大小元素遵守第 18 章的逻辑存储身份合同。违约超出规定语义，不生成自动修复或必需的运行时检查。切片不拥有存储；每次后续访问仍须满足有效期与同步合同，Borrow 开启时另检查借用与返回来源。`user`、`phys`、`mmio` 指针不能直接传入。

### 9.4 完整表达式与临时存储

完整表达式包括表达式语句、局部初始化器、块尾表达式、`return` 或 `break` 的操作数、`if` 或每次 `while` 的条件、`match` 的被检表达式及 `for` 输入。嵌套调用、参数、操作数和括号不单独构成边界；赋值的左右操作数属于同一表达式。

未转移出的临时拥有存储在所属完整表达式结束时结束。匹配被检值和遍历输入若仍为当前结构所需，其存储保持到整个匹配或遍历结束。嵌套块只结束它自己创建且未转移出的临时存储。具名局部存储持续到作用域退出；静态存储持续到程序结束。

复制、移动或保存引用本身不会延长其目标存储期。Core 不自动提升临时对象的存储期。借用扩展使用这些存储边界检查引用是否有效，但不改变目标的实际存储期。

### 9.5 返回引用

Core 允许具名函数和函数指针返回引用、切片或包含它们的聚合，按普通返回值传递地址与长度。返回并不延长被指对象的存储期。返回已结束局部存储的地址可被 Core 翻译，但之后通过该地址访问已结束对象违反执行合同。

返回来源的单源限制、函数指针借用返回限制，以及逃逸诊断只在借用扩展中生效，见第 31 章。C ABI 仍按第 25 章禁止直接传递 biomiya 引用或切片。

## 10. 泛型

### 10.1 语法

```text
generic_params = < Name (: Copy)? (, Name (: Copy)?)* ,? >
generic_args   = < Type (, Type)* ,? >
```

0.5 唯一通用能力约束是 `T: Copy`。没有用户 trait。

类型位置使用 `Queue<u32>`。表达式路径上的显式类型实参必须使用 `::<...>`，例如 `identity::<u32>(value)`、`Queue::<u32>::new()`；方法使用 `value.method::<u32>(argument)`。`identity<u32>(value)` 不作为泛型调用语法。调用前可以省略全部类型实参，由实参类型和期待结果类型唯一推导；不得只提供部分类型实参，也没有类型实参占位符。不能唯一确定全部类型实参时编译失败。

在类型实参列表的闭合位置，语法分析可以从 `>>`、`>=` 或 `>>=` 中拆出所需的 `>`，余下部分按普通记号处理；其他表达式位置不进行这种拆分。类型实参数量必须匹配声明，实例必须满足基础类型约束；借用限制仅在启用 Borrow 时检查。`ptr::<T, space>` 是第 18.3 节单独定义的内部函数语法，其地址空间实参不是用户类型参数。

### 10.2 实例化与约束

Core 在具体实例上进行类型替换、布局与代码生成。每个非泛型函数体均须类型检查，不因未调用而跳过。泛型体的依赖类型检查延迟到实例化；所有出现的具体类型以及所有已检查函数体内引用的具体函数实例均须检查，包括不可达调用。未使用的泛型不要求验证对所有类型都成立。`T: Copy` 要求实参具有第 7 章的结构 Copy 属性，不要求求解用户 trait。无约束 `T` 可以为 non-Copy 或资源类型；Core 不证明泛型函数在每条路径上消费参数。

Core 允许引用、切片和携带引用聚合作为用户泛型实参。借用扩展为保持局部分析而拒绝这些实例，见第 31.5 节；这不是基础语法限制。

### 10.3 实例化边界

直接或间接递归调用可以重用相同的具体泛型实例；当实例依赖路径上再次遇到同一泛型函数但类型实参不同，0.5 Core 编译失败。缓存复用时仍须检查已记录的实例依赖，不能因检查顺序或缓存状态改变接受结果。该限制防止展开为无限多实例，不禁止普通运行时递归。实例按“声明身份＋完整实参类型”缓存，避免重复生成。

布局检查必须接受类型实参引入的有限嵌套，不能仅因展开栈再次遇到同一名义声明而拒绝。采用以下声明依赖规则；别名先展开，数组包括零长度数组：

1. 为每个名义类型求出布局所需的类型参数集合。从空集合开始，反复检查按值成员直到集合不变。直接作为成员的参数需要布局；数组、元组沿元素／分量传播；`Option`、`Result`、`MaybeUninit`、`UnsafeCell`、`Atomic` 沿载荷传播，Atomic 的实例合法性和表示另按第 21 章与目标检查。对名义实例 `S<A...>`，仅沿 `S` 已确定需要布局的参数位置传播到对应实参。引用、原始指针、切片和函数指针的表示不依赖其目标或签名类型的布局。
2. 建立以名义类型声明为节点的有向图。检查声明的按值成员类型：遇到名义实例 `S<A...>` 时添加到 `S` 的边，并仅继续遍历其布局所需实参；数组、元组及上述存储／枚举包装器递归遍历；类型参数本身没有声明边，固定间接类型停止遍历。数组长度等布局常量中的 `sizeof`、`alignof`、`offsetof` 所需类型也参与前两步的布局依赖遍历，不因常量死分支而删除依赖。
3. 请求具体类型布局时，按同样规则取得其布局依赖节点；若任何可达节点处于有向环中，编译失败。否则按具体实参替换计算尺寸。实现可以使用等价算法，但必须得到相同接受结果。

例如 `struct Wrap<T> { value: T }` 的 `Wrap<Wrap<u32>>` 合法；`struct Bad<T> { next: Bad<(T, i32)> }` 请求布局时失败；`struct Node { next: *Node }` 合法。`struct Link<T> { p: *T }` 不需要 `T` 的布局，因此 `struct Tree { link: Link<Tree> }` 也合法。经固定间接类型仍检查名字、实参数量与约束，实际需要其目标布局时才另行请求；常量／布局依赖循环另按第 26 章拒绝。

### 10.4 扩展信息

Core 识别资源与引用相关类型标记，并为启用的扩展保留必要信息。所有权扩展把无约束 `T` 视为可能有消费义务；借用扩展限制可实例化类型。未启用这些扩展时，不执行对应证明或限制。

## 11. 表达式

### 11.1 字面量与路径

字面量、路径和 `null` 是表达式。`null` 只能按期待类型转换成原始指针。不得转换成引用或函数指针。

结构体、枚举和数组构造是表达式。数组逐项构造写作 `[e1, e2, ...]`，允许尾逗号，元素从左到右各求值一次且类型相同。空数组 `[]` 必须由期待类型确定元素类型。

数组重复构造写作 `[expression; N]`。`N` 是非负整数常量，长度及总布局必须可由 `usize` 表示；结果类型为 `[N]T`，元素表达式按期待元素类型推导且必须为 Copy。运行时先求值元素表达式一次，再复制该值形成各元素；即使 `N` 为零也求值一次，元素类型仍必须 Copy。元素表达式提前退出或 panic 时，不产生数组。常量上下文还要求元素表达式满足第 26 章。`[const expression; N]`、按元素执行构造函数和隐式复制 non-Copy 值均不属于 0.5 Core。

### 11.2 块、`if`、`match`、循环

块是表达式。块按顺序检查所有语句：只要存在结构上正常到达末尾的路径，结果由尾表达式（缺少则 `()`）决定；若之前的 `!` 表达式已终止全部正常路径，块为 `!`，后续不可达代码仍单独检查但不产生正常结果。因此 `fn f() -> i32 { return 1; }` 合法。不分析 defer 是否必然 panic 来改变块类型。`if` 的条件必须是 `bool`。`if` 作为表达式时，两个分支的类型必须相同；已启用的所有权扩展另行检查分支状态。缺少 `else` 的 `if` 表达式类型是 `()`，其 then 块须为 `()` 或 `!`。有 `else` 时，`!` 分支可按另一分支类型处理；所有分支均为 `!` 则结果为 `!`。

`match` 必须穷尽。范围模式 0.5 不定义。或模式 0.5 不定义。

`loop` 的类型由指向它的全部 `break` 操作数统一决定，裸 `break` 提供 `()`；没有指向它的 `break` 时类型为 `!`。为避免可达性求解，常量条件和不可达分支中的 `break` 也参与此类型计算。`while` 与 `for` 的类型始终是 `()`。

### 11.3 调用

函数调用先求值被调用表达式，再从左到右求值参数，然后进入被调用者。位置载荷构造和元组／数组构造同样从左到右求值。方法调用顺序是：

1. 求值接收者。
2. 建立接收者借用或移动。
3. 从左到右求其余参数。
4. 调用方法。

构造者只用于构造表达式，不可赋给函数指针；需要间接构造时写普通包装函数。具名普通函数在值位置形成具有其完整签名的函数指针；泛型函数必须由显式实参或期待函数签名唯一确定实例，否则拒绝。方法与关联函数须用类型路径形成这种值，不捕获接收者。外部函数的 effective unsafe 属性总为真。

效果语法见第 16 章，效果传播检查见第 32 章。外部函数调用必须在 unsafe 上下文中。

### 11.4 后缀 `?`

`expression?` 只适用于 `Result<T, E>`。`Ok(value)` 产生 `value`。`Err(error)` 执行正常错误返回。传播的错误类型必须与当前函数的错误类型完全相同。0.5 不执行隐式错误转换。

当前函数返回类型必须是 `Result<U, E>`，且 `E` 与被传播错误相同。`?` 不得出现在不能错误返回的上下文，包括 `const` 初始化器。

### 11.5 `return`、`break`、`continue`

`return` 的值类型必须等于函数返回类型。省略值等于 `return ()`。`break` 可以带值，仅用于 `loop`。`continue` 不带值。二者指向词法上最近的循环；在循环外使用编译失败。`while`、`for` 只接受裸 `break`。函数外使用 `return` 编译失败。

### 11.6 `panic`

```text
panic("message")
```

类型是 `!`。`panic`：

- 不进行异常展开；
- 不保证执行 `defer`；
- 不保证资源清理；
- 不能被 biomiya 代码捕获。

常量求值中的 `panic` 是编译失败。运行时 `panic` 的机器表现由 Architecture Supplement 规定，至少必须停止当前正常控制流。当前 RV64 配置采用不展开、不执行剩余 defer 的 panic 钩子。

### 11.7 转换

```text
expression as Type
checked_cast::<Type>(expression)
```

`as` 在整数类型之间执行位宽与符号转换，不检查溢出。设源整数的数学值为 `x`、目标位宽为 `N`，先取 `x` 模 `2^N` 的非负余数，再按目标的无符号或二元补码有符号表示解释该位模式。例如 `(-1_i8) as u16` 为 `65535_u16`，`255_u8 as i16` 为 `255_i16`。指针与整数之间的 `as` 不在 0.5 定义。指针与地址的转换使用 `addr` 和 `ptr`。

`checked_cast` 成功返回 `Some(value)`，数值不能表示时返回 `None`。它不制造 panic。

### 11.8 索引与字段

下标操作先求值基址，再求值索引；范围下标再按起点、终点顺序求值，每个表达式仅一次。

`place[index]` 要求整数索引，负值与越界值均 panic。`place[a..b]` 的两个端点必须显式给出且类型相同，负值或不满足 `0 <= a <= b <= len` 时 panic；切片不接受闭范围。取得可写数组位置或可变切片的范围时，可按期待类型产生 `[]T` 或 `[]const T`，缺少期待类型时产生 `[]T`；只读来源只能产生 `[]const T`。切片操作构造所选元素的视图；Core 不检查视图间重叠，第 31 章规定启用借用扩展后的根位置冲突规则。

`let` 禁止重新绑定自身，但通过所持有的 `&mut T` 或 `[]T` 修改目标不要求该引用或切片绑定为 `var`；对普通拥有数组的可变切片要求数组位置可写。字段访问 `place.field` 要求具名字段。私有字段只能在所属模块访问。

数组和切片的唯一内建字段是只读的 `.len: usize`，读取长度不移动容器。元组用 `.0`、`.1` 等无后缀十进制索引访问；索引必须存在且不带前导零（零本身除外），不支持动态元组索引。没有位置元组方法。

### 11.9 字段投影与方法选择

对字段、数字字段、下标和 `.len`，先自动解引用零个或多个 `&T`／`&mut T`，再对最终类型应用相应操作；不自动解引用原始指针。可写性沿链传播，经过普通 `&T` 后其普通目标只读。直接索引只接受数组和切片。对 non-Copy 字段的按值读取按第 7 章移动；读取字段并不先按值读取整个聚合。

方法调用先同样去掉引用层，再在最终名义类型的固有实现中按名字选择唯一方法，随后代入类型实参。没有候选就编译失败，不尝试其他类型、转换或重载。`&self` 借用最终位置，`&mut self` 要求最终位置可写并建立可变再借用；`self` 按值取得最终位置，仍受共享位置不能移出 non-Copy 的规则约束。对右值接收者先建立临时拥有位置，仅为这次方法调用允许按签名借用该临时；其存储期仍为所属完整表达式。

切片与存储包装器先按第 9.3 节和附录 D 的封闭内建成员表选择方法，随后使用相同的接收者规则；这不开放用户为它们添加实现。切片成员只用接收者调用语法，不提供 `[]T::method` 这样的源路径。

`Type::method(receiver, args)` 是显式调用形式，接收者作为第一个普通实参检查，不自动借用。无接收者函数只能用 `Type::function(args)` 调用。`value.method` 不形成绑定方法值；必须紧接实参列表。类型参数替换后也按这些规则查找，没有 trait 方法解析。

## 12. 运算符

### 12.1 优先级与结合性

从高到低：

```text
后缀        调用 ()    索引 []    字段 .    后缀 ?
一元        !  ~  -  &  *
转换        as Type
乘除        *  /  %  *%  *?
加减        +  -  +%  -%  +?  -?
移位        <<  >>
按位与      &
按位异或    ^
按位或      |
比较        <  <=  >  >=
相等        ==  !=
逻辑与      &&
逻辑或      ||
范围        ..  ..=
赋值        = 以及复合赋值
```

普通二元运算符左结合。赋值右结合。`x & MASK != 0` 解析为 `(x & MASK) != 0`。

`as` 左结合，优先级低于一元、高于乘除，因此 `-x as i64` 是 `(-x) as i64`，`x as u64 * y` 是 `(x as u64) * y`。对转换结果使用后缀运算时必须加括号，例如 `(x as u32).method()`。赋值的结果是 `()`，右结合不意味着 `a = b = 1` 能把整数同时写入两个变量。

### 12.2 算术

所有算术与整数位运算要求同类型整数操作数；没有混合有符号／无符号提升。默认 `+`、`-`、`*` 在溢出时 `panic`。`/` 与 `%` 在除零，或有符号 `MIN / -1`、`MIN % -1` 时 `panic`。

整数除法向零截断。余数满足 `a = (a / b) * b + a % b` 的数学恒等式；非零余数与被除数同号。例如 `-7_i32 / 3_i32` 为 `-2_i32`，`-7_i32 % 3_i32` 为 `-1_i32`。

包装形式不 panic，按二元补码截断：

```text
+%  -%  *%
```

检查形式返回 `Option`：

```text
a +? b    // Option<同一整数类型>
a -? b
a *? b
```

不能表示时为 `None`。0.5 不定义 `/?` 或 `%?`。

移位计数必须与左操作数同类型，或是无后缀且可放入该类型的字面量。计数为负或大于等于位宽时 `panic`。

合法计数下，左移丢弃移出的高位并在低位补零，不额外检查数值溢出；无符号右移补零，有符号右移复制符号位。移位结果与左操作数同类型。

### 12.3 比较与逻辑

`< <= > >=` 只接受同类型整数。`== !=` 接受同类型整数、`bool`、`()`、同类型原始指针／函数指针／引用，以及元素可相等比较的数组、元组和带 `@copy` 的结构体／枚举。数组与元组无需额外 `@copy` 标记；切片和三个存储包装器、Atomic 不支持相等比较。比较只读操作数，不移动 non-Copy 引用或聚合。聚合按字段／元素递归比较，不比较填充字节；枚举先比标签，相同才比有效载荷。指针和引用比地址，结果不证明对象身份或访问权。所有比较结果为 `bool`，没有用户相等接口。

`&&` 与 `||` 短路。两侧类型都必须是 `bool`。不求值的右部仍做基础类型检查，但不产生运行时移动。资源、借用与效果检查仅由已启用扩展执行。

### 12.4 一元运算符

`!` 只用于 `bool`。`~` 用于整数，按位取反。一元 `-` 只接受有符号整数，溢出时 `panic`，但第 2.5 节的 `MIN` 字面量例外。`&` 和 `&mut` 构造借用。`*` 是解引用。

引用的 `*` 不要求 unsafe 块，但实际访问仍必须满足执行合同。对 `&mut T`，`*` 形成可写位置。对原始指针，`*` 必须位于 unsafe 上下文。

### 12.5 范围

范围只允许直接作为 `for` 输入或下标中的切片范围；不是可存储的第一类值。`a..b` 是半开范围。`a..=b` 是闭范围。两端必须是同类型整数。`for` 接受这两种范围。闭范围若 `b` 为该类型 `MAX` 且实现不能表示结束后的状态，必须仍然只迭代合法值，不得溢出。

### 12.6 复合赋值

0.5 的完整集合为：

```text
+=  -=  *=  /=  %=
&=  |=  ^=  <<=  >>=
+%=  -%=  *%=
```

这些序列按最长匹配识别为单个记号。没有检查算术的 `+?=` 等复合形式，也没有逻辑复合赋值。两端必须为同一整数类型，无后缀字面量可以按期待类型确定类型。目标必须是已初始化的可写整数位置。

对 `place op= rhs`，先求值 `rhs`，再求值 `place` 的基址和索引各一次，然后读取目标的当前值、执行对应的二元运算、写回结果，最终产生 `()`。运算的 panic 和包装行为与对应普通运算一致；原始位置的读写仍要求 unsafe 合同。不能简单展开成重复求值 `place` 的源码。

右部提前离开时不求值左部。右部求值的副作用可以改变目标，读取的是右部完成后的值；运算 panic 时不执行最终写回，但已经完成的副作用不回滚。

## 13. 模式

### 13.1 文法

```text
pattern = _
        | identifier
        | literal
        | path
        | path ( pattern )
        | path { field_pattern_list }
        | ( pattern_list )
```

`_` 丢弃值。绑定默认不可变。0.5 不定义 `mut` 模式前缀。需要可变绑定时，在臂内使用 `var`，或匹配 `&mut` 位置。

### 13.2 穷尽与所有权

枚举匹配必须覆盖全部变体。Copy 被检值不被消费。拥有的 non-Copy 被检值整体移入匹配。载荷按所有权进入对应臂。

按值 `_` 求值并丢弃被匹配值，不执行隐式释放。Core 允许 `Some(_)` 和 `let _ = value`；资源载荷未消费的验证由第 30 章处理。

```text
match &value {
    Variant(payload) => { /* payload: &载荷 */ }
}
match &mut value {
    Variant(payload) => { /* payload: &mut 载荷 */ }
}
```

借用匹配不移动底层载荷。

### 13.3 模式解析、绑定与覆盖

模式不调用用户代码。只允许整数（含负有符号字面量）、布尔字面量、绑定、`_`、元组、结构体／newtype 和枚举构造模式；没有字符串、null、数组、引用前缀或任意常量表达式模式。单个名字若解析为期待枚举的无载荷变体，则为变体模式，否则为新绑定；用其他名字绑定即可消除冲突。带 `::` 的路径或带载荷的构造必须解析为相应构造者，不能作为绑定。模式里的整数必须能由被检类型表示。

字段模式一律写 `field: pattern`，必须列出每个字段一次，不支持简写、`..` 或私有字段绕过。单个模式中的绑定名不得重复；各 match 臂分别拥有作用域。`let`／`var` 的模式必须不可反驳：绑定、`_`、分量均不可反驳的元组／结构体／newtype，或唯一变体且载荷不可反驳的枚举模式。字面量模式不用于局部绑定。

`match` 自上而下选择首个匹配臂，各臂表达式按第 6.12 节统一结果类型。借用匹配最多自动去掉被检类型最外一层引用，并把该层下的载荷绑定转换为对应共享／可变引用；嵌套构造模式沿同一模式树传播这种借用方式。若被检类型本身是聚合，且它的某字段恰好是引用，则该字段的绑定保持普通字段类型，不额外解引用。`_` 在借用匹配中不读取／移出载荷。

覆盖检查以模式矩阵的构造分解进行：枚举按每个变体分支、bool 按 true／false 分支、元组和结构体按唯一构造的分量分解；绑定与 `_` 覆盖当前列的全部值。整数列除逐个已出现字面量外，总保留“其他整数”分支，该分支必须由绑定或 `_` 覆盖，即使显式列出了窄整数的所有值。其他不能分解的类型也只由绑定／`_` 覆盖。对每个构造保留匹配该构造或通配的行、展开载荷列，递归直到无列；无列且有行表示已覆盖，否则有缺口。递归类型通过其引用／指针边界停止分解。该算法是本版必需的保守覆盖标准。

因此 `Some(0), None` 不穷尽 `Option<i32>`；`Some(true), Some(false), None` 穷尽 `Option<bool>`。冗余臂允许并仍检查类型，可以警告；无模式守卫，不要求判定任意表达式条件。

## 14. 语句与循环

### 14.1 `for`

```text
for i in 0..count { ... }
for i in 0..=last { ... }
```

循环绑定是单个标识符或 `_`，不是任意模式。范围端点从左到右各求值一次；半开范围在起点大于等于终点时为空，闭范围在起点大于终点时为空，按整数值升序逐一遍历，循环变量为端点类型。

对 `[]const T`，循环变量是 `&T`。对 `[]T`，循环变量是 `&mut T`。切片 `for` 是借用遍历，不移动元素，也不移动原视图绑定；开始时求值输入一次，快照其地址和长度，逐个建立元素引用。只读遍历不允许修改目标。数组普通遍历须显式取得切片，例如 `for item in array[0..array.len]`。循环绑定不可重新赋值；`&mut` 绑定仍允许修改目标。每次循环体都是新词法作用域；`continue` 先退出该体并执行其 defer，再前进。

### 14.2 `for move`

```text
for move item in array { ... }
```

只用于 `[N]T`，从下标 0 开始递增，每个元素恰好一次；长度为零不执行循环体。输入求值一次，每次迭代得到不可重新赋值的拥有绑定 `T`。数组 non-Copy 时，数组移入遍历。数组 Copy 时按复制取得循环输入。

Core 允许 `break`、`return`、`?` 和 `continue` 按普通控制流转移。提前离开时，遍历持有的剩余元素存储结束，不运行隐式释放。资源数组的完整消费要求由第 30.3 节验证；panic 的不展开行为不变。

## 15. `defer` 与作用域退出

### 15.1 注册

```text
defer call ;
defer block
```

`defer call;` 的主体必须是调用表达式；`defer { ... }` 的主体必须为 `()` 或 `!`，内部可以有自己的 defer。调用形式丢弃返回值，资源返回值由 Ownership 另行检查。注册当前作用域正常退出时执行的动作。多个 `defer` 按 LIFO 执行。注册点完成类型和名字检查。普通值在执行 defer 时求值。

```text
var value = 1;
defer report(value);
value = 2;
// 退出时 report(2)
```

### 15.2 名字绑定与退出路径

注册时解析 defer 体的名字并检查基础类型，实际执行时才读取捕获位置的当前值。defer 不隐式复制或移动被引用的局部值。作用域正常结束、`return`、`?`、`break` 和 `continue` 都执行其退出的作用域中已注册的 defer；尚未执行到注册点的 defer 不执行。

Core 生成这些控制流与存储访问，不证明退出时读取的位置是否仍已初始化或资源是否已消费。对应检查见第 30.4、31.6 节。

### 15.3 顺序

`return expression`：

1. 求值表达式。
2. 保存返回值。
3. 从内到外对每个退出的作用域执行第 15.4 节的处理，其中包含 defer。
4. 返回保存值。

`?` 得到 `Err` 时：

1. 保存错误。
2. 从内到外对每个退出的作用域执行第 15.4 节的处理，其中包含 defer。
3. 返回错误。

defer 体不得通过 `return`、`?`、`break` 或 `continue` 发起越出 defer 上下文的正常非局部转移。defer 中 panic 后，剩余 defer 不保证执行。

### 15.4 正常退出阶段

1. 先求值并保存待返回值、错误或 `break` 值。
2. 从内到外处理所有要退出的作用域。
3. 对每个作用域，按 LIFO 执行其已注册的 defer，然后结束剩余局部存储。
4. 完成原控制转移。

Core 不生成隐式析构、资源证明或借用结束的运行时代码。返回引用不阻止局部存储结束；之后的实际访问必须满足第 9 章的存储合同。借用验证器可以在静态分析中结束不再需要的借用，但不得改变上述存储与 defer 执行顺序。

## 16. 效果声明语法

```text
fn wait() effects { may_block } { ... }
fn() -> () effects { may_block }
```

Core 识别空效果集和 `may_block`，保存函数及函数指针的效果标记；未知或重复效果编译失败。效果不改变参数布局、调用约定或运行时表示。没有子句等于声明空效果集，不表示已经证明函数不会阻塞。

Core 的调用与函数指针兼容性只检查基础参数、结果、ABI 和 unsafe 调用要求，不检查效果子集或传播阻塞效果。效果标记在转换、声明和模块接口中必须保留供扩展读取，不能据此声称 Core 执行了阻塞验证。第 32 章定义启用 Blocking 扩展时的调用、转换与内核上下文限制。

## 17. Unsafe 与执行合同

### 17.1 语法授权

```text
unsafe { ... }
unsafe fn name(...) -> Type { ... }
```

Core 要求原始解引用、原始引用构造、FFI 调用、汇编及其他明确标记的 unsafe 操作位于 unsafe 块中。unsafe 函数声明调用者承担额外合同，函数体不自动成为 unsafe 块。普通调用 unsafe 函数也必须在 unsafe 块中。Core 检查这种词法授权，但不证明合同成立。

unsafe 不关闭基础类型、可写性、地址空间和 ABI 检查，也不豁免已启用扩展的检查。未启用扩展时，没有 unsafe 标记不构成内存安全或资源正确性的证明。

### 17.2 执行合同违反

所有实际内存访问都要求目标存储存活、具有相应权限、正确对齐、读取时已初始化且表示合法，并满足原子和同步规则。实际访问已结束的对象、读取已移动而未重新初始化的值、发生数据竞争或违反其他明确机器前置条件时，从该操作起超出规定语义，无论源代码是否位于 unsafe 块中。

形成或保存一个后来失效的地址、资源未消费或没有通过某项扩展分析本身不等于已经发生上述访问。边界检查失败、普通算术溢出和除零仍按规定 panic，不能以未启用验证为由删除这些行为。

### 17.3 证明与优化

Core 不得仅因存在 `&mut`、`resource`、空效果集或未写 unsafe 就假定已经证明独占、资源不泄漏、不会阻塞或无数据竞争。它可以使用基础类型与执行合同允许的事实，但不能把可选扩展独有的限制当作所有 Core 程序的前提。

分析扩展只对声明的范围提供验证结果。依赖外部函数、原始存储或平台事实的结论必须列明假设；未经验证的模块不能仅凭类型名自动继承这些保证。

## 18. 原始指针与存储

### 18.1 解引用

对 `*kernel T`，`*ptr` 形成原始位置，可用于 Copy 读取、non-Copy 移出、写入和构造引用。这些操作需要 unsafe。

`T` Copy 时，`*ptr` 是复制读，存储保持已初始化。`T` non-Copy 时，`*ptr` 是移出，之后该存储对 `T` 未初始化。

复制读和移出共同要求：指针非空、满足 `alignof(T)`、完整对象范围属于存活且可读的普通内存、映射和访问权限有效、存储含已初始化且表示合法的 `T`，并且该访问遵守第 22 章的同步规则。Core 不另行证明借用关系。零大小对象仍要求非空、对齐和有效对象身份。设备内存访问使用第 23 章，不得以普通读取代替。

移出使目标逻辑上未初始化，不能因此复制 non-Copy 所有权。之后实际读取该目标前必须重新初始化；若后来发生无效读取，从该读取起违反合同，不把尚未执行的读取当成当前移出已经失败。启用所有权或借用扩展时，还必须满足其拥有与引用要求。复制读不产生新的 non-Copy 所有者，也不授予写入权。

`*const T` 可以复制读取 Copy 的 `T`，不得 non-Copy 移出、写入或构造 `&mut T`。

### 18.2 写入

原始写入在存储未初始化时初始化它。已初始化且 discardable 的值可以覆盖。资源类型的覆盖同样不隐式释放旧资源；其消费义务和 unsafe 抽象的不变量由调用者及已启用扩展负责。

写入要求可变的 `*kernel T`、非空与正确对齐的地址、存活且足够容纳完整 `T` 的可写普通存储，以及有效映射、写权限和写入权。写入的值必须是合法 `T`，其所有权随写入转移；操作不得违反同步或所处存储抽象的执行合同；借用限制由已启用扩展另行检查。未初始化目标不要求旧字节是合法 `T`。对实际只读存储写入仍违反合同，即使先经 `addr` 和 `ptr` 重建了可变指针。

`UnsafeCell` 的内部可变操作见第 21.2 节；它不提供同步。原始指针的存在本身不证明任何访问权限，扩展通过也不免除动态存储合同。

Core 不静态追踪任意原始存储的初始化状态。维持该事实属于 unsafe 合同。

### 18.3 地址运算

```text
addr(pointer) -> usize          // 安全，不访问内存
ptr::<T>(address)               // unsafe，默认 *kernel T
ptr::<T, space>(address)        // unsafe，显式地址空间
ptr_add(pointer, count)         // unsafe，增加 count * sizeof(T)
ptr_add_bytes(pointer, bytes)   // unsafe，字节偏移
```

`address`、`count` 和 `bytes` 的类型均为 `usize`；不接受负偏移。`T` 必须是有限大小的对象类型。`ptr::<T, space>` 的 `space` 必须是 `kernel`、`user`、`phys`、`mmio` 之一，省略时为 `kernel`；结果为该空间的可变原始指针。原始可变指针可以隐式弱化为同一指向类型、同一地址空间的 const 指针，反向或跨空间转换不得隐式发生。

`addr` 返回原始指针的地址数值，空指针返回零。`ptr` 把给定数值标记为指定空间的地址，零产生空指针。这两种转换不访问内存、不创建引用、不恢复已失去的所有权；允许构造未映射、未对齐或悬空的原始指针。`ptr` 构造需要 unsafe 上下文，但本身不要求映射存在，访问时再检查相应合同；`addr` 始终是安全操作。

`ptr_add` 与 `ptr_add_bytes` 保留指向类型、const 性和地址空间，只进行地址计算。其 unsafe 前置条件是乘法与加法的数学结果均可由 `usize` 表示；违反时超出规定语义，不按包装运算或 panic 处理。`sizeof(T) == 0` 时元素偏移为零。计算结果可以在对象范围外或是一过尾地址，但不因此获得访问权；实际访问必须重新满足完整对象范围、映射、对齐与同步合同。

0.5 没有独立的类型化指针强制转换。重新解释地址必须经 `addr` 再 `ptr`；字段地址可按第 18.4 节取得，也可使用 `addr(base)`、`offsetof` 和显式地址运算。数值往返不会使 const 存储可写，也不使另一地址空间的对象自动映射到当前空间。

### 18.4 原始取址

```text
addr_of(place) -> *kernel const T
addr_of_mut(place) -> *kernel T
```

两者是按声明身份识别的内部操作，实参按位置检查，不按值读取或移动 `T`，不构造中间引用；不能传右值，也不接受显式类型实参。`addr_of_mut` 要求位置可写。基址与索引按普通位置规则各求值一次，仍执行边界检查；字段可见性照常检查。局部或普通静态对象的取址无需 unsafe；原始指针位置、`static mut` 和全部外部静态对象仍要求 unsafe。`addr_of(*reference)` 提供从引用目标到原始指针的显式通道。

取址不读取被取址对象或投影路径上的聚合载荷，不要求该载荷已经初始化，不因 packed 字段实际未对齐而失败。`addr_of_mut((*p).field)` 可以用于初始化原始存储中的单个字段；只有 kernel 原始位置允许这种投影。为定位位置而实际读取的指针、引用、切片描述符或索引必须是合法已初始化值；地址计算不得溢出 `usize`，原始基址须指向足够的存活存储，外部边界符号的仅取址例外见第 5.7 节。取址不延长存储期，不修改移动状态，不授予未初始化读取、未对齐类型化访问或破坏同步的权利。

## 19. 从原始指针到引用

```text
let r = unsafe { &*ptr };      // &T
let r = unsafe { &mut *ptr };  // &mut T
```

构造引用的执行前置条件是非空、对齐、指向已初始化的合法 `T`，且地址空间允许普通引用；构造可写引用还要求可写存储。每次后续访问继续要求目标存活。Core 不证明整个引用存续期间的有效性或独占性，第 31 章另行检查。

只有 `*kernel` 可以构造普通引用。`*user`、`*phys`、`*mmio` 不得直接构造 `&T` 或 `&mut T`。

Core 返回由原始指针构造的引用时，按普通返回值处理。启用借用扩展后，返回来源仍受第 31.4 节约束；原始目标的有效期由 unsafe 实现的合同提供，不能仅靠写入来源标记制造证明。

## 20. 地址空间

| 空间 | 含义 | 普通解引用 |
| --- | --- | --- |
| `*kernel` | 内核虚拟地址 | 满足 unsafe 合同时可以 |
| `*user` | 用户虚拟地址 | 不得。使用 `copy_from_user` 等平台接口 |

## 21. `MaybeUninit`、`UnsafeCell` 与原子

### 21.1 `MaybeUninit<T>`

`MaybeUninit::uninit()` 创建未初始化存储，可用于常量表达式。该类型 non-Copy，Core 不按载荷类型施加借用限制；相关限制见第 31.5 节。

`write(&mut self, value: T) -> ()` 初始化或覆盖载荷，不释放旧载荷；Core 不要求 unsafe 块。所有权扩展禁止对资源载荷使用该安全写入接口，见第 30.3 节。

`as_ptr(&self) -> *kernel const T` 与 `as_mut_ptr(&mut self) -> *kernel T` 返回载荷地址；取得地址本身安全，不读取载荷，也不创建 `T` 的引用。包装器移动或存储结束后，不得继续通过旧地址访问原载荷。通过可写指针可在 unsafe 中逐字段／逐元素初始化；`assume_init` 前必须完成整个合法 `T` 的初始化。原始写入资源仍需满足第 18 章与已启用扩展的合同。

```text
unsafe fn assume_init(self) -> T
```

消费整个 `MaybeUninit<T>`。调用后原槽位已移动。前置条件：存储含有合法且已初始化的 `T`，且调用者拥有该值。

### 21.2 `UnsafeCell<T>`

`get(&self) -> *T` 返回可变原始指针，取得指针本身安全，访问需要 unsafe。若 `T` resource-bearing，则 `UnsafeCell<T>` resource-bearing。

`UnsafeCell::new(value: T)` 按值接收合法的 `T` 并创建已初始化载荷。可以通过 `get` 的原始指针访问其载荷；实际访问仍要求 unsafe 并遵守存储和同步合同。Core 不据外围只读引用推断载荷不可变。

`UnsafeCell` 的共享冻结例外、载荷引用的独占要求以及泛型借用限制均由第 31 章验证。Core 的实际载荷读取仍要求初始化且表示合法；需要未初始化存储时使用 `MaybeUninit`。

`UnsafeCell` 不提供原子性、锁、线程安全或无竞争。

### 21.3 原子类型

0.5 Core 支持以下实例：

```text
Atomic<u8> Atomic<u16> Atomic<u32> Atomic<u64> Atomic<usize>
Atomic<*T> Atomic<*const T>
```

此处指针实例为默认 kernel 地址空间。其他整数、地址空间、聚合或借用类型不属于 Core 原子实例集合，Core 模式下编译失败；目标扩展按第 1.3 节处理。

`Atomic<T>` 永远 non-Copy。目标可以用多条机器指令实现原子语义，不要求单条 ISA 指令。

对已初始化原子对象的载荷访问必须使用原子 API，不得用普通加载或存储绕过该 API。

整数原子操作：`load`、`store`、`exchange`、`compare_exchange`、`fetch_add`、`fetch_sub`、`fetch_and`、`fetch_or`。指针原子只支持前四个。

`Atomic::new(value: T)` 创建初值为 `value` 的原子对象。上述操作均通过共享接收者访问原子载荷，不要求 `&mut self`，其内部可变性仅适用于原子 API，不扩展到外围字段。`load(order)` 返回 `T`；`store(value, order)` 返回 `()`；`exchange(value, order)` 与所有 `fetch_*(value, order)` 返回修改前的 `T`。整数 `fetch_add` 与 `fetch_sub` 按位宽包装，不因溢出 panic。`compare_exchange` 的参数顺序为期待值、新值、成功顺序、失败顺序。

## 22. 原子内存模型

本章的抽象规则是实现必须满足的下限；允许实现提供更强顺序。原子顺序的规范性基线固定为 C++20 草案 N4861 的 [intro.races 第 4—6、10—20 段](https://timsong-cpp.github.io/cppwp/n4861/intro.races) 与 [atomics.order 第 1—10 段](https://timsong-cpp.github.io/cppwp/n4861/atomics.order)，仅使用无 consume、无原子 fence 的部分；不随草案后续修订变化。该引用只定义操作间的内存顺序关系，不引入 C++ 的类型、对象生存期、别名、表达式求值顺序、线程 API 或 signal 规则。对象表示与有效期按本手册，执行上下文按第 22.1 节。

本语言的 sequenced-before（sb）由规定的实际求值顺序产生。每个原子对象具有包含其初始化的修改全序（mo）；每次读取都关联到确切的一次写入（reads-from），不能仅按数值相等认定观察到了某次 Release。以 Release 或更强写入为首、其后连续 RMW 构成 release sequence；Acquire 从该序列取值时建立 synchronizes-with（sw）。happens-before（hb）为 sb 与 sw 的传递闭包，必须无环。初始值发布仍需满足普通存储合同。

同一对象的原子操作必须满足以下读值约束，RMW 同时具有读和修改两部分：

| 已有关系 | 必需约束 |
| --- | --- |
| 写入 A hb 写入 B | A 在 mo 中早于 B |
| 读取 A hb 读取 B，且 A 从 X 取值 | B 从 X 或 mo 中更晚的写入取值 |
| 读取 A hb 写入 B | A 所观察的写入在 mo 中早于 B |
| 写入 X hb 读取 B | B 从 X 或 mo 中更晚的写入取值 |

读取不得从 hb 上位于自己之后的写入取值。RMW 的读取必须来自其修改在 mo 中的紧邻前驱；失败 CAS 仅为读取，不进入修改序。不得通过循环依赖凭空制造值，包括 N4861 所列的 out-of-thin-air 情形；本语言将该禁止作为要求。上述限制也适用于 Relaxed。

所有 SeqCst 操作另具有一个全序 S。S 必须同时满足上述基线的 strongly-happens-before 与 coherence-ordered-before 约束（不含 fence 条目）；不能任意排列。其直接后果是：同一上下文的 SeqCst 操作保持 sb 顺序；同一对象的 SeqCst 修改保持 mo 顺序；全部原子操作均为 SeqCst 时，读取观察 S 中此前最后的该对象修改或初始化。混用弱顺序时使用基线的完整规则，不把 S 简化成涵盖所有 hb 的全序。后端可统一生成更强顺序，但不能把请求提升误写成源语言已经禁止所有弱顺序结果。

| 顺序 | 保证 |
| --- | --- |
| Relaxed | 原子性与修改序 |
| Release | 此前的 sequenced-before 操作可经匹配 Acquire 对另一执行上下文可见 |
| Acquire | Release 之前的操作 happens-before Acquire 之后的操作 |
| AcqRel | 同时具有 Acquire 与 Release |
| SeqCst | 相应 Acquire 或 Release，并参加单一顺序一致序 |

加载允许 Relaxed、Acquire、SeqCst。存储允许 Relaxed、Release、SeqCst。读改写允许 Relaxed、Acquire、Release、AcqRel、SeqCst。

`compare_exchange` 成功返回 `Ok(previous)`，失败返回 `Err(observed)`。失败顺序矩阵：

| 成功 | 允许的失败顺序 |
| --- | --- |
| Relaxed | Relaxed |
| Acquire | Relaxed、Acquire |
| Release | Relaxed |
| AcqRel | Relaxed、Acquire |
| SeqCst | Relaxed、Acquire、SeqCst |

其他组合编译失败。

顺序类型为 `core::MemoryOrder`，是带 `@copy` 的无载荷枚举，按 Relaxed、Acquire、Release、AcqRel、SeqCst 的顺序声明；五个变体均预导入。顺序参数必须是编译期已知的顺序值，不能通过运行时值绕过静态合法性检查。`compare_exchange` 比较当前值与期待值，相等则执行替换；它不允许伪失败。指针比较按同类型指针的地址数值进行，不解引用目标。

0.5 不定义独立的 `atomic_fence` 或 `compiler_fence`。第 23 章的设备栅栏不替代原子同步。

未正确同步的冲突普通内存访问构成第 22.1 节的数据竞争时违反执行合同。Core 不静态证明无竞争；没有 unsafe 语法不能作为无竞争的证据。

### 22.1 执行上下文与同步合同

执行上下文包括不同 hart 上的执行流，以及可以重入被中断代码的 IRQ 或陷阱处理。对同一存储的两个访问至少有一个写入，且至少一个不是原子访问时，是冲突访问；来自不同上下文的冲突访问若没有 happens-before 顺序或平台保证的互斥，就构成数据竞争。单个 hart 上允许抢占不自动提供互斥。

Core 不提供线程创建或 `Send` / `Sync` 标记。平台建立执行上下文，实际共享存储必须满足存储期、访问权限和同步合同。静态存储只保证存储期；`UnsafeCell` 不提供同步；原子指针不保证其指向载荷可安全共享。第 33 章的并发扩展检查这些协议，Core 不要求完成这种证明。

## 23. Volatile 与 MMIO

支持的标量是全部整数类型。不支持聚合或 resource。

```text
volatile_load(ptr: *kernel const T) -> T
volatile_store(ptr: *kernel T, value: T)
mmio_load(ptr: *mmio const T) -> T
mmio_store(ptr: *mmio T, value: T)
```

这些函数是 unsafe。它们只保证对应机器访问实际发生。不保证原子性、CPU 同步、设备顺序或指针有效。设备顺序使用 `arch::device_read_fence` 与 `arch::device_write_fence`，它们不是原子顺序。

调用者必须保证地址非空，所需宽度的完整访问范围已映射，地址、宽度及对齐满足目标访问要求，且具备相应读写权限。kernel volatile 访问还必须满足第 18 章的初始化与同步合同。MMIO 访问必须满足设备寄存器的读写方向、允许宽度、状态与访问顺序合同；它不要求设备寄存器具有普通 RAM 对象的初始化或生命周期模型。两者都不得以非原子访问绕过原子对象的访问协议。借用保护由已启用扩展另行检查。

## 24. 布局

```text
sizeof(T) -> usize
alignof(T) -> usize
offsetof(T, field) -> usize
```

三者可用于常量表达式。

普通聚合布局实现定义，在当前程序内一致，不构成稳定外部 ABI。

`@repr(C)` 结构体与 newtype 使用目标 C 结构体布局，字段顺序按声明顺序；newtype 不获得透明标量 ABI。`@align(N)` 指定对象或类型的最小对齐，`N` 必须是正的 2 的幂常量；实际对齐为自然对齐与 `N` 的较大者。静态对象上的 `@align` 只提高该对象的对齐，不改变其类型的 `alignof`。超出目标支持的对齐编译失败。

`@packed` 使结构体字段按声明顺序、以 1 字节字段对齐连续布置，类型对齐为 1，不插入字段间或尾部填充；字段类型自身的 `sizeof` 不改变。与同一类型上的 `@align` 冲突。packed 字段的合法按值读取和写入由实现生成支持未对齐访问的代码；这不允许构造实际地址未对齐的引用。第 18 章的原始类型化解引用仍要求对齐。

`@repr(C)` 与类型上的 `@align` 或 `@packed` 同用时，Architecture Supplement 必须明确对应的目标 C 布局扩展和调用约定；没有规定的组合编译失败。枚举的标签和布局在 Core 中实现定义，0.5 不支持 `@repr(C)` 枚举。布局属性不使原本含资源或借用的类型变成 ABI 兼容类型。

## 25. ABI 与链接

### 25.1 C ABI 兼容类型

0.5 的 C ABI 参数与按值返回类型采用以下闭合集合；别名先透明展开，泛型类型先实例化，再检查成员。

| 类型 | 条件与对应关系 |
| --- | --- |
| 所有整数类型 | 对应目标同位宽、同符号整数；`usize` / `isize` 对应目标地址宽度整数 |
| `bool` | 对应目标 C `_Bool`，输入必须表示合法布尔值，不接受任意整数位模式 |
| `*kernel T`、`*kernel const T` | 对应目标对象指针表示；`T` 必须有限 Sized，但不要求其内部布局适合 C 按值访问，可作为不透明对象 |
| C ABI 函数指针 | 参数与结果递归满足本节；指针非空，实际函数的调用约定和 unsafe 合同必须匹配；效果验证属于第 32 章 |
| `@repr(C)` 结构体与 newtype | 非空、非零大小、非 resource-bearing、非 borrow-carrying；所有字段递归满足本节的字段条件 |

结构体字段可以是上述类型，或正长度、元素递归满足字段条件的定长数组。数组自身不得直接作为 C ABI 参数或返回值；应使用对象指针和长度，或显式结构体包装。布局属性的目标兼容性还须通过第 24 章检查。

`()` 仅在函数返回位置表示 C `void`，不能作为参数或字段；`!` 不在 C ABI 返回类型集合中。元组、枚举（包括 `Option` 与 `Result`）、引用、切片、非 kernel 地址空间指针、普通 biomiya 函数指针、`MaybeUninit`、`UnsafeCell`、`Atomic` 和未标记 `@repr(C)` 的聚合均不得按值通过 C ABI。通过原始对象指针传递其地址不等于允许 C 直接访问它们的表示。

Architecture Supplement 必须为上述集合规定整数与指针表示、字节序、对齐、结构体传参与返回约定，以及支持的布局属性组合。缺少所需目标定义时不得声称支持该 ABI。0.5 不定义 C 可变参数、隐式整数提升或按值 C union。

### 25.2 函数、导出与外部合同

`extern abi(C)` 使用目标 C 调用约定。`@export("symbol")` 指定外部符号名。`@section(".text.boot")` 可用于函数或静态对象。

`@export` 只指定符号，不改变调用约定。要定义可由 C 调用的函数，必须同时使用 `extern abi(C)`；特殊陷阱入口使用 Architecture Supplement 的 ABI。无函数体的外部声明以声明名作为链接符号名，0.5 不提供额外的导入符号别名属性。

外部调用的 unsafe 合同包括：链接目标与声明的 ABI、参数和返回类型一致；输入满足目标函数的存储与别名要求；外部实现保持转移给它的 non-Copy 所有权义务，返回值必须具有合法表示。阻塞效果的声明与传播由第 32 章验证。外部代码不得穿过 biomiya 栈帧展开异常或执行未规定的非局部跳转。外部代码调用 biomiya 回调时，也必须满足回调的有效期、重入和同步合同。

```text
@export("increment")
extern abi(C) fn increment(value: u32) -> u32 {
    return value +% 1;
}
```

### 25.3 静态对象与链接一致性

```text
@section(".bss.page_table")
@align(4096)
static mut ROOT: MaybeUninit<PageTable> = MaybeUninit::uninit();
```

Core 要求同一程序内一个导出名字至多有一个定义。同一外部符号的多个声明必须具有相同基础 ABI 和类型，否则编译失败；效果元数据的一致性由 Blocking 扩展检查。缺失定义、重复定义或可由声明与定义信息检查出的 ABI 不匹配，均不得作为成功程序接受；具体链接诊断形式由实现定义。外部二进制的真实合同无法从符号表证明时，仍由外部声明的 unsafe 合同承担。

外部静态声明还必须在可变性上保持一致，同一符号不能同时声明为函数和对象。外部声明不分配存储，也不产生初始化代码；对象或地址符号由外部对象／链接脚本提供。仅前端验收可不解析实际定义；生成可运行构建时所有实际引用的外部符号必须能解析。

## 26. 常量表达式

常量表达式可以包含：

- 整数、布尔和字符串字面量，`null`、先前或向前声明的常量、类型已确定的具名普通函数地址；
- 整数算术、位运算、比较、逻辑运算；
- 块中的不可反驳 `let`、`if` 与 `match`；
- 元组、结构体、枚举和数组构造，包括 Copy 元素重复构造；
- `as` 与 `checked_cast`；
- Copy 聚合的字段与下标读取、`.len`、对不可变静态对象的只读引用和静态数组切片；
- `addr_of` 对本编译单元定义的不可变静态对象及其字段／常量下标元素的取址，不读取初始化值；结果可以含链接重定位；
- `sizeof`、`alignof`、`offsetof`；
- `Atomic::new`、`UnsafeCell::new`、`MaybeUninit::uninit`；
- 特殊 `panic` 表达式，实际求值到时编译失败。

不得包含 `var`、赋值、`for`、`while`、`loop`、`defer`、普通函数调用、原始解引用、原始指针到引用、原子操作、`UnsafeCell` 修改、volatile、MMIO、FFI、汇编或 `static mut`／外部静态访问。除上述 `addr_of` 静态取址外，原始取址、原始切片构造及切片／包装器指针成员不用于常量表达式。0.5 没有 `const fn`。

```text
static_assert(sizeof(Pte) == 8);
```

条件必须是常量 `bool` 且为 `true`，否则编译失败。`static_assert` 可位于模块或块中，不产生运行代码。

常量表达式先检查全部分支的类型与允许操作，再只求值被选择的分支；死分支里的普通函数调用仍拒绝，死分支里的除零不发生求值。常量／布局／静态初始化依赖成环必须拒绝；仅取得静态地址不读取初始化值，因此不形成值依赖。常量上下文的块只允许 `let`、`static_assert` 和尾表达式。整数求值使用与运行时相同的位宽、溢出和包装规则。`sizeof`／`alignof` 的实参是类型，不是表达式；`offsetof(T, field)` 只接受一个结构体字段或元组数字字段，须满足可见性，不沿字段路径递归。

## 27. 内核上下文

Core 识别 `Normal`、`IRQ`、`TrapEntry` 和 `Trap`。

```text
import arch::TrapFrame;

@irq
fn timer_irq(frame: &mut TrapFrame) { ... }

@trap_entry
fn trap_entry(frame: &mut TrapFrame) -> ! { ... }

@trap
fn page_fault(frame: &mut TrapFrame) { ... }
```

普通函数调用不得进入这三类特殊上下文函数。特殊转移必须由本参考或 Architecture Supplement 规定。本版没有一般的“可达路径”证明：转移必须作为函数体、其尾部嵌套块或尾部 if／match 臂的最后表达式；允许 `return transfer(...)`，不允许 `let x = transfer(...)`、普通实参中的转移或带分号的转移表达式语句；`return transfer(...);` 作为 return 语句的特例合法。循环体和 defer 体中不得转移。每个分支结束在转移、panic 或其他 `!` 路径，不能正常返回。RV64 另定义同规则的 `arch::enter_irq_handler`。

标准路径：

```text
硬件陷阱
  -> 架构入口桩
  -> @trap_entry
  -> 上下文转移
  -> @trap 处理函数
  -> 陷阱返回
```

`@trap_entry` 不得用普通调用绕过入口 ABI 和上下文转移规则去调用 `@trap` 函数。转移内部函数的确定形式是（目标绑定与运行合同见 RV64 补充）：

```text
arch::enter_trap_handler(frame, named_handler) -> !
```

它不是普通调用。必须满足：

1. 只出现在 `@trap_entry`。
2. 位于当前路径的尾位置。
3. 每条正常可达路径至多一次。
4. 处理函数是编译期已知的具名 `@trap` 函数。
5. 不得使用运行时函数指针。
6. 结果类型是 `!`。
7. 处理函数满足目标规定的基础签名与入口 ABI。阻塞效果是否符合陷阱合同由第 32 章验证。

陷阱嵌套记账由架构运行时负责。正常陷阱返回撤销当前嵌套层。panic、停机和重启不保证执行普通嵌套展开。

内联汇编的文法、寄存器操作数、clobber、内存效果和控制流限制由 [RV64 补充](architecture-rv64.md) 的受限 `arch::asm` 定义。汇编是 unsafe 操作，即使位于 unsafe 函数中也必须写在 unsafe 块内。汇编的阻塞说明须保留供 Blocking 扩展检查；Core 负责执行目标定义的操作，不分析调用链是否可能阻塞。

## 28. 求值顺序

普通操作数和函数参数从左到右求值。短路运算符除外。普通赋值按第 8.3 节先求值右部，再求值左部位置；复合赋值按第 12.6 节使用同样的右部优先顺序。后缀 `?` 在其操作数完成求值后立即按第 15.3 节动作。

未规定：恐慌信息的文本是否保留源位置。实现应当保留。

# 第二部分：扩展特性（Extend）

## 29. 扩展特性总览（Extend）

### 29.1 定位

本章及后续章节介绍建立在 Core 上的正确性验证与程序分析。它们不构成每个 Core 实现都必须实现的前端、代码生成或运行时机制。扩展可以收紧所接受的程序，但不得重新解释 Core 的求值顺序、对象存储期、布局、调用约定或 panic 行为。

第 30—32 章给出当前分析配置的检查规则；第 33—34 章规定分析范围与接口，具体并发证明算法、平台协议及内核验证注解还需对应的补充规范。支持 Core 不意味着支持全部 Extend；通过某项扩展也不表示程序的任意正确性已获证明。

### 29.2 特性与依赖

以下名称用于识别分析配置，不增加源语言关键字。启用方式由工具文档规定，不在本版引入新的源文件配置语法。

| 特性 | 检查范围 | 依赖 |
| --- | --- | --- |
| Ownership | 移动后使用、控制流状态、资源消费、defer 的未来使用 | Core |
| Borrow | 共享与独占、区域、来源、返回与逃逸、切片分区 | Ownership |
| Blocking | `may_block` 调用传播、函数指针效果、IRQ 与陷阱限制 | Core |
| Concurrency | 共享、发布、同步、重入与跨上下文传值协议 | Ownership、Borrow；分析阻塞时另需 Blocking |
| Kernel Verification | 栈上界、递归、陷阱驻留、故障与分配可靠性 | 明确的目标与平台合同；按所声明检查启用相关分析 |

依赖必须一并启用并报告；缺失时拒绝该扩展配置，不能静默降低保证。除上述依赖外，Core 实现不必为了未来扩展提前执行其分析。

### 29.3 标记、结果与模块边界

Core 已定义的 `resource`、`@copy`、引用类型和 `effects { may_block }` 始终可解析并具有正式部分规定的基础含义。未启用相应验证时，报告必须标明未验证，不能把仅识别标记当作检查通过。

专用扩展属性如 `@stack_limit` 不属于 Core 属性；只有启用且支持其定义的补充规范才可接受，未知属性仍编译失败。专用标记的缺失不能被解释为已经完成验证。

验证结果至少区分：未启用、已验证满足、发现违反、无法证明。启用某项严格验证的构建只有在所要求性质已验证满足时才通过；违反与无法证明必须区别诊断。扩展验证失败不是 Core 编译失败。

各模块和依赖库的配置、验证范围及受信假设必须可追踪。经过验证的调用者不能把未经验证的被调用者自动视为满足同一分析；它必须分析可用实现、使用明确的受信接口合同，或报告无法证明。代码、目标、链接条件或假设改变后，旧验证结果不能直接复用。

### 29.4 与执行语义的关系

资源自然丢弃可被 Ownership 拒绝，但在 Core 中仍按无隐式析构结束存储。借用冲突可被 Borrow 保守拒绝，但单凭两个地址别名不改变 Core 的普通读写行为。Blocking 可以拒绝调用链，而未启用时 Core 仍执行普通调用。

未启用扩展不免除实际访问的存储、初始化、权限和同步合同。已验证的程序仍可能依赖 unsafe、外部代码或平台假设；这些条件必须与静态保证一并说明。分析使用的状态、来源集合和分区身份均为编译期信息，不要求增加对象头部或隐藏运行时分配。

### 29.5 配置差异示例

下表假定示例所需的名字和基础类型均已定义。它说明配置边界，不表示已经存在或运行了相应编译器测试。

| 情形 | 仅 Core | 启用相关扩展 |
| --- | --- | --- |
| `let _ = frame` 丢弃资源 | 可翻译，不隐式释放 | Ownership 验证失败 |
| 某分支移动值，随后可能读取该值 | 可翻译；实际读未初始化值违反合同 | Ownership 在不一致合并点拒绝 |
| 两个指向同一存储的可变引用，依次作合法访问 | Core 不以独占性为前提，按实际顺序访问 | Borrow 拒绝冲突借用 |
| 用户泛型实参为 `&Task` | 可实例化 | 当前 Borrow 配置保守拒绝 |
| 无效果声明函数调用 `may_block` 函数 | 普通调用 | Blocking 验证失败 |
| 原子 load 使用 Release | Core 编译失败 | 扩展不能使其合法 |
| 数组越界 | 按 Core 规定 panic | 通过扩展也不取消该行为 |

## 30. 所有权与资源扩展（Ownership）

### 30.1 移动与局部状态

启用 Ownership 时，non-Copy 拥有位置至少具有 Available 与 Moved 状态。使用 Moved 位置验证失败；重新初始化可写位置后恢复 Available。Copy 使用不改变状态。

本配置不支持字段级部分移动后继续使用聚合或其剩余字段；需要多个拥有字段时必须整体解构。从引用或切片不得直接移出 non-Copy 目标，应使用 `replace` 或拥有数组遍历。non-Copy 静态对象不得通过不含 unsafe 的操作移出。原始存储不要求通用静态初始化跟踪，其操作依赖明确的 unsafe 合同。

第 18.4 节的取址本身不消费或读取被取址值，不能仅因该值已移动而当作移动后读取拒绝；定位所需的基址值仍按普通使用检查。取得原始指针不恢复 Available 状态。经该指针读写、逐字段初始化和 `assume_init` 的正确性依赖明确的 unsafe 合同；验证器不得把仅仅完成取址当作已证明初始化。

### 30.2 分支与循环合并

| 正常到达合并点的状态 | 结果 |
| --- | --- |
| Available 与 Available | Available |
| Moved 与 Moved | Moved |
| Available 与 Moved | 验证失败 |

已经 return、panic 或进入不返回路径的分支不参与合并。循环外拥有位置在每条正常回边上必须恢复为入口状态；同一循环出口的所有正常到达路径也必须状态一致。短路表达式按其实际控制流分支检查，不能把未执行右部视为已消费资源。

### 30.3 资源消费

resource-bearing 的拥有值在正常路径上必须通过显式消费、移动给其他所有者、返回、整体解构并处理载荷，或 `unsafe forget` 结束义务。`Option`、`Result` 等载荷义务按实际变体处理，空变体可由穷尽匹配消费。

以下情况验证失败：

- 正常退出时遗留未消费资源；
- 用赋值覆盖已初始化的资源值；
- 用 `_`、`let _` 或表达式丢弃资源载荷；
- 无约束泛型函数直接丢弃可能为 resource-bearing 的参数；
- 对资源 `T` 使用 `MaybeUninit<T>::write`，使消费义务进入无静态追踪的存储。

`replace` 把旧值义务交给返回值；`swap` 交换已有义务。resource-bearing 静态对象是程序生命周期的所有者，不承担局部作用域退出义务。原始写入或其他 unsafe 抽象接收资源时，其受信合同必须说明消费去向；unsafe 语法本身不能豁免已知的拥有位置检查。

`for move` 遍历资源数组时，正常路径必须处理所有元素。尚有剩余元素时不得 `break`，不得通过 `return` 或 `?` 提前离开；`continue` 前必须处理当前元素。panic 路径不要求完成剩余消费，保持 Core 的不展开语义。

### 30.4 Defer 的未来使用

defer 使用某绑定时，每条将执行该 defer 的正常退出边都必须满足其使用要求。退出边包括作用域结束、`return`、`?`、`break` 与 `continue`。验证器按 Core 的真实 LIFO 顺序检查，而不能为使程序通过重新排序 defer。

```text
var frame = alloc_frame()?;
defer free_frame(frame);
free_frame(frame);
frame = alloc_frame()?; // Ownership 验证失败：Err 路径触发时 frame 已移动
```

此例在 Core 中可以翻译，但相应 Err 路径执行 defer 时会读取未初始化位置。合法的受检模式是先取得新资源，再消费旧值并完成重新初始化。

### 30.5 保证范围

通过本扩展表示受检代码在正常控制流中满足规定的移动与资源使用规则，并依赖已声明的 unsafe 与外部消费合同。它不证明释放函数实际正确、无内存别名、无数据竞争或机器地址有效；这些属于其他分析或运行合同。

## 31. 借用与逃逸扩展（Borrow）

### 31.1 共享、独占与根位置

本扩展依赖 Ownership。有效共享借用存在时，不得普通修改、移动或销毁目标，也不得创建冲突的可变借用。有效可变借用存在时，只能经它或合法再借用访问目标，不得从所有者或其他冲突别名访问。

冲突按根拥有位置保守判断，借用字段冻结整个根；数组不同下标不自动证明互不重叠。不同局部名字不代表不同目标。仅第 31.7 节的受认可拆分关系可以建立分区例外。

### 31.2 区域与来源

存入具名局部的借用持续到该绑定的词法退出阶段，不做一般 NLL 缩短。未保存的临时借用持续到包含它的完整表达式结束；嵌套调用结束不提前结束外层仍需保持的借用。再借用区域不得超过父借用，子借用有效时禁止经父可变引用作冲突访问。

携带引用的值包括引用、切片，以及递归按值包含它们的聚合。原始指针与函数指针不沿目标传播该属性。每个受检值携带来源集合；Copy 保留来源，移动转移来源。写入局部位置时，全部非静态源必须覆盖目标的剩余词法区域。若不能证明则验证失败。

方法接收者在其余实参之前建立借用，不使用两阶段借用。`buf.set(buf.len - 1, 0)` 在接收者需要可变借用且参数又访问同一根时验证失败，虽然 Core 能按规定顺序执行该表达式。

### 31.3 逃逸限制

带非静态源的携带引用值不得写入输入 `&mut` 或 `&mut self` 可达存储、静态对象、其他全局位置或不受检原始存储。返回值另按第 31.4 节检查。此限制是为了避免一般 lifetime 关系求解，不是 Core 对这些存储位置的语法限制。

unsafe 原始存储操作可以使用明确的受信合同管理引用有效期，验证报告必须保留该假设；不能仅因使用原始指针而宣称来源已证明有效。

原始取址、切片／MaybeUninit 指针成员均不产生新的共享或独占证明；通过结果指针的实际访问不得绕过仍有效的借用。`slice_from_raw_parts` 及其可变版本创建携带引用的结果，须按原始引用构造处理来源；原始指针参数本身不成为返回非静态借用的自动来源。受信抽象仍须符合第 31.4 节的接口限制。

### 31.4 返回来源

方法接收者为 `&self` 或 `&mut self` 时，非静态返回借用依附整个 self；不得依附另一个参数，也不支持来源投影到 self 的某个字段。按值 self 不提供默认源。

自由函数有一个顶层引用或切片输入时，非静态返回借用依附该输入；没有这种输入时只允许返回静态源；有多个输入且返回非静态借用时验证失败。返回聚合的多个借用组件可以依附同一输入，并混合静态源。按值携带借用的聚合不自动成为顶层输入源。

返回当前函数局部或临时存储的引用验证失败。原始指针构造的返回引用也必须符合来源接口；目标有效期由 unsafe 合同保证，来源规则本身不证明目标存储事实。

### 31.5 为保持分析简单而施加的限制

启用本配置后：

- 用户泛型类型与函数的类型实参不得为携带引用的类型，即使满足 `T: Copy`；原始指针仍可使用。
- `Option` 与 `Result` 是编译器识别的借用透明例外；元组、数组及具体非泛型结构体可按规定携带引用。
- `MaybeUninit<T>` 和 `UnsafeCell<T>` 的 `T` 不得携带引用。
- `replace` 与 `swap` 只接受不携带引用的 `T`，避免隐藏来源交换。
- 函数指针返回类型不得携带引用，避免间接调用的来源接口分析；具名函数可按第 31.4 节返回引用。

例如 `identity::<&Task>(&task)` 和 `fn(&Table) -> &Entry` 的函数指针类型在 Core 可表示，但在此扩展配置下验证失败。此处的保守拒绝不改变相同类型在 Core 中的布局或调用方式。

### 31.6 Defer 与内部可变性

在不改变第 15 章运行顺序的前提下，验证器可以在作用域退出时结束既未被转移出、又不被后续 defer 使用的借用。defer 使用的借用必须保持到该动作执行；返回值或错误携带的借用必须覆盖转移后的使用区域。真实 LIFO 顺序不能满足这些条件时验证失败。

共享借用的冻结规则对 `UnsafeCell` 和原子载荷保留内部可变性例外，不涉及外围字段。例外不削弱已存在载荷引用的共享或独占要求，也不允许冲突的可变引用。原子载荷仍只能通过原子 API 访问；`UnsafeCell` 不自动获得同步保证。

### 31.7 可变切片分区

`split_at_mut` 的运行操作由第 9.3 节实现。借用验证器为两个结果建立互不重叠的逻辑分区身份，并沿移动、聚合保存与再借用传递；对一段再次拆分形成子分区。零大小元素也按逻辑下标而非地址相等性判断分区。普通用户函数不能仅凭相同返回类型自行声明分区关系。

输入视图已移动；只要任一派生借用有效，原始所有者仍被冻结。每段内部继续遵守根位置冲突规则。在分支合并点，保守要求来源与分区关系一致，否则验证失败；循环回边恢复其入口的来源与分区关系。本扩展不要求证明任意动态区间互不重叠。

### 31.8 保证范围

通过本扩展表示受检代码满足指定的局部所有权与借用规则。结论依赖原始引用构造、外部代码和平台给出的受信合同，不包含栈、驻留、并发协议或业务逻辑的完整证明。Core 单独编译不能声称已得到这些保证。

## 32. 阻塞效果扩展（Blocking）

### 32.1 调用传播

本扩展读取 Core 的 `effects` 标记。无子句的函数声明空效果集。普通调用必须满足被调用者效果集是调用者效果集的子集；空效果函数调用 `may_block` 函数验证失败。

验证应覆盖所有可达普通调用，包括 defer 体、间接调用、外部函数及已声明可能阻塞的汇编。外部实现缺少可用合同、或间接调用目标不能满足所需效果时，不能报告无阻塞已证明。

### 32.2 函数指针与接口

无阻塞效果的函数可以赋给允许阻塞的函数指针，反向验证失败。多个外部声明对同一符号必须具有一致的效果合同，不能通过重新声明或转换抹去效果。Core 只保留相应元数据，本扩展负责这些检查。

### 32.3 内核上下文

`@irq` 和 `@trap_entry` 不得具有或经调用产生 `may_block`。`@trap` 的阻塞能力按 Architecture Supplement 的平台合同验证。第 27 章的特殊控制转移只改变规定的执行上下文，不允许把转移包装成普通函数指针绕过此检查。

通过 Blocking 只证明所声明范围的阻塞限制，不证明无分配、无缺页、无递归或栈有界。Core 的入口 ABI 与特殊转移语法无论是否启用此扩展都必须实现。

## 33. 并发协议分析扩展（Concurrency）

### 33.1 范围

本扩展在 Ownership 和 Borrow 的结果上，结合平台的 hart、抢占、中断、锁与调度合同，分析发布、共享、同步、重入和跨上下文传值。它不改变第 22 章的内存模型，也不把原子访问本身当成整个对象安全共享的证明。

要声称支持某个并发验证配置，补充规范必须给出所识别的平台操作及其合同、同步关系、回调范围和未覆盖行为。本参考不提供任意平台并发程序的完整验证算法，也不预先加入 `Send` / `Sync` 类型机制。

### 33.2 需要检查的性质

- non-Copy 值转移后，源上下文不再拥有它。
- 传递或共享的引用，其源存储覆盖所有目标使用。
- 对普通可变存储的冲突访问由规定的同步或互斥保护。
- IRQ、陷阱、回调和资源释放不会破坏所依赖的重入与拥有关系。
- 安全平台接口对其签名和已声明验证配置允许的所有使用维持这些合同；不能把未表达的调用者义务藏入受检接口。

无法获得同步协议或外部行为的证据时，必须报告无法证明或列出明确受信假设。Copy、静态存储期、原子指针和 unsafe 块都不能单独替代上述证明。数据竞争的运行后果仍由 Core 执行合同规定。

## 34. 内核验证扩展（Kernel Verification Supplement）

### 34.1 定位与合规范边界

Kernel Verification Supplement 是独立于 Core 类型系统的可选验证规范，用于检查内核代码在指定机器与运行时条件下的栈界限、递归限制、陷阱驻留和可靠性。Core 实现不必提供该验证器；仅符合 Core 不表示程序已通过这些检查。

Architecture Supplement 定义机器接口与执行合同；Kernel Verification Supplement 在这些合同以及平台提供的事实之上建立额外的验证义务。锁、调度器、内存驻留管理等仍由平台库实现。验证补充不得改变普通程序的求值、布局、ABI、所有权、借用或效果规则，也不得把基础语法或类型错误认定为合法 Core 程序。

本章规定验证补充与 Core 的接口边界，不定义一套已经完成的验证算法或注解语法。实现若声称支持某个验证补充，必须标明其名称、版本、目标架构、适用的平台合同和检查范围。

### 34.2 检查范围

验证补充可以定义下列检查；它必须说明每项检查使用的入口、假设和证明范围。

| 检查 | 验证目标 | 必须说明的边界 |
| --- | --- | --- |
| 栈界限 | 指定入口及其可达执行路径的最大栈需求不超过给定上限 | 调用链、间接调用、外部函数、汇编、架构入口桩、陷阱嵌套及所用代码生成配置 |
| 递归限制 | 指定调用范围内无直接或间接递归，或递归深度具有规定上界 | 调用图中的环、间接调用目标集合、重入与中断嵌套；仅排除递归不等于已证明栈上界 |
| 陷阱驻留 | 指定陷阱阶段依赖的代码、数据、栈和地址转换设施满足平台的驻留与可访问条件 | 依赖闭包、映射有效期、权限、页面驻留以及进入和退出该阶段的条件 |
| 可靠性 | 指定入口满足补充规范声明的额外限制，例如禁止分配、限制可触发的故障或约束依赖调用 | 分配器与故障模型、外部调用合同、允许的失败方式以及无法验证的机器行为 |

这些检查不得仅凭函数未声明 `may_block` 就判定通过。无阻塞效果不保证无分配、无缺页、栈使用有界、无递归或依赖驻留。Core 的 `@irq`、`@trap_entry` 和 `@trap` 也不自动授予上述保证。

### 34.3 验证注解与启用

`@stack_limit`、`@no_recursion` 和 `TrapResident` 是供验证补充定义的候选名称，不是 0.5 Core 的属性、类型或能力约束。本参考不规定其参数、适用位置或表示方式；特别是 `TrapResident` 不作为 Core 类型参与泛型、Copy 或资源分类。

支持验证补充的工具必须提供显式启用方式，并文档化该方式。启用后，由相应补充定义并识别验证注解；未启用或未识别的专用属性按第 5.8 节编译失败。未知类型名仍按名字解析规则处理。工具不得静默忽略验证注解后报告验证成功。

验证注解表达待检查的要求，不使要求自动成立。对外部函数、汇编、链接布局或平台状态使用的受信假设，必须与已证明的结论区分并记录。

### 34.4 验证结果与失败

验证补充必须区分已证明满足、已发现违反和无法证明。缺少间接调用目标、外部合同、机器信息或平台事实时，不得把无法证明当作已满足。

启用验证补充的构建可以把违反或无法证明作为构建失败，但诊断必须区分 Core 编译错误与附加验证未通过。附加验证未通过本身不使一份原本合法的 Core 程序成为 Core 非法程序，也不单独使其执行超出规定语义；Core 的存储与机器执行合同仍按第 17 章执行。

验证结果必须绑定到其依赖的程序、目标配置与假设。依赖发生变化后，不得继续把旧结论当作新配置的验证结果。若证明依赖平台维护的驻留、映射或嵌套上界，报告必须列出这些条件，供平台在运行时维持。

### 34.5 与 Core 效果和架构合同的关系

Core 只识别 `may_block` 标记，Blocking 扩展负责其传播检查。验证补充可以分析分配、故障、栈、递归和驻留，但不得据此向 Core 函数类型隐式添加 `may_alloc`、`may_fault`、`may_sleep` 或其他效果，也不得在启用了 Blocking 的配置中放宽其效果子集规则。

验证器可以检查第 27 章的陷阱入口和上下文转移是否满足更强的平台要求，但不得新增普通调用进入特殊上下文的通道。通过验证不免除 unsafe 操作的前置条件，也不替代 Architecture Supplement 对陷阱 ABI、寄存器保存、设备顺序与返回路径的规定。

## 附录 A. 完整 Core 语法

以下 EBNF 中，引号内为记号，`?`／`*`／`+` 是文法操作符，`|` 表示选择，`;` 结束产生式；`IDENT`、`INTEGER`、`STRING` 是第 2 章的词法记号。`INTEGER` 包含可选整数后缀，`DECIMAL_INDEX` 仅为无前导零的十进制数字串。语法能解析不表示类型、可见性、属性位置或执行合同必然合法。第 3.1 节的块尾与控制流头部规则负责消除相应歧义。

```ebnf
file = module_decl? import_decl* declaration* ;
module_decl = "module" path ";" ;
import_decl = "import" path ("::" "{" name_list "}")? ";" ;
name_list = IDENT ("," IDENT)* ","? ;
path = IDENT ("::" IDENT)* ;
declaration = attribute* "pub"? declaration_body ;
declaration_body = alias_decl | struct_decl | enum_decl | function_decl
                 | const_decl | static_decl | extern_static_decl | impl_decl | assertion ;
attribute = "@" IDENT ("(" argument_list? ")")? ;
alias_decl = "type" IDENT "=" type ";" ;
struct_decl = "resource"? "struct" IDENT generic_params?
              ("{" field_list? "}" | "(" type ")" ";") ;
field_list = field ("," field)* ","? ;
field = "pub"? IDENT ":" type ;
enum_decl = "enum" IDENT generic_params? "{" variant ("," variant)* ","? "}" ;
variant = IDENT ("(" type ")" | "{" field_list? "}")? ;
generic_params = "<" generic_param ("," generic_param)* ","? ">" ;
generic_param = IDENT (":" "Copy")? ;
generic_args = "<" type ("," type)* ","? ">" ;
function_decl = "unsafe"? extern_abi? "fn" IDENT generic_params?
                "(" parameters? ")" return_type? effects? (block | ";") ;
extern_abi = "extern" "abi" "(" "C" ")" ;
parameters = receiver ("," parameter)* ","? | parameter ("," parameter)* ","? ;
receiver = "self" | "&" "self" | "&" "mut" "self" ;
parameter = IDENT ":" type ;
return_type = "->" type ;
effects = "effects" "{" ("may_block" ","?)? "}" ;
impl_decl = "impl" generic_params? type "{" method_decl* "}" ;
method_decl = attribute* "pub"? function_decl ;
const_decl = "const" IDENT ":" type "=" expression ";" ;
static_decl = "static" "mut"? IDENT ":" type "=" expression ";" ;
extern_static_decl = extern_abi "static" "mut"? IDENT ":" type ";" ;
assertion = "static_assert" "(" expression ")" ";" ;

type = type_path | "&" "mut"? type | "*" address_space? "const"? type
     | "[" expression "]" type | "[" "]" "const"? type
     | "(" ")" | "(" type ")" | "(" type "," type ("," type)* ","? ")"
     | function_type | "!" ;
type_path = type_segment ("::" type_segment)* ;
type_segment = IDENT generic_args? ;
address_space = "kernel" | "user" | "phys" | "mmio" ;
function_type = "unsafe"? extern_abi? "fn" "(" type_list? ")" return_type? effects? ;
type_list = type ("," type)* ","? ;

block = "{" statement* expression? "}" ;
statement = ";" | binding | assertion | defer_stmt | expression ";" | block_expression ;
binding = ("let" | "var") pattern (":" type)? "=" expression ";" ;
defer_stmt = "defer" (block | expression ";") ;
block_expression = block | "unsafe" block | if_expr | match_expr | loop_expr ;
if_expr = "if" expression block ("else" (block | if_expr))? ;
match_expr = "match" expression "{" match_arm ("," match_arm)* ","? "}" ;
match_arm = pattern "=>" expression ;
loop_expr = "loop" block | "while" expression block
          | "for" "move"? loop_binding "in" expression block ;
loop_binding = IDENT | "_" ;

expression = assignment ;
assignment = range_expr (assignment_op assignment)? ;
assignment_op = "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "&=" | "|=" | "^="
              | "<<=" | ">>=" | "+%=" | "-%=" | "*%=" ;
range_expr = logical_or ((".." | "..=") logical_or)? ;
logical_or = logical_and ("||" logical_and)* ;
logical_and = equality ("&&" equality)* ;
equality = comparison (("==" | "!=") comparison)* ;
comparison = bit_or (("<" | "<=" | ">" | ">=") bit_or)* ;
bit_or = bit_xor ("|" bit_xor)* ;
bit_xor = bit_and ("^" bit_and)* ;
bit_and = shift ("&" shift)* ;
shift = additive (("<<" | ">>") additive)* ;
additive = multiplicative (("+" | "-" | "+%" | "-%" | "+?" | "-?") multiplicative)* ;
multiplicative = cast (("*" | "/" | "%" | "*%" | "*?") cast)* ;
cast = unary ("as" type)* ;
unary = ("!" | "~" | "-" | "*" | "&" "mut"?) unary | postfix ;
postfix = primary suffix* ;
suffix = "(" argument_list? ")" | "[" expression "]" | "?"
       | "." DECIMAL_INDEX | "." IDENT
       | "." IDENT "::" generic_args "(" argument_list? ")" ;
argument_list = expression ("," expression)* ","? ;
primary = INTEGER | STRING | "true" | "false" | "null" | "self"
        | value_path | record_expr | "(" ")" | "(" expression ")"
        | "(" expression "," expression ("," expression)* ","? ")"
        | "[" argument_list? "]" | "[" expression ";" expression "]"
        | block_expression | layout_expr
        | "return" expression? | "break" expression? | "continue" ;
value_path = value_segment ("::" value_segment)* ;
value_segment = IDENT ("::" generic_args)? ;
record_expr = value_path "{" field_init_list? "}" ;
field_init_list = field_init ("," field_init)* ","? ;
field_init = IDENT ":" expression ;
layout_expr = ("sizeof" | "alignof") "(" type ")"
            | "offsetof" "(" type "," (IDENT | DECIMAL_INDEX) ")" ;

pattern = "_" | IDENT | INTEGER | "-" INTEGER | "true" | "false"
        | path | path "(" pattern ")" | path "{" field_pattern_list? "}"
        | "(" ")" | "(" pattern ")" | "(" pattern "," pattern ("," pattern)* ","? ")" ;
field_pattern_list = field_pattern ("," field_pattern)* ","? ;
field_pattern = IDENT ":" pattern ;
```

补充约束：

- 只有外部声明可用函数体位置的 `;`；实现块不得包含外部函数或外部静态声明。`pub` 不用于实现块或断言。属性适用位置按第 5.8 节检查。
- 泛型只可附在对应泛型声明的路径段；模块、局部变量、字段不可带类型实参。模式由被检类型决定泛型实参，不在模式中书写类型实参。
- `Type::method` 中的 `Self`、`core`、`arch`、`root` 依照正文作为特殊名字解析。`self` 只在接收者方法内作为表达式。
- `ptr::<T, space>` 是值路径类型实参的唯一地址空间特例；其第二项按第 18.3 节读取地址空间记号，不是类型。
- `as` 后的类型不吞掉表达式后缀；对转换结果取字段／下标或调用须显式加括号。函数类型结果中的 `effects` 归最内层未闭合函数类型；需要标记外层时用括号界定内层类型。
- `arch::asm` 的参数区使用目标补充定义的专用语法，不按普通 `argument_list` 解析；其他目标内部函数采用普通调用形式。
- `addr_of`／`addr_of_mut` 使用普通调用语法，但解析到对应内部声明后，其唯一实参按位置处理，不生成按值读取；数组重复构造的第二个表达式须为常量长度。
- 整数、布尔、字符串词法以及泛型闭合 `>` 的记号拆分仍由第 2、10 章约束。语法内部函数仅使用这里列出的不带路径形式，不存在 `core::sizeof` 等别名。

## 附录 B. 泛型范围

Core 提供类型参数、泛型函数、泛型固有实现、结构 `T: Copy` 约束与受限递归实例化。借用实参在 Core 中可表示；借用扩展的保守拒绝规则见第 31.5 节。所有权扩展对无约束参数的消费要求见第 30 章。

## 附录 C. 失败类别

| 类别 | 示例 | 未启用 Extend 时 |
| --- | --- | --- |
| Core 编译失败 | 语法或名字错误、基础类型不匹配、无限按值布局、非法 ABI、非法原子顺序 | 仍必须拒绝 |
| 扩展验证失败 | 所有权合并不一致、借用冲突、资源未消费、阻塞效果不匹配 | 不作为 Core 拒绝条件 |
| 规定的运行时失败 | 边界越界、普通算术溢出、除零 | 仍执行 panic 语义 |
| 执行合同违反 | 实际读取未初始化值、访问已结束存储、数据竞争、非法机器访问 | 从实际违反操作起超出规定语义 |

缺少证明或关闭扩展不自动造成执行合同违反。反之，Core 接受程序或源代码未使用 unsafe，都不证明执行合同成立。

## 附录 D. `core` 内部函数与类型表面

除整数／bool 等预定义类型及语法内部函数外，下列名字可用 `core::` 限定，也由第 4.5 节预导入。此处 `P` 仅是表格元记号，表示任意地址空间、任意 const 性的同一原始指针类型，不是用户泛型机制。写为 `T`、`E` 的类型参数必须按实参或期待类型确定；唯一显式目标型特例 `checked_cast::<D>(x)` 中源整数类型由 `x` 决定。

| 名字 | 签名／行为入口 | unsafe |
| --- | --- | --- |
| `Option<T>`、`Result<T,E>` | 变体构造、Copy 和资源规则见 6.11 | 否 |
| `MemoryOrder` | 22 章的五个枚举变体 | 否 |
| `replace<T>` | `(&mut T, T) -> T` | 否 |
| `swap<T>` | `(&mut T, &mut T) -> ()` | 否 |
| `split_at_mut<T>` | `([]T, usize) -> ([]T, []T)` | 否 |
| `forget<T>` | `(T) -> ()` | 是 |
| `panic` | `([]const u8) -> !`；消息允许运行时切片 | 否 |
| `checked_cast::<D>` | `(S) -> Option<D>`，S、D 均为整数 | 否 |
| `addr` | `(P) -> usize` | 否 |
| `addr_of`、`addr_of_mut` | `(place: T) -> *kernel const T`／`*kernel T`；位置操作见 18.4 | 按位置来源 |
| `ptr::<T, space>` | `(usize) -> *space T`，space 默认 kernel | 是 |
| `ptr_add`、`ptr_add_bytes` | `(P, usize) -> P` | 是 |
| `slice_from_raw_parts<T>` | `(*kernel const T, usize) -> []const T`；合同见 9.3 | 是 |
| `slice_from_raw_parts_mut<T>` | `(*kernel T, usize) -> []T`；合同见 9.3 | 是 |
| `volatile_load<T>` | `(*kernel const T) -> T` | 是 |
| `volatile_store<T>` | `(*kernel T, T) -> ()` | 是 |
| `mmio_load<T>` | `(*mmio const T) -> T` | 是 |
| `mmio_store<T>` | `(*mmio T, T) -> ()` | 是 |

load／store 的 `T` 只限整数。`addr`、两个指针偏移函数由输入指针唯一决定类型，两个原始取址操作由位置决定类型，均不接受显式类型实参。`ptr` 必须显式给出 `T`；其余普通泛型接口可按第 10 章省略或完整给出类型实参。内部函数不作为可取地址的函数值；需要间接调用时写普通包装函数。切片内建成员的完整集合另见第 9.3 节，不作为可取地址的方法值。

存储包装器的完整成员集合如下；不能访问其内部字段，没有其他隐式方法：

```text
MaybeUninit<T>::uninit() -> MaybeUninit<T>
MaybeUninit<T>::write(&mut self, value: T) -> ()
MaybeUninit<T>::as_ptr(&self) -> *kernel const T
MaybeUninit<T>::as_mut_ptr(&mut self) -> *kernel T
unsafe MaybeUninit<T>::assume_init(self) -> T
UnsafeCell<T>::new(value: T) -> UnsafeCell<T>
UnsafeCell<T>::get(&self) -> *kernel T
Atomic<T>::new(value: T) -> Atomic<T>
Atomic<T>::load(&self, order: MemoryOrder) -> T
Atomic<T>::store(&self, value: T, order: MemoryOrder) -> ()
Atomic<T>::exchange(&self, value: T, order: MemoryOrder) -> T
Atomic<T>::compare_exchange(&self, expected: T, desired: T,
                           success: MemoryOrder, failure: MemoryOrder) -> Result<T,T>
Atomic<T>::fetch_add/sub/and/or(&self, value: T, order: MemoryOrder) -> T
```

最后一行是四个名字的缩写，不是源语法；支持实例与顺序规则见第 21—22 章。包装器不再接受成员自己的类型参数，`T` 属于接收者／关联类型；例如显式构造写 `Atomic::<u32>::new(0)`，省略时由参数或期待结果推导包装器类型。这些接口不隐式分配堆内存。内部成员可使用第 11.9 节的接收者语法。

所有 Core 内部函数的 Blocking 效果为空，panic 不正常返回；架构内部函数的效果按目标补充。语法内部函数 `sizeof(T)`、`alignof(T)`、`offsetof(T, field)`、`static_assert(condition)` 分别见第 24、26 章；它们不是第一类函数，也不求值类型或字段名。

## 附录 E. 目标适配与分析扩展

Architecture Supplement 定义目标 ABI、RV64 寄存器、CSR、汇编、`TrapFrame`、入口桩、陷阱返回和设备栅栏。Core 实现必须完成所宣称目标的代码生成，不能把可运行所需的目标适配当作可选正确性证明。

Extend 是额外分析层，不是运行时依赖。其职责、启用与保证边界见第 29—34 章。Kernel Verification Supplement 不改变目标指令或基础 ABI，而是验证更强的内核使用条件。

## 附录 G. 诊断类别与阶段

这些类别标识规范失败原因，不规定错误文本或终端格式。实现可有更细子类，但须能归入本表；测试适配器可以转换实现自身的代码。输入具有多个错误时不规定报告顺序。

| 类别 | 范围 |
| --- | --- |
| `E_LEX` | 非法 UTF-8、词法记号、未闭合注释／字符串 |
| `E_PARSE` | 不符合附录 A 的语法，包括明确排除的语法 |
| `E_NAME` | 名字／模块未找到、名字冲突、不可见成员 |
| `E_ATTRIBUTE` | 未知、重复、位置错误的属性 |
| `E_TYPE` | 类型不匹配、可写性、操作不支持、无法推导、成员构造错误、Core 排除的 C ABI 参数／结果／外部对象类型 |
| `E_PATTERN` | 不穷尽、绑定模式可反驳、模式结构不合法 |
| `E_CONST` | 非法常量操作、常量失败、非法或动态原子顺序 |
| `E_LAYOUT` | 无限／溢出布局、无对象表示、非法对齐 |
| `E_INSTANTIATION` | 多态递归或具体实例不满足约束 |
| `E_UNSAFE` | 缺少明确要求的词法 unsafe 授权 |
| `E_CONTEXT` | 特殊函数普通调用、错误转移上下文／签名／尾位置 |
| `E_TARGET` | 所选目标不支持的 ABI／属性组合、寄存器／CSR 或目标语法参数 |
| `E_LINK` | 缺失／重复符号、可检查的 ABI 不一致、目标运行依赖未满足 |
| `V_OWNERSHIP`、`V_BORROW`、`V_BLOCKING` | 对应已启用扩展的规则违反 |
| `V_CONCURRENCY`、`V_KERNEL` | 对应具名验证配置的规则违反 |

## 附录 H. 实现起点与合规范声明

开始编译器开发时，使用以下固定输入：本 reference、[rv64-core-v1](architecture-rv64.md)、[合规范用例与运行协议](conformance.md)。不得以历史 draft 补充未声明的要求。实现定义的选择仅限明确列出的项目：诊断文字、驱动与缓存形式、内部符号名、panic 消息和满足目标合同的平台内部策略；目标布局与调用降低已由 rv64-core-v1 固定。

建议实现顺序（不是新语言限制）：词法／语法与名字解析；基础类型和单态化；布局及常量；保留源顺序的有类型表达式和结构化退出展开；目标调用与存储降低；目标运行验收；最后按需增加 Extend。词法区域、来源集合、资源证明不是 Core 前置阶段。

一个实现可以声明“Core 前端已通过当前接受／拒绝基线”或“rv64-core-v1 目标验收已完成”，但二者不能混称。支持 Extend 时另外列出分析名称、版本、依赖、通过的正反例和受信合同。文档闭合提供实现依据，不代替编译器及平台的实测证明。

## 附录 I. 0.5 修订范围与实现取舍

0.5 修正有限泛型嵌套的布局判定，补齐原始取址、切片与未初始化存储接口、外部静态符号、Copy 数组重复构造，并固定原子顺序的精确定义。Core／Extend 分层、无隐式析构及现有 RV64 ABI 保持不变；新的源能力不得冒充 0.4 支持。对应正反例和平台验收是本次修订的一部分。

首版实施审计还在第 3.1 节明确了独立块式语句与后续一元表达式之间的定界：保留后缀链，区分语句位置与初始化器／操作数位置，并要求有歧义的块结果二元运算使用括号。

本版继续排除常量泛型、`const fn`、用户 trait、闭包、字段简写、模式 `..`、导入别名和开放端点切片。除底层存储接口外，优先加入可直接降低为一次求值加固定次数复制的数组重复构造；其他便利性功能在真实内核程序和首个编译器实现中再评估。可调度陷阱需要新的平台合同，不作为语法便利性改动加入。

实现可按词法／解析、名字解析、类型与实例化、布局与常量、有类型中间表示、作用域退出降低、目标后端划分模块。所有正常退出共用清理展开，原始位置地址计算与按值读取分开表示；模式覆盖检查独立于代码生成。使用 C 或其他后端时仍须保留求值快照、溢出检查、别名合同、原子及 MMIO 语义。复用外部汇编器、链接器或后端不减免合规范要求；本手册不以代码行数代替完整性、可读性或目标验收。
