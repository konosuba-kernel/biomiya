# B3.1：可维护的自编译器和一个 Blocking 分析

本轮执行已确认的 N0→N1→N2→N3→N4→N5 计划。输入为 Git 1c0f143 的已验收 B3；不改变语言子集、不补齐 R1a、不实现 B4，也不增加泛型、闭包、通用插件 ABI。各节点独立验收和哈希保存于 `docs/workflows/bootstrap-b31/`。

## 节点合同

- N0：保留提交、B3 C2 seed、所有源码哈希与原81项证据。审查冻结范围和恢复路径。
- N1：展开密集VT语句；命名类型kind、声明kind、AST tag、IR op、二元运算和错误类别；记录通用记录字段合同，补齐高频语义构造函数。真实机器编码数字可保留。允许行数增加，不新增语言能力。源token保持的格式化单独验证，符号替换以行为与自编译验证。适配测试源码列表若确有需要须明确列入候选。
- N2：扫描游标与诊断位置分离，checker不修改token；函数arena初始化责任唯一，明确全局表/函数表/目标工作表拥有者。具体小状态可用结构，但大数组不按值传递。节点错误位置、声明前向引用、递归布局、跨函数状态复用回归通过。
- N3：共享整数、转换、布局的纯规则，不引入通用求解器；明确静态初始化验证与全零判断合同。函数语义IR在交给分析后只读；后端帧偏移使用目标侧表而不回写语义Slot。保留非法IR检查，只在安全且有证据时缩小重复扫描。自编译、算术/布局/静态初始化/清理反例通过。
- N4：目标语言中实现一个可选的具体Blocking检查，不增加源语法。普通Core编译与关闭分析行为不变；分析开启不修改IR/ELF。以独立文本配置列出不得阻塞函数和外部合同；内部函数从实际CALL提取稳定DeclId摘要，在函数表重用前记录，跨函数传播支持递归。外部合同缺失是Unknown，声明为may_block是Violation；仅完整可达调用闭包均不阻塞才Verified。不得阻塞根不存在、合同冲突/重复/未知函数、非extern合同均拒绝。严格检查只有所有要求Verified才可发布ELF，失败不留下新输出、不改输入或既有输出。配置及报告不是通用插件API；不声称IRQ/并发安全。
- N5：旧B3编译器可以启动新源码，随后新版D2/D3完整固定点；C0路径也保持。完整旧81项和新增有效回归、干净源码构建、源码扰动、无宿主代编译、分析开关同ELF、独立验收通过。统计所有生产VT、运行库、s0、保留seed和测试，区分排版变化与语义改动。静态数据/映像≤64MiB，目标在1MiB栈配置运行。

## 结构约束

保留具体定长表、按ID引用和逐函数复用。规则计算尽量使用显式输入，返回小结果；错误出口统一，无须所有函数改成Result。构造允许原地修改；完成类型条目和完成函数IR只读。分析可以修改自己的有限工作表，不得修改编译器语义。跨函数只保存稳定身份和调用摘要，不保存临时AST/slot引用。

N4格式与上限由实现时按真实数据规模具体冻结，不借此扩大语言或框架。若试点需要新增框架、全程序AST或不满足预算，应先简化实现，不能把未实现分析标记通过。未知与违反必须分开；支持未知外部实现不代表已经证明非阻塞。

## 执行与证据

产品写入范围按节点串行；作者和验收者分离。基线旧证据不覆盖。下游仅在依赖最新候选独立通过后正式启动。探索可以先行但不得冒充正式通过。候选保存内容哈希和输入版本；源码改变则重新冻结/验收。旧B3中保留的已知seed差异继续公开，不为迁移随意修种子或改语言。
